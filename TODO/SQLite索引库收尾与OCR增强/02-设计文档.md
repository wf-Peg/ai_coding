# 设计文档：SQLite索引库收尾与OCR增强

## 架构设计
- **SQLite 生命周期**：`db.js` 单例连接常驻主进程；新增 `optimize()` / `vacuum()`，`closeDatabase()` 内串联 optimize + WAL checkpoint + close。`index-service.js` 以 `startMaintenance()`（两个 unref 定时器：6h optimize、24h vacuum）与 `close()`（停维护→关库）对外，`main.js` 启动时 start、`will-quit` 时 close。
- **OCR 降噪**：`ctcDecode` 增加可选 `minCharScore`，列 argmax 概率低于阈值按 blank。
- **模型下载**：`getModelJobs`（Node/PowerShell 共用清单）+ 按平台分发（Windows PowerShell 内联、其余 Node 直连）。

## 技术方案
- `closeDatabase`：`PRAGMA optimize;` → `PRAGMA wal_checkpoint(TRUNCATE);` → `close()`，异常静默。
- 周期维护定时器 `unref()`，不阻止应用退出；`vacuum()` 先 checkpoint 再 `VACUUM`。
- `ctcDecode(probs, width, dict, numClasses, minCharScore)`，`REC_MIN_SCORE = 0.5`，导出供单测。
- 下载源重排 + User-Agent + 失败归因到缺失文件。

## 接口定义
- db.js 导出补充：`optimize`、`vacuum`。
- index-service 导出补充：`startMaintenance`、`stopMaintenance`、`close`。
- ocr-service 导出补充：`ctcDecode`。

## 关键决策
- cls 不纳入必需项（无可下载源），正立文本不受影响。
- 源顺序：hf-mirror → huggingface → PaddleOCR raw（字典）。
- 低置信度阈值默认关闭、可选开启，保证无阈值行为向后兼容。
