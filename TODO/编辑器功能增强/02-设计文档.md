# 设计文档：编辑器功能增强

## 架构设计

### 整体架构

编辑器功能增强采用分层架构，以现有编辑器模块为基础进行增量扩展：

```
┌─────────────────────────────────────────────────────┐
│                    UI 层（editor.html + CSS）          │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────────┐ │
│  │标签栏 │ │工具栏 │ │面板区 │ │状态栏 │ │遮罩层     │ │
│  └──────┘ └──────┘ └──────┘ └──────┘ └──────────┘ │
├─────────────────────────────────────────────────────┤
│              逻辑层（editor.js）                      │
│  ┌──────┐ ┌──────────┐ ┌────────┐ ┌────────────┐  │
│  │多标签 │ │收藏管理   │ │翻译/词典│ │面板动画控制  │  │
│  │管理   │ │(localStor)│ │(DICT)  │ │(aria-hidden)│  │
│  └──────┘ └──────────┘ └────────┘ └────────────┘  │
├─────────────────────────────────────────────────────┤
│              ACE 编辑器核心                            │
│  ┌──────────────┐ ┌──────────────────────────────┐  │
│  │  mainEditor  │ │  UndoManager (历史栈)          │  │
│  │ (单实例+快照) │ │  selectionStyle: 'line'       │  │
│  └──────────────┘ └──────────────────────────────┘  │
├─────────────────────────────────────────────────────┤
│          Electron IPC 层（main.js + preload.js）      │
│  ┌──────────────┐ ┌──────────────┐ ┌────────────┐  │
│  │showItemInFolder│ │backend-ready │ │快捷键注册   │  │
│  └──────────────┘ └──────────────┘ └────────────┘  │
└─────────────────────────────────────────────────────┘
```

### 关键设计决策

| 决策 | 方案 | 理由 |
|------|------|------|
| 多标签实现 | 单 Ace 实例 + 标签快照 | 避免多实例内存开销和创建/销毁性能问题 |
| 面板隐藏机制 | aria-hidden + class 控制 | display:none 无法实现 grid 列宽过渡动画 |
| 拖拽排序 | HTML5 原生 Drag & Drop API | 不引入第三方库，减少依赖 |
| 收藏数据持久化 | localStorage | 与最近文件一致，无需后端介入 |
| 词典存储 | localStorage (USER_DICT + DICT_LIB) | 用户自定义数据，无需后端 |
| 在线翻译 | AI 对话方式（sendAiMessage） | 取代 MyMemory 第三方 API，统一交互入口 |
| 启动流程 | 并行启动，先显示窗口 | 消除用户等待后端启动的空白期 |

## 技术方案

### 1. 多标签（Multi-Tab）

**核心思路**：不创建多个 Ace 实例，始终只使用一个 mainEditor。切换标签时保存当前标签快照，再恢复目标标签快照。

**标签状态快照结构**：
```javascript
{
  id, fileToken, fileName, displayPath, encoding,
  modified, content, language, scrollTop, scrollLeft,
  cursorRow, cursorColumn
}
```

**切换流程**：
```
用户点击标签 B
  → saveActiveTabSnapshot()  ← 保存当前标签 A
  → activeTabIndex = B 的索引
  → state = tabs[activeTabIndex]  ← 切换引用
  → mainEditor.setValue(state.content)
  → 恢复光标、滚动位置
  → updateDocumentIdentity()  ← 更新 toolbar
  → renderTabBar()  ← 更新标签栏高亮
```

### 2. 推拉式抽屉面板动画

**核心机制**：利用 CSS grid-template-columns 过渡，隐藏时列宽为 0fr，打开时过渡到目标宽度。

```css
.editor-workspace {
  transition: grid-template-columns 240ms cubic-bezier(0.22, 1, 0.36, 1);
}
.editor-pane[aria-hidden="true"] {
  visibility: hidden;
  opacity: 0;
  transition: visibility 0s linear 240ms, opacity 240ms ease;
}
```

### 3. 翻译与词典体系

**词典查找优先级**：USER_DICT → DICT_LIB → DICT_CN → DICT

**ACE 自定义 completer**：前缀匹配，不区分大小写，合并所有词典来源，取前 30 个结果。

### 4. 启动流程优化

**改造前**：串行启动 → startFrontendServer → startBackend → 等待3秒 → 创建窗口
**改造后**：并行启动 → startFrontendServer + startBackend（不 await）→ 立即创建窗口 → 前端遮罩 → 后端就绪 IPC → 隐藏遮罩

## 多模块多类型双向链接设计（fp-019）

### 后端（electron/main.js）

**可链接扩展名集**：`LINKABLE_EXT_RE = /\.(md|mdown|markdown|txt|sql|json|xml|csv|log|yaml|yml|ini|conf)$/i`；排除模块常量 `EXCLUDED_MODULE_DIRS = ['clip-storage']`。

**模块发现** `discoverLinkModules()`：
- 基目录 = `config.storagePath`，遍历一级子目录，跳过点开头与排除目录，递归检查含 ≥1 个可链接文本文件即视为模块
- 兜底：无任何模块时回退 `resolveVaultRoot(config)` 单一模块

**逐模块构建** `buildModuleIndex(mod)`：
- `targets` 条目带 `moduleId/moduleName/basename/fileName/relativePath/absolutePath`
- 对所有可链接文本文件都扫 `[[...]]`（真正双向），键保留扩展名形式（如 `[[query.sql]]` → 键 `query.sql`）
- 大小守卫：>10MB 文件只作目标、不扫反链

**逐模块监听**：每模块 `fs.watch(recursive)` + 500ms 防抖仅重建对应模块；不可用走 TTL(3s) 兜底；模块根变化时重建模块清单。

**聚合接口**：
- `editor-list-wikilink-targets` → `{ targets: 各模块合并, modules }`
- `editor-find-backlinks(currentPath)`：由 currentPath 推导 basename 与 fileName 双键聚合各模块 reverse 并去重，排除自引用，就近排序
- `editor-find-outgoing(currentPath)`（新增）：读当前文件解析出链，返回 `[{ target, resolved, missing }]`
- `editor-save-to-vault`：优先使用发现的 clip-organized 模块根

### 前端（frontend/js/editor.js + editor.html + editor.css）

- `wikilinkState = { targets, modules, loaded }`；`getModuleIdByPath(currentPath)` 判定模块归属
- `resolveWikilink(target, currentPath)`：相对路径精确 → fileName 精确 → basename 就近优先排序
- 反链点击用 `openWikilinkByPath(b)` 打开精确文件（修复误开 bug）；条目显示模块小标签，标题显示真实文件名
- 新增 `buildOutgoing()` 出链面板：每条显示 `[[target]]` + 解析结果，断链加 `wikilink-missing` 样式
- `scheduleBacklinksRefresh` 按当前激活 tab 刷新；打开新文件后显式刷新
- `registerWikilinkCompleter`：去重改 `seen[basename+ext]`，meta 显示模块名/相对路径，同名冲突额外生成 `[[相对路径]]` 候选
- editor.html 反链面板新增「反链|出链」分段 tab 与 `outgoingList`；editor.css 新增分段 tab、模块小标签、出链条目、断链样式

### Obsidian 对齐的产品/交互

- 面板标题「双向链接」，数量徽标 pill；tab 分段控件（反链 | 出链）
- 反链条目：来源文件名加粗 + 模块小标签 + 相对路径 + 最多 3 行匹配行（行号胶囊 + `[[目标]]` 主题色高亮）
- 出链条目：`[[目标]]` + 解析结果，断链标红「未找到目标」不可点
- 同名选择弹窗：Obsidian 式 suggest 列表（文件名 + 模块/相对路径）
- 全部沿用 `--app-*` 主题变量，暗色自动适配；抽屉动画沿用现有机制
