# 工作台词典功能埋线计划

## 一、概述

将编辑器模块的词典功能数据"埋线"到工作台模块的概览页中，在工作台概览页右侧面板展示词典知识卡片，包括词典统计和最近学习词汇。

### 设计原则
- **不重复造轮子**：工作台只读展示词典数据，不负责词典的增删改维护
- **共享数据源**：直接读取编辑器写入的 localStorage（`editor_dict_lib_v1` / `editor_user_dict_v1`）
- **最小侵入**：编辑器新增活动日志记录逻辑，但不影响现有功能流程

## 二、当前状态分析

### 工作台概览页布局（右侧面板）
```
┌─ project-panel ─────────────────────┐
```

### 现有词典数据源
| 数据 | Storage Key | 存储位置 | 来源 |
|---|---|---|---|
| USER_DICT | `editor_user_dict_v1` | localStorage | 编辑器写入 |
| DICT_LIB | `editor_dict_lib_v1` | localStorage | 编辑器写入 |
| 内置 DICT | `dict-offline.js` 全局变量 | 内存 | 静态 JS 引入 |
| 内置 DICT_CN | `dict-offline.js` 全局变量 | 内存 | 静态 JS 引入 |

### 当前问题
- 编辑器新增词典条目时**没有记录时间戳**，无法追踪"最近新增"
- 工作台模块**完全不感知**词典数据的存在

## 三、修改方案

### 3.1 新增活动日志追踪（editor.js）

#### 新增 localStorage 键
| Key | 结构 | 说明 |
|---|---|---|
| `editor_dict_activity_v1` | `[{source, target, type, timestamp}]` 数组，最多保留 50 条 | 按时间倒序排列的词典活动日志 |

#### 新增函数

**`logDictActivity(source, target, type)`** — 在 `addDictLibEntry` 和 `addUserDictEntry` 中调用
- 参数：`source` 源词, `target` 释义, `type` ('mapping' | 'lib')
- 写入 `{ source, target, type, timestamp: new Date().toISOString() }` 到活动日志数组头部
- 截断数组保留最多 50 条
- 写入 `localStorage.setItem('editor_dict_activity_v1', ...)`

**`loadDictActivity()`** — 初始化时调用
- 从 localStorage 读取活动日志
- 挂到 `window.DICT_ACTIVITY` 全局变量，供工作台读取

### 3.2 工作台概览页新增词典知识卡片（workspace.html）

#### HTML 结构变更

在右侧面板 `project-panel` 中，工作台摘要卡片之后、项目列表之前，插入词典知识卡片区域：

```html
<!-- 词典知识卡片 -->
<div class="dict-knowledge-panel" id="dictKnowledgePanel">
  <div class="panel-heading">
    <h2>📖 词典知识</h2>
    <p>最近学习与词汇积累</p>
  </div>
  <div class="dict-stats-row" id="dictStatsRow"></div>
  <div class="dict-recent-list" id="dictRecentList"></div>
</div>
```

#### CSS 样式变更

新增约 50 行样式，包含：
- `.dict-knowledge-panel` — 与 `.project-panel` 同级卡片样式
- `.dict-stats-row` — 水平统计卡片行（与 `.ws-summary-cards` 类似布局）
- `.dict-stat-card` — 单个统计卡片（总词条数、自定义映射数、词典库数、今日新增）
- `.dict-recent-list` — 最近词汇列表容器
- `.dict-recent-item` — 单条词汇条目（源词 + 释义 + 类型标签 + 时间）
- `.dict-empty` — 空态提示

#### JavaScript 逻辑变更

在 IIFE 内新增函数：

**`loadDictKnowledge()`** — 异步读取词典数据并渲染
- 从 `localStorage` 读取 `editor_user_dict_v1`、`editor_dict_lib_v1`、`editor_dict_activity_v1`
- 计算统计值：总条目数、自定义映射数、词典库数、今日新增数
- 调用 `renderDictStats()` 和 `renderDictRecent()`

**`renderDictStats(stats)`** — 渲染统计卡片行
- 4 个卡片：总词条数、自定义映射数、词典库数、今日新增 + 累计学习

**`renderDictRecent(activity)`** — 渲染最近词汇列表
- 取最近 10 条活动记录
- 每条显示：源词 → 释义、类型标签（自定义映射/词典库）、相对时间（"2小时前"、"昨天"等）
- 空态：暂无学习记录

#### 修改点
1. HTML 部分：在 `project-panel` 内、`workspaceSummary` 之后、`projectList` 之前插入词典知识卡片 HTML
2. 初始化区域（第 1377-1378 行）：`loadOverview()` 和 `loadWorkspaces()` 之后增加 `loadDictKnowledge()` 调用
3. 主题 `postMessage` 监听（第 1370 行）：`refresh` 消息也触发 `loadDictKnowledge()`

### 3.3 数据流

```
┌─ 编辑器 (editor.js) ─────────────────────┐
│  addDictLibEntry() ──→ logDictActivity()  │
│  addUserDictEntry() ──→ logDictActivity()  │
│                          ↓                 │
│             localStorage:                  │
│  editor_user_dict_v1  ←── USER_DICT        │
│  editor_dict_lib_v1   ←── DICT_LIB         │
│  editor_dict_activity_v1 ←── 活动日志       │
└────────────────────────────────────────────┘
                        │ 同一 origin，共享
                        ▼
┌─ 工作台 (workspace.html) ─────────────────┐
│  loadDictKnowledge()                      │
│    ├─ 读取 localStorage 三个 key           │
│    ├─ renderDictStats()  → 统计卡片        │
│    └─ renderDictRecent() → 最近词汇列表    │
└────────────────────────────────────────────┘
```

## 六、边界情况与注意事项

1. **localStorage 数据不存在**：`loadDictKnowledge()` 需处理所有 key 缺失的情况，兜底为空数据
2. **活动日志格式兼容**：编辑器可能写入旧格式数据，`loadDictActivity()` 需做防御性解析
3. **跨 iframe 数据同步**：工作台初始化时读取一次 localStorage；如果用户在编辑器添加词典后切换到工作台，可通过 `postMessage` 的 `refresh` 事件触发 `loadDictKnowledge()` 刷新
4. **性能**：词典条目数量较大时（1000+），`Object.keys()` 操作仍然很快，无需优化
5. **相对时间显示**：实现 `timeAgo()` 工具函数，处理 "刚刚、N 分钟前、N 小时前、昨天、N 天前、具体日期" 等格式
