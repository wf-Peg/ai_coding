## 功能点 fp-003：修复后端状态同步与工作台产品开发页 Bug

### 架构设计

#### 问题 1：后端状态指示器重复 + 数据不自动刷新
- **根因**：editor.html 底部独立维护一套后端状态机，与 index.html 标题栏全局指示器互不同步
- **方案**：删除 editor.html 底部重复指示器，后端就绪后通过 postMessage 广播 refresh 到所有子 iframe
- **去重保护**：`handleBackendReady()` 内 5 秒时间窗去重
- **竞态处理**：子 iframe 在 backend-ready 事件之后才加载完时，通过 load 事件补发刷新

#### 问题 2：工作台产品开发页
- **根因**：`.product-dev-view` 是 `.shell` 的兄弟节点且位于其后，visible 时在侧边栏下方渲染
- **方案**：`.product-dev-view` 改为 `position: fixed; inset: 0; z-index: 60` 全屏覆盖
- **Tab 无响应**：新增 `.pd-tab` 点击切换逻辑（参照 `.detail-tab` 写法）

#### 问题 3：健康检查 500 / CORS + 前端异常未统一上报
- **根因**：后端只有 `/health` 无 `/api/health`，且无 `@CrossOrigin`
- **方案**：后端补 `/api/health` 端点 + `@CrossOrigin(origins = "*")`
- **异常上报**：所有子页面引入 `js/logger.js`，利用全局 error/unhandledrejection 上报

### 接口定义
- 新增 `GET /api/health` → 复用 `/health` 返回体 `{status: UP, timestamp}`
- 新增 `@CrossOrigin(origins = "*")` 到 HealthController

### 关键决策
| 决策点 | 结论 |
|--------|------|
| 编辑器底部后端指示器 | 直接删除，保留标题栏全局指示器 |
| 数据自动刷新方式 | 复用 postMessage refresh 机制 + 帧 load 竞态补发；不刷新 editorFrame |
| 未支持 refresh 的页面 | 统一用 `location.reload()` |
| 异常上报 | 所有子页面引入 logger.js，不改动各页面 fetch 失败分支 |

## 功能点 fp-006：密码管理器深度集成

### 架构设计

```
Electron 主进程 → 前端 (vault.html+vault.js) → Spring Boot 后端 → 文件存储
```

#### DES 加密流程
- 用户生成 DES Key（8 字节随机密钥，Base64 编码）
- DES/ECB/PKCS5Padding 加密密码库 JSON
- 写入 `clip-storage/vault/vault.enc`
- 解锁时用户输入 Key → DES 解密 → 内存中返回明文

#### 数据模型
- `PasswordEntry`：id, title, category, username, password, url, notes, tags, favorite
- `VaultData`：version, entries, lastModified
- `vault-meta.json`：非敏感元数据（版本、算法、keyCheckHash）

#### 后端 API
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/vault/generate-key` | 生成随机 DES Key |
| POST | `/api/vault/init` | 初始化密码库 |
| POST | `/api/vault/unlock` | 解锁密码库 |
| POST | `/api/vault/lock` | 锁定密码库 |
| GET | `/api/vault/status` | 查询状态 |
| POST/PUT/DELETE | `/api/vault/entry` | 密码条目 CRUD |
| GET | `/api/vault/audit` | 安全审计 |
| POST | `/api/vault/generate-password` | 密码生成器 |

#### 前端页面结构
- 锁屏页 → 密码列表（分类侧边栏 + 卡片列表 + 搜索）→ 详情面板
- 密码生成器 UI（长度/字符集/强度）
- DES Key 管理面板
- 安全审计面板（弱密码/重复密码/过期密码）

#### Electron 集成
- 导航栏新增「密码」按钮
- 托盘菜单新增「密码管理」入口
- 应用最小化到托盘时自动锁定
- 闲置 5 分钟自动锁定

### 关键决策
- 本地优先：密码数据 DES 加密存储在本地 `clip-storage/vault/`
- 零知识：DES Key 不存储在服务端
- 借鉴 1Password/Bitwarden/KeePass/LastPass/Proton Pass 设计理念

## 功能点 fp-008：周报生成 Skill 设计

### 架构设计

#### Title 编码格式
```
<任务内容描述>[<任务类型>,<计划工时>h,<完成进度>%]
```
示例：`度小满账务文件入账内容开发[需求分析,15h,30%]`

#### 任务类型枚举
项目开发、需求分析、系统设计、详细设计、架构设计、开发自测、联调测试、缺陷

#### 解析规则
1. 提取末尾 `[...]` 内容
2. 按逗号分割
3. 逐项识别：关键词→taskType，`数字h`→plannedHours，`数字%`→progress
4. 默认值：taskType=项目开发，plannedHours=0，progress=0%（completed=true 则 100%）

#### 周报生成流程
1. 计算本周时间范围（本周一 00:00 - 本周日 23:59）
2. 调用 `GET /api/todo/list` 获取所有待办
3. 按 createdAtTimestamp 过滤本周待办
4. AI 识别工作 vs 生活待办（关键词规则）
5. 解析 title 提取字段
6. 按 taskType 分组
7. 用 PowerShell COM Excel 复制模板并填充数据
8. 输出到指定目录，文件名：`开发组_周报_{本周五YYYYMMDD}_彭文峰.xlsx`

### 关键决策
- 不扩展 TodoContent 模型，title 中编码字段
- 不复用现有 WeeklyReportService（基于剪藏内容，与待办无关）
- 不新增后端 API，复用 `/api/todo/list`
- 本周时间范围：本周一 00:00 - 本周日 23:59

## 功能点 fp-010：异常日志模块设计

### 架构设计

#### 统一异常日志格式（JSON Lines）
```json
{
  "id": "err_20260808_001",
  "timestamp": "2026-08-08 14:30:15.123",
  "level": "ERROR",
  "source": "backend|electron|frontend",
  "sourceDetail": "类名.方法名(文件名:行号)",
  "message": "异常简要描述",
  "stackTrace": "完整堆栈信息",
  "thread": "线程名称",
  "requestUri": "请求路径（仅后端）",
  "appVersion": "应用版本号"
}
```

#### 文件存储策略
- 路径：`{clip.storage.path}/tmp/exception-logs/YYYY-MM/exception-YYYY-MM-dd.jsonl`
- 格式：JSON Lines（每行一条 JSON）
- 滚动：按天切分，按月归档目录
- 清理：保留最近 90 天

#### 后端实现
- `ExceptionLogWriter.java`：底层文件写入器，管理 JSON Lines 文件写入、按天滚动
- `ExceptionLogService.java`：Spring Service，封装 ExceptionLogWriter，提供 `record()` 方法
- `GlobalExceptionHandler.java`：`@ControllerAdvice`，全局捕获异常并记录
- 写入方式：异步批量写入（5 秒间隔 flush），使用 `@Async`
- 查询 API：`GET /api/data/exception-logs`（分页）、`GET /api/data/exception-logs/stats`（统计）、`DELETE /api/data/exception-logs?days=90`（清理）

#### Electron 端
- 修改 `electron/logger.js`，通过 IPC 获取 storagePath，写入同目录
- 捕获 `uncaughtException`/`unhandledRejection` 写入统一格式

#### 前端
- 修改 `frontend/js/logger.js`，`error` 级别日志增加向后端 `POST /api/data/exception-logs` 上报
- 数据观测模块新增异常日志面板：统计卡片、分页列表、筛选栏、详情弹窗、趋势图、清理按钮

### 关键决策
- 日志格式使用 JSON Lines 而非纯文本
- 后端使用异步批量写入（5 秒间隔 flush），Electron 使用同步追加写入
- 不侵入现有日志系统（logback 和 electron-log 继续保留）
- 全局异常通过 `@ControllerAdvice` 统一捕获，无需侵入每个 Controller
