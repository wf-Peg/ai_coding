## 技术方案

### MCP Server（桥接层）

- 基于 `@modelcontextprotocol/sdk` 的 `McpServer`
- 传输层：`StdioServerTransport`（stdio 协议）
- 每个工具封装对剪藏后端 REST API 的 HTTP 调用
- 超时控制：`AbortController`，默认 60s
- 工具定义：Zod schema 参数校验

### DSH 插件（会话落库层）

- 基于 `@deepseek-ai/dsh-tools` 的 `defineTool`
- 通过 `cordis.yml` 的 `insert` 行挂载
- 插件注册 `clip_session` 工具，调用后端 `/api/clips` 写入
- 支持 `baseUrl` 配置或环境变量覆盖

## 关键决策

1. MCP 桥 vs 直接 API 调用：选择独立 MCP 桥，避免影响后端稳定性
2. Dual-read 策略：文件工具零成本读 + MCP 工具写
3. 写操作安全：需用户确认，clip_delete 必须显式确认
4. 自动去重：clip_add 内部去重，避免重复数据
5. Tools Hub 概念澄清：Tools Hub 是 UI 小工具，Agent 工具是可调用函数，通过只读桥工具互通
6. 技能包安装链路：源按打包形态解析 → ~/.dsh/skills/cut-shelter，安装前清空旧目录

## Phase 2：Electron 内嵌 DSH sidecar（AI 干活面板）

- 固定端口 3081（避开 3080）；3081 已有实例直接复用，退出不杀用户进程。
- 运行时由主进程生成 `dsh-agent.patch.yml`（webserver 端口覆盖 + insert mcp-client/clip-capture），写入无空格配置目录，避免 shell 参数拆分。
- dsh CLI 解析优先级：配置 dshBinPath → DSH_BIN → npx 缓存扫描（含 LOCALAPPDATA）→ 未装则提示自助安装。
- 安装命令在线同步：`getDshInstallCommand(force)`，优先级 `DSH_NPX_SPEC` → 6h 缓存（config.dshSync）→ npm registry latest（`fetch` 带 8s 超时）→ GitHub README raw 兜底 → 配置/默认兜底；全程失败非致命，断网自动降级 缓存→默认。「检测/重试」=force 强制刷新。
- 进度广播：detecting / starting / ready / failed / **need-install**；前端状态灯 + 进度条 + 取消/重试/刷新/反色。
- 主进程对缺失 CLI 返回 `{ success:false, needInstall:true }`，前端 AI干活 卡片前置检测：未装则显示安装说明+步骤（npx 命令 + 复制 + 检测/重试），装好才允许装载面板。
- iframe 不预加载，就绪后统一 loadAgentFrame（空则设置、已设置则强制重载），2s 端口探测 watchdog 兜底收敛状态。
- 离线闭包：`scripts/build-dsh-offline.mjs` 保留（研发手动可用），但**不再进入 prebuild 与默认打包**，`build.extraResources` 移出 `resources/dsh-offline`，以减小安装体积。
