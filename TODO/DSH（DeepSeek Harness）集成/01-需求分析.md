# 需求分析：DSH（DeepSeek Harness）集成

## 原始需求

让 DeepSeek Harness（DSH）的 Agent 能检索与写入剪藏知识库（剪藏/待办/学习计划/Wiki 索引/周报状态），并在完成工作后将会话成果自动落库，实现"AI 用你的知识库干活，干完自动沉淀"。

## 分析结论

需要实现三层架构：
1. **Phase 0 - MCP 桥**：通过 stdio MCP server 代理剪藏后端 REST API，暴露 11 个工具给 DSH Agent
2. **Phase 1 - 会话自动落库**：DSH 本地插件，Agent 完成后调用 clip_session 工具将成果落库
3. **Phase 2 - Electron 内嵌（后续）**：剪藏 Electron 内嵌 DSH Agent 模式

## 关键技术决策

- MCP 桥方案优于直接 API 调用：DSH 原生协议、自动发现工具、不影响后端稳定性
- Dual-read 策略：文件工具零成本读 + MCP 工具写
- 写操作安全设计：需用户确认，避免破坏数据结构
