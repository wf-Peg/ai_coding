# 需求分析：DSH（DeepSeek Harness）集成

## 原始需求

让 DeepSeek Harness（DSH）的 Agent 能检索与写入剪藏知识库（剪藏/待办/学习计划/Wiki 索引/周报状态），并在完成工作后将会话成果自动落库，实现"AI 用你的知识库干活，干完自动沉淀"。

## 分析结论

按阶段实现，Phase 0/1/2/3 与配套能力已完成；TODO 目录扫描已退役；仅 DSH Web 客户端插件与可选演进的会话级摘要待开发：

1. **Phase 0 - MCP 桥** ✅：通过 stdio MCP server 代理剪藏后端 REST API，暴露 13 个工具给 DSH Agent
2. **Phase 1 - 会话自动落库** ✅：DSH 本地插件，Agent 完成后调用 clip_session 工具将成果落库
3. **Phase 2 - Electron 内嵌** ✅：剪藏 Electron 内嵌 DSH「AI 干活」面板（sidecar 3081 + iframe）
4. **Phase 3 - Tools Hub 互通** ✅：MCP 桥新增 tools_hub_list/tools_hub_page 只读工具
5. **配套能力** ✅：技能包一键安装、Trae 技能同步、体验测试指南、DSH 离线依赖闭包
6. **已退役 - TODO 目录扫描（TodoScannerService）**：feature-points.json 改由 FeaturePointsService 直读服务产品概览，剪藏/待办走 API，不再恢复扫描器
7. **待开发 - DSH Web 客户端插件**：conversation node 内联渲染，需源码构建 DSH
8. **已实现 - 会话成果自动归档**：clip-capture 监听 turn/end 自动落库产品概览（source=dsh-session，fp-012）；更细粒度会话级摘要为可选演进

## 关键技术决策

- MCP 桥方案优于直接 API 调用：DSH 原生协议、自动发现工具、不影响后端稳定性
- Dual-read 策略：文件工具零成本读 + MCP 工具写
- 写操作安全设计：需用户确认，避免破坏数据结构
- 集成层保持薄：只用 MCP / HTTP / 文件等生态标准，不深绑 DSH 内部 API（预览期兼容）
