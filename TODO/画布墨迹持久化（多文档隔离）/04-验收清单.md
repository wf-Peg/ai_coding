## 二、功能闭环走查

### 基本持久化

- [ ] 画一笔后刷新页面，墨迹仍在，且位置、颜色、粗细、透明度与刷新前一致
- [ ] 画一笔后完全重启应用，墨迹仍在
- [ ] 画笔「细 / 粗」与荧光笔（宽 + 半透明）三种样式各自落库后还原正确
- [ ] 橡皮擦擦掉一笔后刷新：被擦的笔不再出现，其余笔完整保留
- [ ] 撤销（Ctrl+Z）后刷新：被撤销的笔不再出现
- [ ] 清空画布后刷新：墨迹为空，且库中该文档墨迹已清

### 多文档隔离

- [ ] 文档 A 画一笔 → 切到文档 B（无墨迹）→ 切回 A：A 的墨迹完好
- [ ] 文档 A、B 各画不同笔迹 → 来回切换互不串味
- [ ] 删除含墨迹的文档：该文档墨迹随之清理；随后拉取后端快照，**不出现幽灵墨迹**
- [ ] 新建文档：墨迹为空，不与任何既有文档共享

### 坐标与视图

- [ ] 缩放 / 平移画布后落库，刷新后墨迹与节点的相对位置不变（世界坐标正确）
- [ ] 空文档（无任何节点）时也能作画、保存并还原（擦写板路径，空态不遮挡墨迹）
- [ ] 主题切换、视图三态切换后墨迹渲染正常

### 性能与边界

- [ ] 连续快速画多笔，落库 IPC 受 400ms 防抖收敛（不逐笔往返）
- [ ] 连续快速画多笔，快照推送受 2.5s 节流收敛（不随每笔 POST 后端）
- [ ] 画完立即切换文档，最后一笔不丢（`flushInk()` 生效）
- [ ] 关闭窗口/应用前画的一笔不丢（卸载前 flush 生效）
- [ ] 单文档笔迹数超过 800 上限时被截断且不报错（返回 `truncated`），界面不卡顿

### 同步与兼容

- [ ] 导出 PNG 仍包含墨迹（与改动前行为一致）
- [ ] 跨设备：A 机画一笔 → 同步 → B 机拉取后能看到该笔迹
- [ ] 后端快照文件 `{storagePath}/clip-storage/graph/canvas-state.json` 出现 `ink` 字段，且 `version` 为 `3`
- [ ] 「只画笔迹、不动节点」时快照 `updatedAt` 会前进，墨迹能推送到后端（不被 last-write-wins 吞掉）
- [ ] 旧版本升级（v2 快照 / v7 库，均无 ink）：节点、大纲、坐标、分组均不受影响，墨迹为空且不报错

## 三、范围边界确认（本批明确不做）

- [ ] （确认为预期）墨迹**不出现**在层级大纲面板中
- [ ] （确认为预期）导出 Markdown **不包含**墨迹信息
- [ ] （确认为预期）点击「一键按大纲排版」后，墨迹**不随节点平移**，可能与卡片错位
- [ ] （确认为预期）墨迹与节点之间**没有**归属/吸附关系，移动节点不会带动墨迹
- [ ] （确认为边界）跨设备同步假定两端同版本；v2/v3 双版本混跑时，旧端会用无 ink 快照覆盖后端致墨迹丢失（canvas-sync 全量 last-write-wins 固有边界，本批不修）
