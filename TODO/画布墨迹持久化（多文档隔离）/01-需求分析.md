# 需求分析：画布手绘墨迹持久化（多文档隔离）

## 原始需求

画布上的手绘墨迹（画笔 / 荧光笔 / 橡皮）目前只存在于前端内存，一旦刷新页面、重启应用或切换画布文档就全部丢失。本批要求让墨迹「不再静默丢失」：持久化落库、按画布文档隔离、并纳入跨设备同步快照。

「墨迹与节点建立关联、按大纲排版与转大纲时带上墨迹」属于完整版内容，列入后续阶段，本批不做。

## 现状与问题

墨迹在代码里是一块纯前端内存的「临时擦写板」：

- **数据**：`frontend/canvas.js` 模块级变量 `strokes = []`，元素形如 `{color, width, opacity, points:[[x,y]...]}`；坐标为**世界坐标**，渲染在 `g.ink-layer` 内，随画布缩放平移。
- **渲染**：`renderInk()` 从 `strokes` 全量重绘；`ensureInkLayer()` 让空文档也能当擦写板用。
- **落库**：**完全没有**。`electron/` 全目录无任何 ink/strokes 表或字段；快照 `buildSnapshot` 只输出 `{docs, nodes, edges, layout, groups}`。
- **导出口径不一致**：导出 PNG 会把墨迹截进去（只隐藏了 `.draw-toolbar / .minimap / .legend / #drawOverlay`，`ink-layer` 未隐藏），而导出 Markdown 完全忽略墨迹。

由此产生的缺陷：

| 场景 | 现状 |
|---|---|
| 切换画布文档 | `switchDoc()` 直接 `strokes = []` → 墨迹丢失，且**无任何提示** |
| 刷新 / 重启应用 | 墨迹丢失（不进快照、不进 SQLite） |
| 跨设备同步 | 另一台设备完全看不到墨迹 |
| 多文档隔离 | 墨迹是全局一块草稿板，不属于任何文档 |

## 分析结论

- 墨迹属于「手动画布层」的增量创作数据，与 `canvas_node / canvas_edge / canvas_layout / canvas_group` 同性质，因此应**照抄既有画布层的落地范式**（新表 → IPC → 快照），不新造任何存储机制。
- 存储位置无需新增配置：本地索引库固定在 `{storagePath}/.index/app-index.sqlite`，后端权威快照固定在 `{storagePath}/clip-storage/graph/canvas-state.json`，两者都挂在设置模块的「数据文件存储路径」下。
- 墨迹的最小管理单位是**「一笔」**（整笔增、整笔删），不是「一个点」，这决定了表结构与落库策略（一笔一行 + 整文档全量替换）。
- 当前 `strokes` 元素**没有稳定 id**，无法与库中行对账；落库前必须补 id。

## 范围

**本批做**：SQLite 新表 + schema v8 迁移、本地索引模块与 IPC、快照 v3（含 v2 兼容）、前端按文档载入与防抖落库、切换文档/删除文档/清空时的正确性、单测与全量回归。

**本批不做**（留后续阶段）：墨迹与节点建立归属关系、一键按大纲排版时带着墨迹平移、转大纲与 Markdown 导出中表达墨迹、墨迹的富样式编辑（更多颜色/线型/文字标注）。
