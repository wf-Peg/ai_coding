# 需求分析：产品开发工作区MVP设计与实现

## 原始需求

每次与编码 agent 的交互（需求分析→设计→开发→验收）产生的设计产出，缺少自动归档到系统剪藏/待办模块的机制，导致设计记录丢失、无法追溯。原有设计过重（仪表盘、甘特图、知识图谱、独立 ProductDev 数据存储），数据链路是断的——agent 产出没有真正落库到剪藏/待办。

## 分析结论

MVP 聚焦核心：打通链路，让 agent 产出自动落库为剪藏和待办，通过工作台规则系统展示。不建设知识图谱、甘特图、独立 ProductDev 存储。

## 会话摘要

- 审阅了未提交的 md 文件，发现 ClassCastException 风险、字段不匹配（file/label/type → contentFile/title/category）、重复初始化器等问题
- 重写 TodoScannerService，对齐 spec 字段契约
- 合并 ProductDevWorkspaceInitializer 为唯一初始化器
- 删除旧的 ProductDevController/Service/Record 独立数据源
- 实现规则 AND 匹配模式支持
