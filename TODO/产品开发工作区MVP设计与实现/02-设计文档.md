# 设计文档：产品开发工作区MVP设计与实现

## 一、TODO 目录规范设计

### 目录结构

```
TODO/
├── {需求中文概述}/
│   ├── feature-points.json          # ★ 核心约定文件
│   ├── 01-需求分析.md              # 原始需求、分析结论、会话摘要
│   ├── 02-设计文档.md              # 技术方案、架构设计、接口定义
│   ├── 03-实施任务.md              # 可拆分的子任务列表
│   └── 04-验收清单.md              # 验收项 checklist
```

### feature-points.json 结构

- version: "1.0"
- requirement: title, summary, tags, phase, createdAt, completedAt
- featurePoints[]: id, name, description, layer, tags, clips[], todos[]
- config: clipCategory, todoCategory, autoTag

### 导入标记 .imported

JSON 格式 `{importedAt, featurePointIds[]}`，用于增量导入幂等判断。

## 二、TodoScannerService 扫描落库

### 扫描流程

1. 扫描 TODO/ 下所有子目录
2. 检查是否有 feature-points.json
3. 读取 .imported 中的 featurePointIds
4. 对每个 featurePoint，仅导入 id 未出现在 featurePointIds 中的功能点
5. 解析 clips → 调用 ClipService.createClip()
6. 解析 todos → 调用 TodoService.saveTodo()（status=done 映射 completed=true）
7. 更新 .imported 文件

### 字段映射

- clip: title, contentFile→读取内容, section→截取章节, category, tags
- todo: title, priority, status→completed boolean

## 五、规则 AND 匹配模式

### 设计

- Workspace 新增 boolean matchAll 字段（默认 false）
- matchAll=true 时：内容必须匹配所有启用的规则
- matchAll=false 时：保持原有 OR 行为，任意匹配即可
- 手动/关系成员始终绕过规则匹配

详情视图规则面板下方增加 toggle slider 切换 AND/OR 模式
