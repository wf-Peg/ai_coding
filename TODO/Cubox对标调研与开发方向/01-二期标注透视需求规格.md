# 二期「标注透视」需求规格说明书

创建日期：2026-09-09　状态：已定版 · 暂不开发（属一期规格书 8.2 节二期事项第 1 项）

## 1 背景与定版结论

一期（见 `00-需求规格说明书.md`）已完成标注的「打标段」：插件在网页上多色高亮、写想法、随剪藏入库，剪藏详情页可查看标注并跳回原网页。但「看标段」只做了一半——标注散在全库各剪藏条目下，没有一个汇总入口，用户回忆"我在哪篇文章标过什么"时只能逐条翻。

二期把标注的「看标段」补完：在知识模块增加标注透视列表，把全库标注汇总成一张可筛选的列表。

### 1.1 定版决策记录

| 编号 | 决策 | 结论 |
| --- | --- | --- |
| P1 | 标注是不是独立功能模块 | 不是。数据上标注挂在剪藏条目下（一期 FR-3.1 已定版），不单独成库；入口上标注透视是知识模块内的一个子页，不加顶栏独立入口 |
| P2 | 完成形态 | 知识模块新增「标注透视」子页（与详情/图谱/编辑器子页并列）+ 剪藏列表项标注角标 |
| P3 | 读写权限 | 本期透视只读。标注的增删改仍由浏览器插件端（打标）完成，透视页不做编辑，避免两端写冲突 |
| P4 | 筛选实现 | 后端接口一次返回全量标注，颜色/来源/时间筛选全部前端本地完成（个人库量级小，避免多次请求的复杂度） |
| P5 | 跳转语义 | 点标注跳所属剪藏详情（剪藏模块），「回原文」直接开原网页新标签 |

### 1.2 现状确认（回答两个定版问题）

- 剪藏详情页的「网页标注」区是条件渲染：仅当该剪藏 `annotations` 非空时显示，无标注的剪藏不显示该区块 [已确认，一期实现如此]。
- 剪藏列表与编辑器模块当前看不到标注内容 [已确认]，编辑器按 D5 定版永不做标注展示。

## 2 目标

- 所有标注一张列表全看到：进「标注透视」页即可浏览全库标注，不再逐条翻剪藏；
- 找得到来源：每条标注一眼看到颜色、来源网页、时间，可跳所属剪藏、可回原网页；
- 列表不盲区：剪藏列表项显示标注角标，知道哪些条目有标注、有几条。

衡量方式：个人工具不做埋点，以自用"找标注不用翻剪藏"的体验感知为准 [Assumption — 沿用一期]。

## 3 用户与核心场景

- S4-1 按色回看（高频）：只记得"那段话我标的是黄色"，按颜色一筛全部列出来；
- S4-2 按源回看：回忆"在那个站点标的"，按来源站点筛选；
- S4-3 按时间回看：最近一周标过什么，一眼看完；
- S4-4 列表速览：在剪藏列表扫一眼就知道哪些条目带标注。

## 4 需求总览

| 编号 | 模块 | 说明 |
| --- | --- | --- |
| FR-4.1 | 后端·标注聚合接口 | 新增按全库聚合标注的接口，返回拍平的标注列表（带所属剪藏信息） |
| FR-4.2 | 知识模块·标注透视子页 | 新增「标注透视」页面，展示标注列表，入口与图谱/编辑器并列 |
| FR-4.3 | 透视·筛选器 | 按颜色（4 色）、来源（站点）、时间（全部/近 7 天/近 30 天）前端本地筛选 |
| FR-4.4 | 透视·跳转 | 点标注跳所属剪藏详情；「回原文」开原网页新标签 |
| FR-4.5 | 剪藏列表·标注角标 | 剪藏列表项显示标注角标「标 N」，无标注不显示 |

## 5 模块设计

### 5.1 FR-4.1 后端标注聚合接口

- 路径：`GET /api/clip/annotations/all`，无必填参数；
- 响应：`List<Map<String,Object>>`，复用一期 `getAnnotationsByUrl` 的拍平结构并扩展字段，每项包含：
  - 标注字段：`id`、`text`、`note`、`color`、`createdAt`、`updatedAt`、`sourceUrl`、`sourceTitle`；
  - 所属剪藏字段：`clipId`、`clipTitle`、`clipCategory`、`clipCreatedAt`；
- 排序：按标注 `createdAt` 倒序（新的在前）；
- 空库语义：返回空数组，HTTP 200；
- 实现：`ClipService` 新增 `getAllAnnotations()`，遍历 `storageService.getAllClips()` 收集标注（逻辑与 `getAnnotationsByUrl` 同源，抽公共方法避免复制）；
- 边界：`text/note` 超长不截断，交给前端显示截断；标注数上限不设（个人库量级），预留 `limit` 参数位但本期不实现 [Assumption — 个人库量级小，全量遍历可接受]。

### 5.2 FR-4.2 知识模块标注透视子页

- 新增 `frontend/knowledge-annotations.html` + `frontend/knowledge-annotations.js`，沿用知识模块子页模式（`location.href` 跳转、`window.API_BASE_URL`、design-tokens 样式）；
- 入口：`knowledge.html` 现有的图谱/编辑器入口旁增加「标注透视」入口按钮，风格一致；
- 页面结构：顶栏（返回知识库 + 页面标题 + 标注总数）→ 筛选器行 → 标注列表；
- 数据加载：进入页面调 FR-4.1 接口；失败时显示错误提示 + 重试按钮，不静默空白；
- 空状态：全库无标注时显示引导文案「还没有标注，去网页选中文字试试」+ 说明入径（浏览器插件标签页）。

### 5.3 FR-4.3 筛选器（前端本地筛选）

- 三组筛选，全部客户端过滤，组合生效：
  - 颜色：全部 / 黄 / 绿 / 蓝 / 紫（色点标识）；
  - 来源：去重后的站点名（由 `sourceTitle` 派生，取 main 域名或标题），下拉选择；
  - 时间：全部 / 近 7 天 / 近 30 天（按 `createdAt` 计算）；
- 筛选无结果时内联提示「当前筛选下没有标注」，可一键清空筛选；
- 筛选状态不持久化（刷新回默认全部）[Assumption — 保持轻量]。

### 5.4 FR-4.4 列表项与跳转

- 每条标注卡片：左侧色条（按 color）→ 高亮原文（超 3 行截断 + 展开）→ 想法（有则显示，可收起）→ 元信息行（来源标题 · 创建时间 · 所属剪藏标题）→ 操作（「看详情」「回原文」）；
- 「看详情」：跳转所属剪藏详情，`clip.html?id={clipId}` 直达。当前 `clip.html`/`clip-list.js` 不解析 URL id 参数 [已核实]，本需求新增「剪藏页解析 `?id=` 参数并自动打开对应详情」作为 FR-4.4 的实现范围（页面加载后读参数、拉详情、渲染，约数行代码）；
- 「回原文」：`sourceUrl` 新标签打开（`rel="noopener noreferrer"`），无来源时按钮禁用；
- 交互细节遵循全局样式与用户偏好：色点/色条循环四色、hover 反馈、滚动条全局同款。

### 5.5 FR-4.5 剪藏列表标注角标

- 剪藏列表项（`frontend/js/clip-list.js` 渲染处）当 `clip.annotations` 非空时，在标题行显示角标「标 N」（N 为条数），无标注不显示；
- 数据前提：已核实 `ClipContent` 无 `@JsonIgnore`，Jackson 默认序列化全部 getter，`GET /api/clip/list` 返回对象已含 `annotations` 字段 [已核实]，角标直接读取无需额外接口。

## 6 实施顺序

1. 后端：`ClipService.getAllAnnotations()` + `ClipController` 新接口 + 冒烟验证（老库空标注返回空数组、新库返回拍平数据）；
2. 前端：`clip-list.js` 标注角标（改动最小，最先见效）；
3. 前端：`knowledge-annotations.html/.js` 子页 + `knowledge.html` 入口 + 筛选器 + 跳转；
4. 联调验收：按第 8 节 AC 逐项核对。

## 7 明确不做（本期）

- 标注编辑/删除（透视页只读，写方仍是插件）；
- 编辑器模块任何标注展示（D5 已定）；
- 顶栏独立「标注」入口（知识模块子页内达成，P1 已定）；
- 标注导出（Markdown/CSV）与跨库搜索合并（后续需求另立）；
- 缓存/持久化筛选状态。

## 8 验收标准

| 编号 | 验收 |
| --- | --- |
| AC-P1 | 知识模块有「标注透视」入口，点击进入子页，与图谱/编辑器入口并列不破坏原布局 |
| AC-P2 | 子页列出全库标注（含一期入库的高亮数据），每条显示色条、原文、想法、来源、时间 |
| AC-P3 | 颜色/来源/时间筛选组合生效，筛选无结果有提示且可一键清空 |
| AC-P4 | 「看详情」打开所属剪藏详情；「回原文」新标签打开原网页，无来源时按钮禁用 |
| AC-P5 | 剪藏列表项：有标注的条目显示「标 N」角标，无标注不显示 |
| AC-P6 | 老库兼容：历史剪藏无标注字段时接口返回空数组、页面正常显示空状态，不报错 |
| AC-P7 | 接口失败时子页显示错误提示与重试，不静默空白 |

## 9 风险与假设

- 跳转路由：`clip.html` 的 `?id=` 直达解析为本需求新增实现（已列入 FR-4.4 范围）[已核实]；
- 列表字段：`annotations` 随列表接口返回，无需另做计数接口 [已核实]；
- 性能：聚合接口全库遍历，个人库（当前 82 文件量级）可接受；未来量大再加 limit 分页 [Assumption]；
- 兼容：老条目无 `annotations` 字段行为一期已验证（空列表），本接口复用同一模型无新增风险；
- 依赖：不新增 AI 依赖，不受 DashScope 额度问题影响 [已确认，本功能为纯查询+展示]。
