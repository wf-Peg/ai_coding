# CutShelter 数据层重构与用户习惯聚合开发计划

> 状态：按 TDD 分阶段实施  
> 更新日期：2026-08-02

## 目标

保留现有 JSON 业务数据和本地优先特性，新增可重建的统一索引、关系、项目和习惯统计层。该计划不建设 Agent 平台，不自动移动或修改用户数据。

## 重构顺序

1. **Phase 0：统一内容引用**
   - 定义 `ContentRef`、`ContentRelation` 和映射器。
   - 为剪藏、知识、待办、学习计划、编辑器文件建立稳定引用 ID。
   - 先兼容旧 JSON，不改变现有实体存储格式。
2. **Phase 1：只读内容索引**
   - 新增 `ContentIndexService`。
   - 扫描现有业务目录生成可重建索引。
   - 提供状态、重建和搜索接口。
3. **Phase 2：关系索引**
   - 统一 `sourceClipId` 和后续项目关系。
   - 支持来源链、反向查询和幂等关系写入。
4. **Phase 3：轻量项目模型**
   - 支持手动创建项目、加入内容、项目内搜索和默认偏好。
   - 不自动创建项目，不自动移动文件。
5. **Phase 4：用户行为事件**
   - 记录打开、编辑、保存、分类、标签、转换、项目关联等轻量事件。
   - 本地 JSONL，异步写入，默认保留 30～90 天。
6. **Phase 5：习惯画像**
   - 聚合常用分类、标签、目录、文件类型、动作和时间段。
   - 使用计数 + 时间衰减，不引入机器学习。
7. **Phase 6：项目聚合建议**
   - 根据标签、分类、目录、时间和连续操作生成可解释建议。
   - 用户确认后才建立项目关系，支持忽略和永久拒绝。

## 数据目录

```text
业务数据：{storagePath}/
  clip-storage/ todoList/ knowledge/ topic/ learning-plan/ vault/

应用索引：~/.cut-shelter/config/index/
  content-index.json
  relation-index.json
  project-index.json
  habit-profile.json
  action-events.jsonl
```

索引不是数据真相，损坏后必须可以通过业务目录重建。配置、行为数据和索引不得写入用户选择的业务数据目录之外的随机位置。

## TDD 约束

- 每个阶段先写失败测试，再实现最小代码。
- 映射、索引、关系和评分逻辑优先使用纯单元测试。
- 文件系统测试使用临时目录，不能读写用户真实数据。
- 重建操作必须幂等，失败不能影响编辑器和剪藏主流程。
- 自动建议必须包含原因、置信度、确认、忽略和永久拒绝状态。

## Phase 0 首批验收

- `clip:1001`、`knowledge:2001`、`todo:3001` 等引用 ID 稳定且类型明确。
- 标题、分类、标签、来源路径和创建时间能从现有实体正确映射。
- 缺失字段和旧 JSON 字段不会抛出异常。
- 相同实体重复映射结果一致。
- `ContentRef` 不携带正文，避免索引重复保存用户内容。

## 观测页面第一版

- 页面展示内容索引、关系索引、项目、成员关系和行为事件数量及更新时间。
- 页面展示常用分类、标签、最近动作和活跃日数量，明确提示数据仅用于本地整理建议。
- 提供“刷新数据”和“重建内容索引”操作；重建只扫描业务目录，不修改原始内容。

## 第二轮落地状态（2026-08-03）

- 增加 `ContentIndexAutoSyncService`：应用启动时重建一次，之后按配置周期（默认 5 分钟）后台校准内容索引；失败只记录日志，不阻塞主流程。
- 增加 `UserActionEventRecorder`：剪藏新增、编辑、删除会记录本地 JSONL 事件；事件采集为 best-effort，不影响剪藏接口。
- 观测页面主题变量改为使用统一设计令牌，并补充父页面主题初始化和主题广播，因此深色皮肤下卡片、文字、按钮、进度条均能正确适配。
- 下一优先级是把行为事件扩展到编辑器打开/保存、待办操作，并接入项目推荐确认流；本轮暂不自动建立项目关系。

## 项目概念设计（下次开发前置约束）

当前软件没有“项目”概念，第一版项目定义为用户主动创建的轻量聚合工作视图，而不是新的文件夹、数据库或内容副本。项目只保存名称、描述、颜色、状态和成员引用；原始内容继续留在剪藏、知识、待办或编辑器文件中，项目删除或归档不得删除原始内容。

### 数据关系

```text
原始数据 → ContentRef（可重建索引） → ProjectMembership（用户确认的成员关系） → 项目工作视图
```

- `ContentRef` 描述内容是什么、在哪里、属于什么类型。
- `ProjectMembership` 描述内容是否被用户确认加入项目，以及 `source/reason/confidence`。
- `ContentRelation` 描述来源、引用和转换关系，不等同于项目成员关系。
- 一个内容可以属于多个项目；移除成员只删除关系，不修改内容。

### 第一版模型与生命周期

```text
Project: id(p_<uuid>), name(1～60), description(≤500), color, status(active/archived), createdAt, updatedAt
ProjectMembership: projectId, contentId(ContentRef.id), source(manual/suggestion/import), confidence, reason, createdAt
```

用户先手动创建空项目，再从内容详情、编辑器文件树或观测页加入内容。项目支持查看成员、移除成员、归档和删除；删除项目必须二次确认，只删除项目及成员关系。第一版不保存正文、规则或 AI Prompt，正式创建统一使用 `p_<uuid>`。

### 推荐边界

第一版不自动创建项目，也不因一次操作就推荐。只有存在 active 项目，且候选内容与已有成员在标签、分类、目录或近期操作上形成稳定重合时才展示建议。建议卡片必须包含目标项目、候选内容、评分、原因、加入和忽略操作；低于 0.55 不展示。用户确认后才写入成员关系，忽略支持冷却期和永久拒绝。

## 后续开发顺序与待完成内容

### P0：项目基础能力

- [ ] 新增项目列表、创建、更新、归档、删除接口。
- [ ] 增强 `ProjectIndexService` 的按 ID、按状态查询和安全删除。
- [ ] 项目成员关系保持幂等，支持 `source/reason/confidence` 和非法 `contentId` 校验。
- [ ] 新增项目页：空状态、成员列表、移除成员、归档和删除确认。
- [ ] 内容详情、编辑器文件树、观测页增加“加入项目”入口。

### P1：行为事件与观测

- [ ] 记录编辑器打开/保存/文件切换、待办创建/完成、标签变更和项目操作。
- [ ] 统一事件字段：`eventType/contentId/projectId/metadata/createdAt`。
- [ ] 事件异步写入，支持坏行跳过、保留期清理和诊断导出。
- [ ] 观测页增加近 7/30 天趋势、未整理数量、项目采纳率和忽略率。

### P2：推荐确认流

- [ ] `ProjectSuggestionService` 输出稳定 suggestion ID。
- [ ] 推荐状态支持 `pending/accepted/ignored/rejected`。
- [ ] 接受建议后写入成员关系并记录 `suggestion_accepted` 事件。
- [ ] 忽略、永久拒绝可撤销；同一候选在冷却期内不重复提示。
- [ ] 推荐服务只读取索引和画像，不修改原始正文。

### P3：索引与恢复

- [ ] 内容新增/编辑/删除优先增量更新，定时全量重建作为兜底。
- [ ] 索引增加 `schemaVersion/sourceSnapshotAt/rebuildReason`。
- [ ] 分别提供内容、关系、项目和行为事件健康状态。
- [ ] 索引损坏时隔离坏文件并自动重建，不阻塞应用启动。

## 下次 TDD 清单

1. 项目 API：创建、重复名称策略、归档、删除不影响内容。
2. 成员关系：重复加入、跨项目加入、移除、非法引用、幂等重放。
3. 行为事件：编辑器/待办事件、异步失败降级、坏行恢复、保留期清理。
4. 推荐状态：评分、稳定 ID、接受/忽略/永久拒绝和冷却期。
5. 前端逻辑：空状态、加入/移除反馈、推荐确认、主题切换和错误恢复。
6. 最后执行后端全量测试、Electron 页面语法检查和桌面/浏览器冒烟测试。

## 明确不做

- 不把项目实现成第二套内容存储，不自动移动文件、修改分类或删除内容。
- 第一版不引入团队协作、权限、云同步和跨设备项目。
- 不以 AI 生成项目名称作为唯一入口；AI 只能提供候选，用户必须确认。
- 行为画像默认不上传云端，除非未来单独设计并取得授权。
