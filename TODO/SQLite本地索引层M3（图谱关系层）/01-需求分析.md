# 需求分析：SQLite本地索引层M3（图谱关系层）

## 原始需求

在 SQLite 本地索引层（一期已覆盖 clip 内容索引 + FTS 全文搜索）基础上，进入第二阶段：新增 `relation` 表替代 Java 侧 `index/relation-index.json`，为前端知识图谱提供统一的关系数据源，逐步脱离 Spring Boot。

## 分析结论

- 一期只索引 clip；图谱关系需要 knowledge / learning-plan 节点，因此 M3 把这批实体一并纳入 `content` 表（type=knowledge/learning-plan），与 clip 共用索引与 FTS 能力，顺势打通「全库统一搜索」。
- 关系端点需依赖实体索引存在，故 M3.2 先行扩展扫描器。
- 前端知识图谱页（knowledge-graph.html）原本走后端 `GET /api/graph` 全量内存扫描；M3 改为本地索引 IPC 优先，失败回退 REST。
- 权威数据源仍为 JSON 文件：「文件为真、库为缓存」，故关系采用「全量重建 + 每次合并遗留文件」策略。
