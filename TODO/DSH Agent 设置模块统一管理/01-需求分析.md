# 需求分析：DSH Agent 设置模块统一管理

## 原始需求

设置模块的 DSH Agent（AI 干活）模块能否统一集中管理 DSH 的功能？目前「打开插件市场」按钮和「打开面板」一样只是浏览器打开网页，设计冗余了；还需要完善哪些方面，抓住核心功能不要过度复杂化。

## 分析结论

1. **设置区块已是 DSH 的事实管理中心**：启用开关 / 端口 / dsh CLI 路径 / 技能包 / 插件市场 / 操作（启动/停止/打开）/ 升级助手，均已集中在 `frontend/settings.html` 的「DSH Agent（AI 干活）」区块。因此「统一集中管理」已基本成立，缺的是**去冗余与语义收敛**。

2. **核心冗余**：`btnOpenDshMarket`（打开插件市场）与 `btnOpenDshAgent`（打开面板）代码完全相同，都是 `window.open('http://127.0.0.1:' + port)`；加上导航「AI 干活」的 iframe 内嵌面板，实际有 3 个「打开 DSH」入口。而插件市场只是 DSH 自身 UI 里的一项（DSH → Settings → Plugin Market），无需独立入口。

3. **待完善点（抓住核心，不扩 scope）**：
   - 删除「打开插件市场」按钮，把 dshmarket 预装状态折叠为被动说明文字。
   - 「打开面板」语义澄清为「浏览器打开完整 DSH UI」，与应用内 iframe 区分。
   - （低优先级）「保存设置」明示启用开关即时生效、端口/CLI 路径重启生效。

4. **连带发现的 fp012 缺口**：自动归档记录 `project=''/fpId=''`，产品概览按 `fpId===item.id` 过滤导致「入库但不可见」，需最小补缺（总览页「AI 干活记录」区块）。

## 会话摘要

本次会话同时以「DSH Agent 设置模块统一管理」这一真实需求作为测试用例，验证 fp012「会话级自动摘要落库」方案：回合结束自动归档（source=dsh-session）应把本次工作成果写入产品概览迭代记录，无需 Agent 显式调用 clip_session。
