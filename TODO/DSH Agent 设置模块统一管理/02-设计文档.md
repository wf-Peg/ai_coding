# 设计文档：DSH Agent 设置模块统一管理

## 架构设计

设置区块（`frontend/settings.html` + `frontend/js/settings.js`）作为 DSH 唯一配置/生命周期管理入口，保持「即时生效」语义；应用内「AI 干活」面板（`frontend/index.html` iframe）负责内嵌 Agent 交互，二者入口分离、职责清晰。

## 技术方案

### fp-001 去冗余与集中管理（frontend）
- 删除「插件市场」setting-row 与「打开插件市场」按钮。
- `dshMarketStatusDesc` 迁移到「技能包」行作为被动说明；`settings.js` 的 `refreshMarketStatus` 仅更新该元素文案，去掉按钮禁用逻辑；删除 `btnOpenDshMarket` 点击监听。
- 「打开面板」按钮加 `title` 提示 + 「操作」行补充静态说明，明确其为浏览器打开完整 DSH UI（含 Settings → Plugin Market）。
- 同步更新 `integrations/dsh/README.md` 中的使用路径描述。

### fp-002 产品概览「AI 干活记录」可见性（frontend）
- `workspace.html` 总览 Tab「最近活动」下新增 `pdAiArchiveList` 容器。
- `workspace.js` 新增 `renderPdAiArchive()`：过滤 `pdIterations` 中 `source ∈ {dsh-session, dsh-agent}` 的记录，按 `createdAt` 倒序，渲染四字段（title/problem/solution/outcome）+「AI 干活」徽标 + 时间；在加载流程 `renderPdTaskList` 之后调用。
- `workspace.css` 补 `.pd-ai-archive-list` 最小样式（纵向列表 + 限高滚动），复用既有 `.pd-iter-*` 类。

## 接口定义

- 无新后端接口；复用既有 `GET /api/workspace/feature-points/iterations`（前端已全量缓存于 `pdIterations`）。
- 无 Electron IPC 改动（`dshAgentMarketStatus` 仍被 `refreshMarketStatus` 使用）。

## 关键决策

- **不改后端 / 不改 clip-capture 插件 / 不改升级助手逻辑**：本次仅为前端去冗余 + 产品概览可见性补缺。
- **自动归档可见性**：选择「新增总览页 AI 干活记录区块」而非「给自动归档记录补 project/fpId」，因为自动归档无法可靠推断所属需求目录，区块式展示更通用。
- **独立需求目录归档**：新建 `TODO/DSH Agent 设置模块统一管理/`，保证「本次任务」在产品概览中独立可见。
