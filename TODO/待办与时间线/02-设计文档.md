## 二、功能分离设计

### 2.1 待办事项页面（todo.html）

- 基于 timeline-todo.html 的设计
- 包含完整的待办事项时间线功能
- 包含优先级、筛选、编辑等功能
- 独立的样式和脚本
- 集成后端 API 调用

### 2.2 剪藏页面（clip.html）

- 从 index.html 中提取剪藏相关代码
- 保留所有剪藏功能和样式
- 确保 API 调用正常
- 独立的样式和脚本

### 2.3 导航页面（index.html）

- 创建简单的导航界面
- 添加两个功能的入口链接
- 响应式设计，在小屏幕上自适应

## 三、数据存储设计

### 3.1 数据模型

```json
{
  "id": "唯一标识符",
  "title": "待办事项标题",
  "priority": "high/medium/low",
  "deadline": "截止日期",
  "completed": "true/false",
  "createdAt": "创建时间",
  "category": "分类"
}
```

### 3.2 存储结构

- **存储路径**：`./clip-storage/todolist/{date}.json`
- **整理结果**：`./clip-organized/todolist/{date}.md`
- **存储格式**：JSON 格式，按日期组织
- **字段拼接**：`字段名/字段值` 方式拼接存储（如：`title/完成方案设计 priority/high deadline/2026-04-20`）

### 3.3 后端接口

| 接口 | 方法 | 说明 |
|------|------|------|
| /api/todo | GET | 获取所有待办事项 |
| /api/todo/date/{date} | GET | 按日期获取待办事项 |
| /api/todo | POST | 创建待办事项 |
| /api/todo/{id} | PUT | 更新待办事项 |
| /api/todo/{id} | DELETE | 删除待办事项 |

### 3.4 后端组件

1. **TodoContent 模型类**：包含 id、title、priority、deadline、completed、createdAt、category 字段
2. **FileStorageService**：添加 saveTodo、getAllTodos、getTodosByDate、deleteTodo 方法
3. **TodoService**：实现待办事项的业务逻辑，调用 FileStorageService 进行存储操作
4. **TodoController**：实现 REST API 接口，处理前端请求

## 四、时间线UI/UX设计

### 4.1 交互流程

```
添加待办：点击'+'号按钮 → 打开添加模态框 → 填写信息 → 提交 → 刷新时间线
查看详情：点击待办项右下角'...'按钮 → 打开详情模态框 → 查看详情 → 关闭
滚动浏览：鼠标滚轮在时间线区域垂直滚动 → 内容自动换行 → 无横向滚动条
```

### 4.2 模态框设计

- **添加待办模态框**：包含标题输入、优先级选择、截止日期选择、分类选择、提交/取消按钮
- **详情模态框**：展示待办完整信息，支持编辑和删除操作
- **交互行为**：支持 ESC 快捷键关闭、点击模态框外部关闭、平滑动画效果

### 4.3 样式设计

- **'+'号按钮**：浮动按钮设计，固定在时间线底部，悬停效果
- **时间线滚动**：overflow-y: auto 实现垂直滚动，overflow-x: hidden 禁用横向滚动
- **详情按钮**：每个待办项右下角'...'按钮，悬停显示提示
- **内容截断**：过长内容自动换行，不出现横向滚动条
- **模态框**：现代化设计，平滑动画，响应式布局

## 五、分区显示布局设计

### 5.1 布局比例

- **待办事项页面（todo.html）**：占屏幕 1/3 宽度
- **剪藏页面（clip.html）**：占屏幕 2/3 宽度
- **导航页面（index.html）**：全屏导航设计

### 5.2 技术方案

- **CSS Flexbox/Grid**：实现灵活的页面布局
- **HTML5 语义化标签**：构建清晰的页面结构
- **响应式设计**：确保不同设备上的良好体验
- **主题变量**：颜色、字体、间距保持一致的设计风格

## 六、风险评估

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 功能迁移导致功能丢失 | 高 | 仔细测试所有功能，确保迁移后的页面功能完整 |
| 布局调整影响用户体验 | 中 | 进行充分的响应式测试，确保不同设备上的良好体验 |
| 存储路径问题 | 中 | 确保 todolist 目录正确创建 |
| 数据格式问题 | 中 | 确保待办事项数据格式正确 |
| API 接口问题 | 中 | 确保前端 API 调用正确 |
| 兼容性问题 | 中 | 确保与现有剪藏功能兼容 |
