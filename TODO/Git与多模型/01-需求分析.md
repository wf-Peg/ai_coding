# Git与多模型 - 需求分析

## 一、需求背景

### 1.1 Git 功能现状问题

当前 Git 操作存在以下问题：

1. **缺少远程仓库配置** - Git pull 失败提示 `If you wish to set tracking information for this branch you can do so with: git branch --set-upstream-to=1/<branch> master`，push 失败提示 `fatal: No configured push destination`
2. **配置未持久化** - GitConfig 只存储在内存中，重启服务后丢失
3. **Git 工作流程不完善** - 缺少 fetch 步骤、pull/push 未指定 remote/branch、remote 已存在未处理、commit 失败时继续执行 push
4. **缺少前端同步按钮** - 用户无法手动触发 Git 同步操作

### 1.2 多模型现状

当前仅支持阿里云 DashScope 模型，AI 调用通过 `dashscope-sdk-java` 的 `Generation` 类直接调用，配置硬编码在 `DashScopeConfig.java` 中。项目已存在 `spring-ai-openai:0.8.1` 依赖，可用于调用 DeepSeek（OpenAI 兼容 API），但未利用。

### 1.3 Prompt 体系现状

当前 Prompt 体系存在 3 个维度的问题：

1. **架构层** - clipAnalyzePrompt 被 40+ 行硬编码指令截断，用户自定义 Prompt 仅占 10%
2. **设计层** - 6 个 AI 方法使用硬编码 Prompt 完全绕过 PromptConfigService，3 个核心 Prompt 设计哲学不一致（极简/超长/中等）
3. **工程层** - JSON 解析使用手动字符串操作脆弱已多次出问题，缺少版本管理，弹窗 UX 不完善

## 三、用户场景

### 场景 1：首次使用 Git 配置
用户打开应用 → 点击 Git 配置按钮 → 输入远程仓库 URL、用户名、密码、分支名 → 点击测试连接 → 连接成功 → 保存配置 → 后续同步操作自动使用已保存的配置

### 场景 2：日常 Git 同步
用户整理内容或生成周报后 → 自动触发 Git 同步（pull → add → commit → push）→ 同步失败时仅打日志不影响主流程 → 用户也可通过前端同步按钮手动触发

### 场景 3：切换 AI 模型
用户进入设置页面 → 选择 DeepSeek 模型 → 输入 API Key → 点击测试连接 → 确认可用 → 保存 → 后续所有 AI 调用自动使用 DeepSeek 模型 → 无需重启

### 场景 4：自定义 Prompt
用户进入 Prompt 配置弹窗 → 看到完整 Prompt（含模板变量）→ 编辑 clipAnalyzePrompt → 点击预览完整 Prompt → 确认修改后保存 → 保存时自动备份旧版本 → 不满意可回滚到上一版本

### 场景 5：桌面端模型配置
用户打开 Electron 桌面端配置窗口 → 在模型选择区域选择 DeepSeek → 输入 API Key → 保存 → 重启应用 → 自动使用 DeepSeek 模型

## 四、需求约束

1. **兼容性** - 多模型接入不破坏现有 DashScope 功能，切换回 DashScope 后原有功能完全正常
2. **安全性** - Git 凭证和 API Key 需加密存储，前端输入支持密码显隐切换
3. **可靠性** - Git 操作失败不影响主流程，仅记录日志；Prompt 修改有版本备份可回滚
4. **性能** - 模型切换支持热切换无需重启，RoutingLlmProvider 每次调用动态路由开销需控制在可接受范围
