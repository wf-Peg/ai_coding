## 二、Git 功能设计

### 2.1 Git 配置管理

**GitConfig.java** 配置类：
```java
public class GitConfig {
    private String remoteUrl = "";
    private String username = "";
    private String password = "";
    private String branch = "master";
    // getter/setter
}
```

**GitController.java** API 端点：
| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/git/config | 获取当前 Git 配置 |
| POST | /api/git/config | 保存 Git 配置 |
| POST | /api/git/test | 测试远程仓库连接 |
| POST | /api/git/sync | 手动触发 Git 同步 |

### 2.2 Git 配置持久化

**GitConfigStorageService.java** 使用 JSON 文件存储配置：
- 路径：`./clip-storage/git-config.json`
- 方法：`saveConfig(GitConfig)` / `loadConfig(): GitConfig`
- 备份机制：保存时自动备份旧版本到 `git-config.json.bak`
- 配置优先级：`git-config.json` > `application.yml` > 默认值

### 2.3 Git 同步流程优化

优化后的执行顺序：
```
1. configureRemoteRepository (先 fetch)
2. git fetch (获取远程更新)
3. git pull (指定 remote/branch)
4. git add (添加更改)
5. git commit (处理无更改情况，无更改跳过 push)
6. git push (使用 -u 设置上游分支)
```

关键技术点：
- remote 已存在时：先 remove 再 add 或直接 update url
- 设置用户配置：`git config user.name` / `git config user.email`
- 并发控制：使用 `ReentrantLock` 防止并发 Git 操作冲突
- 错误处理：Git 操作失败仅打日志，不影响主流程

## 三、多模型设计

### 3.1 LlmProvider 接口

```java
public interface LlmProvider {
    String chat(String systemPrompt, String userMessage);
    String getProviderName();
    boolean isAvailable();
}
```

### 3.2 实现类

| 实现类 | 调用方式 | 依赖 |
|--------|----------|------|
| DashScopeLlmProvider | dashscope-sdk-java Generation 类 | dashscope-sdk-java:2.16.0 |
| DeepSeekLlmProvider | Spring AI OpenAiApi + OpenAiChatModel | spring-ai-openai:0.8.1 |

### 3.3 RoutingLlmProvider 热切换

```java
public class RoutingLlmProvider implements LlmProvider {
    private final ModelConfigService configService;
    private final LlmProvider dashScopeProvider;
    private final LlmProvider deepSeekProvider;

    @Override
    public String chat(String systemPrompt, String userMessage) {
        String active = configService.loadConfig().getActiveProvider();
        LlmProvider provider = "deepseek".equals(active) 
            ? deepSeekProvider : dashScopeProvider;
        return provider.chat(systemPrompt, userMessage);
    }
}
```

### 3.4 ModelConfig 配置管理

```java
public class ModelConfig {
    private String activeProvider = "dashscope";
    private String deepseekApiKey = "";
    private String deepseekModel = "deepseek-chat";
    private String dashscopeApiKey = "";
    private String dashscopeModel = "qwen-plus";
}
```

**ModelConfigController.java** API 端点：
| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/model-config | 获取当前模型配置 |
| POST | /api/model-config | 保存模型配置 |
| POST | /api/model-config/test | 测试模型连接 |

### 3.5 Electron 配置扩展

**config.json 扩展**：
```json

```

## 四、Prompt 体系设计

### 4.1 模板变量方案

将完整 Prompt 改为模板变量模式：
```
{{system_prompt}}
{{task_format}}
{{category_tree}}
{{output_format}}
```

变量替换逻辑：
- `{{output_format}}` → JSON 格式约束
- `{{category_tree}}` → 分类树描述
- `{{date}}` → 当前日期
- `{{count}}` → 条目数
- `{{week_range}}` → 周报日期范围

### 4.2 统一 Prompt 模板结构

每个 Prompt 统一四段式结构：
```
# Role
你是一个...

# Goal
你的目标是...

# Output Format
请严格按以下 JSON 格式返回：
{...}

# Constraints
- 约束1
- 约束2
```

### 4.3 JSON 解析优化

- 替换 extractJsonStringValue / parseProcessResult / parseSimpleJson 为 Jackson ObjectMapper
- 创建 DTO 类：ClipAnalysisResult、KnowledgeExtractionResult
- 解析策略：FAIL_ON_UNKNOWN_PROPERTIES=false（宽松解析）
- 预处理：保留 markdown 代码块清理逻辑（清理 ```json 标记）

### 4.4 Prompt 版本管理

- 保留最近 3 个版本
- 保存时自动备份旧版本
- 备份文件命名：`prompt-config.json.v1`、`prompt-config.json.v2`
- 提供回滚 API：`POST /api/prompt-config/rollback/{version}`
