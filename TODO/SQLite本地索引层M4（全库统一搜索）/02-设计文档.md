# 设计文档：SQLite本地索引层M4（全库统一搜索）

## 架构设计
全库统一搜索复用 M3 已建的 `content` 表 + `content_fts` 倒排索引。`content` 表已统一以 `{type}:{source_id}` 作为 `id` 主键，`type` 列标识 clip/knowledge/learning-plan。搜索路径为：FTS5 MATCH（英文/标点生效）→ 未命中时 LIKE 子串兜底（中文/任意子串），两者都支持 type 过滤。

## 技术方案
- `searchAll(query, { topK, type })`：返回跨全部实体类型的统一命中结构 `{type, id, title, snippet}`。
- type 过滤：`type === 'all' | null | undefined` → 不限制；否则按 `content.type` 等值过滤。
- title/snippet 归一化：clip→title/body 截断；knowledge→title；learning-plan→goal（title 缺省用 goal，snippet 缺省用 phases 拼接）。

## 接口定义
- **IPC**：`local-index:search-all`（入参 `{ query, topK, type }`；返回 `{ success, results: Array<{type,id,title,snippet}> }`）
- **preload**：`window.electronAPI.localIndex.searchAll(query, opts)`
- **apiClient**：`window.apiClient.searchAll(query, { type, topK })`，本地索引优先，REST 兜底 `/api/local-search`

## 关键决策
- **沿用 `content.id` 作为命中 id**：M3 已统一为 `{type}:{source_id}`，前端可直接拼接实体链接，无需二次解析。
- **保留原 clip `search`/`searchByCategory`**：既有调用契约不破坏，全库搜索是新增能力。
- **统一命中结构**：前端只需一套渲染逻辑，类型字段用于路由跳转。
