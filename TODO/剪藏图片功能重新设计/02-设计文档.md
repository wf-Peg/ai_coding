# 剪藏图片功能重新设计 - 设计文档

## 一、架构设计总览

### 1.1 模块关系与数据流

```
[前端/扩展]                              [后端]
粘贴/选择图片
  → canvas 客户端压缩（1600px/q0.82）
  → XHR multipart 上传 ──────────────→ POST /api/clip/image/upload
       （upload.onprogress 进度）         │ magic-byte 校验 → images/{yyMM}/{uuid}.{ext}
  → 光标处插入 ![图片](images/...)        │ 返回 {path, url, size}
  → 维护本地 imagePaths 列表              │
提交剪藏 JSON { content, imagePaths } ──→ POST /api/clip/add
                                          │ 校验 imagePaths 存在 → 写入 ClipContent
[查看剪藏]
  → marked renderer 将 images/... 重写为
    {API origin}/api/clip/image/{yyMM}/{file} ──→ GET /api/clip/image/... (带 ?thumb=1)
[删除剪藏]                                   │ 图片生命周期
  → DELETE /api/clip/{id} ─────────────→ 清理未引用图片文件
[整理]                                     │
  → organize ──────────────────────────→ 复制引用图片到 organized assets + 重写引用
[孤儿清理]                                 │
  → POST /api/clip/image/cleanup-orphans ─→ 扫描清理未被引用图片
[旧数据迁移]                                │
  → POST /api/clip/migrate-images ────────→ 搬文件 + 重写 content + 补 imagePaths
```

### 1.2 存储布局

```
{clip.storage.path}/                    ← 与剪藏同根
├── images/                             ← 剪藏图片（uuid 命名，与分类/整理解耦）
│   ├── 2608/                           ← 按月分片
│   │   ├── 3f2a9c1e-...-uuid.png
│   │   └── ...
│   └── 2609/
├── documents/                          ← doc-ai 源文件（独立目录）
│   └── {uuid}.pdf
└── {category}/...                      ← 剪藏 JSON（不变）

{clip.organized-storage.path}/{category}/assets/{uuid}.{ext}   ← organize 复制出的扁平化图片
```

## 二、核心设计决策

### 2.1 传输：multipart 分步上传（替代 base64 JSON）

- 图片在粘贴/选择时**立即上传**，而非随剪藏提交
- 客户端先 canvas 压缩（最长边 1600px、JPEG q0.82、透明图保留 PNG），体积降 5-10 倍
- XHR `upload.onprogress` 提供进度；单张失败可重试
- 剪藏 JSON 只带文本 + imagePaths（后端校验路径存在）

### 2.2 引用：相对路径存储 + 渲染时重写

- content 中图片引用存**相对路径** `images/{yyMM}/{uuid}.{ext}`
- marked renderer 在渲染时按当前 API origin 重写为绝对 URL
  - 前端/扩展/editor 三处 renderer 统一实现（`rewriteImageSrc` helper）
  - 避免绝对 URL 在端口/前端源变更后失效
- `ClipContent.imagePaths` 为权威引用清单（相对路径），用于生命周期管理

### 2.3 存储：UUID + 按月分片，与分类解耦

- 文件名 `{uuid}.{ext}`，不包含分类/时间戳语义
- 路径 `images/{yyMM}/{uuid}.{ext}`，按月份分片避免单目录膨胀
- 分类变更、organize、重新整理均不影响图片引用

### 2.4 服务端点（新增 ClipImageController）

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/clip/image/upload` | POST | multipart；magic-byte 校验（jpg/png/gif/webp）、上限 10MB；返回 `{path, url, size}` |
| `/api/clip/image/{yyMM}/{fileName}` | GET | UUID 文件读取；`?thumb=1` 返回 256px 缩略图；路径穿越防护（`^[\w.-]+$` + normalize + 限定根） |
| `/api/clip/image/cleanup-orphans` | POST | 清理未被任何剪藏 imagePaths 引用的图片，返回清理数 |
| `/api/clip/migrate-images` | POST | 迁移旧数据（见 2.6） |
| `/api/clip/file/{uuid}` | GET | doc-ai 附件下载（Content-Disposition） |

### 2.5 数据模型变更

- `ClipContent.imagePaths`：语义明确为图片相对路径清单（`images/{yyMM}/{uuid}.{ext}`）
- `ClipContent` 新增 `attachmentPath`：doc-ai 源文件相对路径（`documents/{uuid}.{ext}`），与图片分离
- `ClipRequest` 新增 `imagePaths`（List\<String\>）；`imageDataList`（base64）标记废弃，保留兼容解析
- `ClipService.saveClip`：移除 base64 图片处理；校验 imagePaths 中每个路径存在于 images 根目录内，将引用写入 content 与 imagePaths

### 2.6 旧数据迁移（migrate-images）

对每条剪藏：
1. 解析 content 中旧引用 `![...](/api/clip/image/{cat}/{file})`
2. 定位旧文件 `{organizedPath}/{cat}/assets/**/{file}`（支持子目录）
3. 复制到 `images/{yyMM}/{uuid}.{ext}`，重写 content 引用为相对路径
4. 回填 `imagePaths`
5. 旧文件保留（或由 cleanup 统一清理）

### 2.7 生命周期

- `deleteClip(id)`：删除该剪藏 imagePaths 指向且**未被其他剪藏引用**的文件
- 编辑器更新内容（updateClipFromEditor）：重扫 content 中图片引用，reconcile imagePaths（移除不再引用的、补全新引用的）
- `cleanup-orphans`：扫描 images/ 目录，删除不在任何剪藏 imagePaths 中的文件

### 2.8 整理链路修复

- organize 时把引用图片**复制**到 `{organizedPath}/{category}/assets/{uuid}.{ext}`（扁平化，不再保留 noteFileName 子目录）
- content 引用重写为 `./assets/{uuid}.{ext}`（修复原正则丢 category/子目录问题）
- 原图保留在 images/（不移动），避免破坏剪藏本身引用

### 2.9 doc-ai 分离

- 源文件存 `documents/{uuid}.{ext}`，`attachmentPath` 记录
- 下载端点 `GET /api/clip/file/{uuid}` 供前端"打开源文件"使用
- 不再走 imageUtils.storeImage / 图片 assets 目录

## 四、边界情况处理

| 情况 | 处理方式 |
|------|----------|
| 超大/非法文件 | 客户端压缩后仍超 10MB → 后端 400 明确提示；magic-byte 不符拒绝 |
| 上传中断 | XHR 重试；未提交剪藏的孤儿由 cleanup 兜底 |
| 剪藏未保存但图片已上传 | 孤儿图片，cleanup 清理 |
| 分类变更/整理 | 引用不依赖分类，不受影响；organize 复制后原图保留 |
| 端口/前端源变更 | 相对路径 + 渲染时重写 → 无需迁移 |
| 旧 base64 数据 | 兼容解析（扩展旧版提交 imageDataList 仍可存，不推荐） |
| 并发 | saveClip/deleteClip 已加锁；图片文件写临时名+rename 防半写 |
| 同名/重复上传 | uuid 命名天然去重 |
