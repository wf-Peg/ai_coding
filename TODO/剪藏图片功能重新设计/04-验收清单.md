# 剪藏图片功能重新设计 - 验收清单

## 一、功能验收

### 1.1 上传与插入
- [ ] 粘贴剪贴板图片 → 自动压缩 → 上传 → 在**光标位置**插入引用
- [ ] 点击上传按钮批量选择图片 → 逐个上传 → 缩略图预览
- [ ] 上传过程有进度反馈
- [ ] 单张上传失败可重试，不阻塞其他图片
- [ ] 删除预览图 → 内容中对应引用同时移除
- [ ] 超大图片（>10MB）压缩后仍超限 → 明确提示

### 1.2 展示
- [ ] 剪藏详情展开后，原文图片**正常显示**（不再 404）
- [ ] 剪藏列表显示缩略图（?thumb=1）
- [ ] 图片在 frontend 页面、扩展剪藏页、编辑器预览中均可显示

### 1.3 生命周期
- [ ] 删除剪藏 → 未被其他剪藏引用的图片文件被清理
- [ ] 编辑剪藏内容移除图片引用 → imagePaths 同步更新
- [ ] `cleanup-orphans` 清理未引用图片，返回清理数量

### 1.4 整理链路
- [ ] 执行"整理今日内容"后，生成的 Markdown 中图片引用为 `./assets/{uuid}.{ext}`
- [ ] Obsidian 打开整理文件，图片正常显示
- [ ] 原剪藏图片引用不受整理影响

### 1.5 doc-ai 附件
- [ ] 文档源文件存 `documents/` 独立目录
- [ ] `GET /api/clip/file/{uuid}` 可下载原文件

### 1.6 旧数据迁移
- [ ] `migrate-images` 执行后，存量剪藏 content 引用重写为相对路径
- [ ] 存量图片文件搬入 `images/`，imagePaths 回填
- [ ] 迁移后旧剪藏详情图片正常显示

## 二、安全与健壮性

- [ ] 上传校验 magic-byte（伪造扩展名被拒）
- [ ] 图片读取路径穿越防护（非法文件名/越权路径返回 404/400）
- [ ] 图片文件写入使用临时名+rename，无半写文件
- [ ] 并发上传/保存无数据损坏（依赖既有 synchronized 锁）

## 三、兼容性

- [ ] 旧 base64 imageDataList 提交仍可解析（不推荐使用）
- [ ] 端口/前端源变更后图片仍可显示（相对路径 + 渲染重写）
- [ ] frontend/clip.html 与 browser-extension/clip-main.js 行为一致
