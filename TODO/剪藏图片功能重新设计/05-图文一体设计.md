# 剪藏图片功能重新设计 - 图文一体设计（补充）

> 本文档是对 01-04 四件套的补充，聚焦"图文一体"（图片与文字同篇编排）的
> UX 设计、核心数据流、跨模块 media 层设计与新增决策点。

## 一、核心数据流（用户确认版）

**所有输入入口（前端剪藏表单 / 浏览器扩展弹窗 / Ace 编辑器）行为一致：**

```
Ctrl+V 粘贴（或选择/拖拽）
  → 拦截 paste 事件，从 clipboardData.items 提取 image 类型 → File/Blob 对象
  → canvas 客户端压缩（最长边 1600px / JPEG q0.82 / 透明保留 PNG / webp 转 jpg/png）
  → 立即 multipart 二进制流上传（FormData + XHR，upload.onprogress 进度）──▶ POST /api/media/upload
  → 后端 magic-byte 校验 → 存统一目录 {mediaRoot}/{yyMM}/{uuid}.{ext}
  → 返回相对路径 media/{yyMM}/{uuid}.{ext}
  → 光标处插入 ![alt](media/{yyMM}/{uuid}.{ext})        ← content 存相对路径
提交剪藏：content + imagePaths（相对路径清单）
渲染时：marked 渲染 content → rewriteImageSrc 将相对路径重写为
        {API origin}/api/media/{yyMM}/{file}（列表 ?thumb=1 缩略图）
```

**关键约定：**

| 项 | 约定 |
|----|------|
| 传输 | multipart/form-data 二进制流（FormData + XHR），**不是** base64 JSON |
| 存储 | `{mediaRoot}/{yyMM}/{uuid}.{ext}`，UUID 命名 + 按月分片，与分类/整理解耦 |
| 引用 | content 中存**相对路径** `media/{yyMM}/{uuid}.{ext}`，渲染时按 API origin 重写 |
| 生命周期 | `imagePaths` 为权威引用清单；删除/编辑/cleanup 均以此为准 |
| 跨模块 | 端点与存储为通用 `media` 层（决策 D-H），剪藏为首个消费者 |

## 二、图文一体 UX 设计

**目标定义**：剪藏正文中，图片与文字在同一篇 Markdown 中按用户意图排列
（图片即段落、可插在任意位置、可删除、可随文本编辑），三端行为一致，
导出 Obsidian 可见。

**规范表示（不 block 化）**：content 为 Markdown 字符串，图片引用
`![alt](media/{yyMM}/{uuid}.{ext})`；`imagePaths` 为权威引用清单（生命周期用）；
渲染时重写为绝对 URL。

### 场景 1：创作端（前端创建表单 + 扩展弹窗，行为一致）

- 内容 textarea 上方图片工具栏：`📷 上传图片`（多选 file input）+ 提示
  "可直接粘贴/拖拽图片"。
- **粘贴/选择/拖拽** → 客户端 canvas 压缩 → **立即** XHR multipart 上传
  （`upload.onprogress` 进度条，逐张）→ 成功后**在光标位置**插入
  `![图片](media/{yyMM}/{uuid}.{ext})`（用户可编辑 alt）。
- 内容区下方"已上传图片"缩略条：每张显示 缩略图(dataURL 本地预览) /
  上传状态（上传中百分比、成功、失败可重试）/ 删除按钮
  （删除时同时移除 content 中对应引用）。
- 单张失败不阻塞其它图片；压缩后仍 >10MB → 明确提示。
- **"预览"开关**：textarea ↔ markdown 渲染切换（渲染走共享 helper，
  图片立即可见）——用 textarea+预览实现图文"所见即所得"，不引入 WYSIWYG 依赖。
- 提交剪藏 JSON：`content` + `imagePaths`（相对路径清单）。

### 场景 2：查看端（剪藏列表/详情）

- `renderContent` 改为：escapeHtml → markdown 渲染（marked + 消毒 +
  `rewriteImageSrc`）。
- 详情展开后原文图片正常显示（大图，`max-width:100%`，点击 lightbox 放大，可选）。
- 列表项显示首图缩略图（`?thumb=1`，256px），无图不占位。

### 场景 3：编辑端（Ace 编辑器）

- 编辑器工具栏增加图片按钮 + 粘贴/拖拽监听 → 同一上传流 → 光标处插入引用。
- 右侧 markdown 预览面板（已有 `markdownBody`）复用 `rewriteImageSrc`，
  图片实时可见。
- 保存走 `updateClipFromEditor`：后端重扫 content 图片引用 reconcile
  `imagePaths`（移除不再引用的、补全新引用的）。

### 场景 4：生命周期与整理

- 删除剪藏：删除该剪藏 `imagePaths` 指向且**未被其他剪藏引用**的文件。
- `cleanup-orphans`：扫描 media/ 清理未被任何剪藏引用的文件
  （含"上传后未提交剪藏"的孤儿）。
- organize：复制引用图片到 `{organizedPath}/{category}/assets/{uuid}.{ext}`
  （扁平化），引用重写 `./assets/{uuid}.{ext}`，原图保留。

## 三、跨模块 media 层设计

**设计原则**：图片能力做成与业务解耦的通用层，剪藏先落地，其它模块按需接入。

1. **存储**：`{mediaRoot}/{yyMM}/{uuid}.{ext}`。模块内容中存相对路径
   `media/...`，各模块自维护引用清单（新增字段或扫描 content）。
2. **端点**：
   - `POST /api/media/upload`（multipart，magic-byte，10MB）
   - `GET /api/media/{yyMM}/{file}?thumb=1`（路径穿越防护）
   - `POST /api/media/cleanup-orphans`（按全库引用清单扫描）
   - `GET /api/media/file/{uuid}`（doc-ai 附件下载）
3. **前端共享 helper**：
   - `frontend/js/media-uploader.js`：压缩上传（带进度/重试）
   - `frontend/js/media-render.js`：`rewriteImageSrc`（markdown/HTML 重写）+ 白名单消毒
   - 图片 CSS：`max-width:100%`、缩略图尺寸
   - 扩展独立打包，复制一份到 `browser-extension/libs/` 并标注同步（决策 D-L）
4. **各模块接入清单**（M5 之后按需）：
   - **Knowledge**：`knowledge-editor.html` 图片插入（复用 media-uploader）；
     详情渲染 `rewriteImageSrc`；`Knowledge` 模型加 `imagePaths` 或扫描 content。
   - **Wiki**：`wiki.html` markdown-body 渲染加 rewriteImageSrc。
   - **Learning-plan / Todo**：文本为主，暂不接入；预留 helper。
   - **Obsidian 导出**：统一处理 `media/` 引用复制（与剪藏 organize 同逻辑）。

## 四、新增决策点（在 02-设计文档.md 决策点基础上补充）

| ID | 决策 | 结论 | 理由 |
|----|------|------|------|
| D-H | 端点/存储命名：clip-specific vs 通用 media | **通用 /api/media/*** | 成本≈0，直接服务跨模块复用；剪藏旧路径由 migrate 重写 |
| D-I | web 剪藏远程图片下载（扩展剪网页时顺带下载原图） | **本期不做** | 范围膨胀；作为后续增强项记录 |
| D-J | 列表缩略图（原 D-G） | **做** | 后端已生成 256px 缩略图 |
| D-K | XSS 消毒方案 | **自写白名单（DOMParser 过滤，不引依赖）** | 保持"不引入新依赖"约束 |
| D-L | 扩展 helper 维护方式 | **复制到 browser-extension/libs/ 并标注同步** | 扩展独立打包单元 |

### D-K 消毒白名单

- 允许标签：`p, div, strong, em, code, pre, blockquote, ul, ol, li, a, img, h1-h6, br, hr, table, thead, tbody, tr, th, td`
- 允许属性：`src, href, alt, title, class`（class 前缀白名单 `language-`/`markdown-content`）
- 实现：DOMParser 解析 → 遍历过滤非法节点/属性 → 序列化
