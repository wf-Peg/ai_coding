# 设计文档：剪藏知识知识图谱联调

## 架构设计

- 统一关系索引 RelationIndexService：管理剪藏→知识 derived_from 与知识→知识 linked_to，业务写入时同步记录。
- GraphService：关系同步 + 图谱组装，产出类型化节点（clip:xxx / knowledge:xxx）与双类型边。
- GraphController：GET /api/graph（支持 includeTypes 过滤）、POST /api/relations/sync（幂等重建）。

## 技术方案

- 节点 typedId 命名空间：clip:123 / knowledge:456，前端据此区分形状与颜色。
- 边类型：derived_from（虚线，剪藏→知识）、linked_to（实线，知识→知识）。
- 前端 D3 力导向图：方块=剪藏、圆=知识，搜索聚类、视图开关、同步刷新。

## 接口定义

- GET /api/graph?includeTypes=knowledge → { nodes:[{id,type,sourceId,title,category,tags,summary,linkedCount,sourceCount}], links:[{source,target,type}] }
- POST /api/relations/sync → 重建关系索引
- GET /api/knowledge/by-clip/{clipId} → 剪藏关联知识（冲突预警/角标复用）

## 关键决策

- 知识溯源元数据使用 SourceRef 附属知识条目，前端据此展示站点角标与内联原文预览。
- 编辑保存时反向校验来源剪藏是否已关联别条知识，给出确认提示形成"同一剪藏对应多条知识"的显式交互。
