# 需求分析：剪藏知识知识图谱联调

## 原始需求

从剪藏模块内容到知识模块内容，中间的来源剪藏、关联知识，有没有更好的设计，优化交互体验与知识整理的核心逻辑。目前的知识图谱只对知识与知识之间的关联，需完全打通这两块数据的流转关系。

## 分析结论

- 剪藏与知识之间存在隐式但未固化的流转关系：剪藏既可被"合成"为知识（1对N），也可被"引用"为知识的来源（N对1）。
- 原知识图谱仅消费知识列表，无法表达"来源剪藏"这一跨实体边，导致数据流断裂。
- 方案：引入统一关系索引（derived_from / linked_to），新增统一图谱数据源 /api/graph，前端多类型可视化，并增强来源/关联的交互体验。

## 会话摘要

- M1 后端接线 RelationIndexService + GET /api/graph + POST /api/relations/sync
- M2 多剪藏 AI 合成知识与 sourceRefs 来源溯源
- M3 知识图谱前端改消费 /api/graph，多类型节点+搜索聚类+视图开关
- M4 来源剪藏/关联知识 UX 优化（内联预览、站点名、列表角标、冲突预警）
- M5 Bug 修复（B1 ID 扫描、B2 合成桩）与回归
