## 二、核心设计决策

### 决策1：Wikilink 渲染方案

**方案**：在 marked.parse() 前将 `[[Title]]` 替换为 HTML `<a>` 标签
**理由**：marked.js 会将 `<a>` 标签原样保留不转义，是最轻量方案，无需修改 marked 库
**参考**：[knowledge-wikilink-rendering-plan.md]

### 决策2：评论存储方案

**方案**：JSON 文件存储，路径 `{knowledgeDir}/comments/{id}.json`
**理由**：与知识文件的存储方式一致，保持轻量级设计，无需引入数据库
**参考**：[knowledge-module-bugfix-plan.md]

### 决策3：Vault 路径统一解析

**方案**：WikiConfig 中 @PostConstruct resolveVaultPath() 统一解析
**核心逻辑**：绝对路径直接使用，相对路径以 AppConfig.storagePath 为基准解析
**参考**：[obsidian-vault-path-config-design.md]

### 决策4：多密码库文件结构

```
{storagePath}/vault/
├── vaults.json              ← 注册表（非敏感）
├── default/                 ← 默认密码库
│   ├── vault.enc            ← DES 加密数据
│   └── vault-meta.json      ← 元数据
├── work/                    ← 工作密码库
└── personal/                ← 个人密码库
```
**向后兼容**：自动检测旧版 vault.enc 迁移到 vault/default/
**参考**：[vault-multi-vault-and-key-improvements.md]

### 决策5：CSV 导入前端解析策略

**方案**：前端解析 CSV → JSON 数组 → POST /api/vault/import
**理由**：前端可预览/字段映射/错误提示，后端只负责去重加密，浏览器插件也可直接传 JSON
**参考**：[vault-import-integration-plan.md]

### 决策6：模型档位从 provider 改为模型名

**方案**：simpleTierModel（默认 deepseek-v4-flash）+ strongTierModel（默认 deepseek-v4-pro）
**理由**：用户心智模型是"简单=flash，复杂=pro"，provider 降级为底层细节
**参考**：[wiki-query-refactor-review-and-model-tier-redesign.md]

### 决策7：Wiki 查询本地优先策略

**方案**：WikiLocalRetriever（CJK 2-gram + 英文空格分词）→ 本地优先 → LLM 兜底
**理由**：零依赖纯算法，对 wiki index 条目级匹配足够，节省 API 调用成本
**参考**：[wiki-query-refactor-review-and-model-tier-redesign.md]

### 决策8：Wiki 省 Token 策略

- 批量攒批 ingest（默认5条）
- index.md 优先查询
- 模型路由（抽取用 DeepSeek、综合用 Qwen）
- 增量更新
- 按需 lint
**参考**：[wiki-module-current-state.md]

### 决策9：日志系统三层架构

| 层 | 组件 | 日志文件 | 滚动策略 |
|---|------|---------|---------|
| 后端 | logback-spring.xml | application.log | 按天，保留30天 |
| Electron | electron/logger.js | electron.{date}.log | 按天，保留30天 |
| 前端 | frontend/js/logger.js | → IPC → Electron 主进程 | 同上 |

**参考**：[vault-fix-and-global-logging.md]

## 三、数据流

### 3.1 CSV 导入流程
```
用户导出 CSV → 选择文件 → 前端解析 → GET /api/vault/search 获取现有条目
→ 前端去重标记/预览 → 用户勾选 → POST /api/vault/import
→ 后端 ensureUnlocked() → 去重合并 → saveVault() (DES加密落盘)
→ 返回结果 → 前端刷新列表
```

### 3.2 插件右键导入流程
```
用户浏览网站 → 右键 → 保存当前网站密码
→ 弹窗自动填充 title/url → GET /api/vault/status 检查解锁
→ 用户填写用户名/密码 → POST /api/vault/entry
→ 成功提示 → 1.5s 自动关闭
```

### 3.3 Wiki 批量入库流程
```
Web Clipper 写入 sources/*.md → VaultWatchService 检测新文件
→ BatchIngestService 批量读取 → AI 抽取实体/概念/综述
→ 生成页面到 entities/concepts/synthesis 目录
→ WikiIndexService 更新 index.md
```
