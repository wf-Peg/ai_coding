# 工作台规则与筛选 — 设计文档

## 一、规则引擎设计

### 1.1 两级表达式模型

```
RuleExpression(workspaceId, relation, groups)
  └─ relation: "AND" | "OR" (组间关系)
  └─ groups: List<RuleGroup>
       └─ RuleGroup(id, relation, ruleIds)
            └─ relation: "AND" | "OR" (组内关系)
            └─ ruleIds: List<String> (引用 WorkspaceRule.id)
```

**语义示例**：`(tag=product-dev OR category⊇product-dev) AND type∈(clip,todo)`
- 根 relation = AND
- 组1：relation = OR，ruleIds = [pd-rule-tag, pd-rule-category]
- 组2：relation = AND，ruleIds = [pd-rule-type]

### 1.2 求值逻辑

```
对每个 ContentRef:
  每组内启用规则按组 relation 折叠得到组结果
  各非空组结果按根 relation 折叠得到最终结果
  整体为 true 才加入 ruleIds
```

### 1.3 存储设计

- **规则定义**：`workspace-rules.json`（不变）
- **分组结构**：`workspace-rule-expressions.json`（新文件）
- **原子写**：临时文件 + `Files.move(tmp, path, REPLACE_EXISTING)`

### 1.4 惰性迁移

无表达式但有旧平铺规则时，自动迁移为单组 OR 表达式：
```
根 relation = OR
组1 relation = 旧 matchAll ? AND : OR
组1 ruleIds = 所有旧规则 ID
```

## 二、API 设计

### 2.1 表达式端点

| 方法 | 端点 | 说明 |
|------|------|------|
| GET | `/{workspaceId}/rule-expression` | 获取表达式 |
| PUT | `/{workspaceId}/rule-expression` | 更新表达式 |
| POST | `/{workspaceId}/rule-expression/groups` | 添加分组 |
| DELETE | `/{workspaceId}/rule-expression/groups/{groupId}` | 删除分组 |

### 2.2 设置端点

| 方法 | 端点 | 说明 |
|------|------|------|
| PUT | `/{workspaceId}/settings` | 更新 matchAll 等设置 |
| PUT | `/{workspaceId}/set-default` | 设为默认工作台 |
| PUT | `/workspace/reorder` | 更新工作台排序 |

### 2.3 筛选端点

| 方法 | 端点 | 说明 |
|------|------|------|
| GET | `/overview?workspaceId=` | 作用域概览 |
| GET | `/clip/list?workspaceId=` | 剪藏筛选 |
| GET | `/todo/list?workspaceId=` | 待办筛选 |
| GET | `/knowledge/list?workspaceId=` | 知识筛选 |

### 2.4 建议端点

| 方法 | 端点 | 说明 |
|------|------|------|
| GET | `/{workspaceId}/suggestions` | 获取建议（含规则建议） |
| GET | `/suggestions/{id}/detail` | 建议详情 |

```java
                                  LocalDateTime createdAt, LocalDateTime expiresAt,
                                  String status,
                                  String type,           // "content-suggestion" | "rule-suggestion"
                                  String title,          // 内容标题 / 建议描述
                                  String suggestedField, // 规则建议专用
                                  String suggestedValue) {} // 规则建议专用
```

## 四、规则建议生成逻辑

```
1. 聚合排除内容的 tag 频次
2. 过滤已有规则（已存在的 tag 规则不重复建议）
3. 频次 >= 2 的 tag 生成规则建议
4. 接受时自动创建规则：field=tag, operator=contains, value={tag}
5. 拒绝后不再出现该建议
```

## 五、前端跨页面通信

```
index.html (localStorage active_workspace_id)
  ├── postMessage → workspace.html (工作台页面)
  ├── postMessage → clip.html (剪藏页面)
  ├── postMessage → todo.html (待办页面)
  ├── postMessage → knowledge.html (知识页面)
  └── postMessage → learning-plan.html (学习计划页面)
  
storage 事件监听：同一页面内 iframe 间同步
```

## 六、标题兜底策略

```
优先级：
1. title (非空) → 直接使用
2. content (非空) → 去除HTML标签，截断前60字符 + "..."
3. 兜底 → "{实体类型}#{ID}" (如 "剪藏 #1003")
```
