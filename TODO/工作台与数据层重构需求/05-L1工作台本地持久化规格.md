# L1 工作台本地持久化规格

## Why
L0 已提供跨内容只读工作台，但尚无独立的工作台业务数据存储。L1 先建立不破坏旧项目索引的本地 JSON 持久化基础，为后续 CRUD、成员操作和工作台页面接入提供稳定模型。

## What Changes
- 新增 `Workspace` 模型，持久化到索引目录 `workspace.json`。
- 新增 `WorkspaceMembership` 模型，持久化到索引目录 `workspace-memberships.json`。
- 新增 `WorkspaceIndexService`，提供工作台和成员关系的保存、读取、幂等加入、移除及按工作台查询。
- 工作台类型支持 `general`、`project`、`learning`，本阶段只校验并保存类型，不实现学习业务。
- 删除工作台时仅删除工作台记录及其成员关系，不触碰 ContentRef、原始业务 JSON 或旧的 `projects.json`、`project-memberships.json`。
- 本阶段不新增 HTTP CRUD 接口和前端写入操作，后续任务在此持久化服务之上实现。

## Impact
- Affected specs: 工作台基础模型、内容引用、项目兼容。
- Affected code: `backend/src/main/java/com/example/clip/index/` 及对应单元测试。

## ADDED Requirements
### Requirement: 工作台模型持久化
系统 SHALL 将工作台列表写入索引目录下的 `workspace.json`，并保留 id、名称、类型、描述、颜色、状态和创建/更新时间。

#### Scenario: 保存并读取工作台
- **WHEN** 服务保存一个合法工作台后重新读取
- **THEN** 返回内容与保存值一致，且文件位于配置索引目录

### Requirement: 成员关系持久化
系统 SHALL 将工作台成员关系写入 `workspace-memberships.json`，成员只保存 workspaceId、contentId、source、reason、confidence 和创建/更新时间等引用关系字段，不保存正文。

#### Scenario: 成员幂等加入
- **WHEN** 同一工作台重复加入同一 contentId
- **THEN** 文件中只保留一条成员关系

### Requirement: 工作台删除隔离
系统 SHALL 删除工作台时同步删除该工作台的成员关系，但不得删除或修改内容索引、原始业务 JSON、旧 Project 索引或内容正文。

#### Scenario: 删除工作台
- **WHEN** 用户删除一个已有成员的工作台
- **THEN** 工作台和对应成员关系消失，其他工作台成员关系保持不变

### Requirement: 合法性与容错
系统 SHALL 拒绝空 id、空名称、非法类型、非法状态和空 contentId；缺失 JSON 文件视为空集合；损坏 JSON 必须以明确异常报告，不得静默覆盖。

#### Scenario: 非法工作台被拒绝
- **WHEN** 保存名称为空或类型不在允许集合中的工作台
- **THEN** 服务抛出明确的参数异常且不写入文件

### Requirement: 旧项目索引兼容
系统 SHALL 保持现有 `ProjectIndexService` 及其两个旧文件的读写行为不变，新增工作台持久化不得迁移或改写旧项目数据。

#### Scenario: 旧项目数据仍可读
- **WHEN** 索引目录同时存在旧项目文件和工作台文件
- **THEN** 两套数据可以分别读取，互不覆盖
