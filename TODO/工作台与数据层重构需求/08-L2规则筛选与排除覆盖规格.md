# L2 工作台规则筛选与排除覆盖规格

## Why
L1 已建立工作台、成员关系和本地 JSON 持久化基础，但工作台还不能根据内容元数据自动聚合内容，也无法记住用户明确排除的内容。L2 增加可解释的规则筛选和工作台级排除覆盖，为后续工作台页面和建议确认流提供纯后端基础。

## What Changes
- 新增 `WorkspaceRule` 模型，持久化到 `workspace-rules.json`。
- 新增 `WorkspaceExclusion` 模型，持久化到 `workspace-exclusions.json`。
- 支持规划中固定字段：`type`、`category`、`tag`、`sourcePath`、`workflowStatus`、`updatedAt`。
- 支持规划中固定操作符：`equals`、`contains`、`in`、`before`、`after`。
- 实现规则校验、启用/禁用、规则并集、结果去重和排除优先。
- 规则命中只产生展示结果，不写入 `WorkspaceMembership`。
- 本轮只实现后端本地 JSON 和纯逻辑，不新增 HTTP 接口和前端页面。
- 不修改原始业务 JSON、ContentRef 正文、旧 Project 索引和现有成员关系。

## Impact
- Affected specs: 工作台规则、工作台排除、内容索引、工作台成员关系。
- Affected code: `backend/src/main/java/com/example/clip/index/` 及对应单元测试。

## ADDED Requirements
### Requirement: 规则模型持久化
系统 SHALL 将每条规则保存到 `workspace-rules.json`，规则包含 id、workspaceId、field、operator、value、enabled、createdAt、updatedAt。

#### Scenario: 保存规则
- **WHEN** 保存一条合法且启用的标签包含规则
- **THEN** 规则可以被读取，并只影响对应工作台的候选计算

### Requirement: 固定规则契约
系统 SHALL 只接受规划规定的字段和操作符；非法字段、操作符、空 workspaceId、空 value 或非法时间值必须拒绝。

#### Scenario: 非法规则被拒绝
- **WHEN** 规则字段或操作符不在允许集合中
- **THEN** 系统抛出明确参数异常且不写入文件

### Requirement: 规则并集与去重
系统 SHALL 将同一工作台启用规则的命中结果按并集计算，并按 `ContentRef.id` 去重；禁用规则不得参与计算。

#### Scenario: 多规则命中
- **WHEN** 两条启用规则分别命中同一内容或不同内容
- **THEN** 返回去重后的内容引用集合，规则命中不会创建永久成员关系

### Requirement: 排除优先
系统 SHALL 将工作台级排除记录保存到 `workspace-exclusions.json`，并从规则命中、手动成员和关系带入的合并结果中移除被排除内容。

#### Scenario: 排除规则命中内容
- **WHEN** 内容同时被规则命中且存在工作台排除记录
- **THEN** 内容不出现在工作台解析结果中

### Requirement: 来源统计
系统 SHALL 返回规则命中、手动加入、关系带入和排除的数量统计，统计按去重后的内容引用计算，不改变任何持久化关系。

#### Scenario: 读取工作台统计
- **WHEN** 工作台存在规则候选、手动成员、关系带入和排除记录
- **THEN** 返回四类来源数量及最终可见内容数量

### Requirement: 数据隔离与容错
系统 SHALL 在删除工作台时同步删除其规则与排除记录；缺失规则/排除文件按空集合处理，损坏 JSON 明确失败；不得修改其他工作台和旧项目数据。

#### Scenario: 删除工作台
- **WHEN** 删除工作台
- **THEN** 其规则、排除记录和成员关系被删除，其他工作台数据与原始内容保持不变
