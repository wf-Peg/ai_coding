# 内容分发初步设计方案（借鉴 Foclip/ClipFlow）

> **版本**：v0.1 初步设计（待后续实现分析细化）
> **日期**：2026-08-15
> **依据**：`01-调研报告.md`（Trae 论坛热帖调研）、`02-Foclip深度分析.md`（复赛作品拆解）、ClipFlow 开源代码（derek2000139/ClipFlow v2.1.0，已下载拆解）、Foclip 复赛架构图（用户提供翻译，与帖文 6.1 文字及开源代码交叉验证）
> **范围**：本方案聚焦「分发」与「导出」能力设计；拾取/加工沿用 Clip 现有剪藏能力（浏览器扩展 + 链接/文档解析），不重复设计

---

## 1. 背景与目标

Foclip（Trae 论坛复赛作品）验证了一条完整链路：**拾取 → 加工 → 分发 → 沉淀**。其中「分发层」含 8+ AI 平台一键投递（数据驱动规则自动填入）、本地导出（md/txt/html/docx/png）、飞书 Webhook；「沉淀层」为 Vault 剪藏历史库（IndexedDB + 500 条 LRU + 搜索/标签/星标）。

Clip 现状：已具备**拾取**（浏览器扩展右键/快捷键/弹出窗剪藏、链接/文档解析）、**加工**（后端多模型 AI 分析/总结/标签/智能整理/发散性总结）、**沉淀**（本地 JSON+MD 存储、剪藏列表、专题、知识库、待办时间线、日报/周报）。**分发与导出是本项目空白**，也是本期设计目标：

- **内部投递**：把剪藏内容一键投递给 Clip 自身已配置的多 LLM（DashScope/DeepSeek/路由），获得分析/总结/发散结果并回存 —— Clip 特有优势，零新依赖
- **外部投递**：一键复制 + 打开外部 AI 平台（DeepSeek/豆包/ChatGPT/Kimi/Claude/Gemini/通义/文心等），满足"喂给外部工具"场景
- **多格式导出**：md / txt / html / docx / png 卡片
- **Prompt 模板包裹**：`{content}/{title}/{url}` 变量插值，按平台/场景切换

## 2. 现状与差距分析

| 能力 | Foclip/ClipFlow | Clip 现状 | 复用/新建 |
|---|---|---|---|
| 拾取（四级识别/截图） | 四级识别+内容密度算法、区域/长截图 | 选中文本+整页提取、右键菜单、快捷键 | 可复用；四级识别为 P2 增强 |
| 加工（多格式解析） | 六解析器（文本/代码/表格/图片/布局/格式转换）→ MD/结构树/富文本/设计快照 | 后端 AI 分析（processClipContent 等） | 后端已覆盖核心；多格式前端化按需 |
| **分发（8+ 平台投递）** | 剪贴板+storage pending+tabs.create+自动填入；数据驱动规则包 | **无** | **新建（本期核心）** |
| **Prompt 模板包裹** | `{content}/{title}/{url}` 模板 | 有 PromptConfigService（各场景 prompt 可配） | 扩展模板变量与"分发模板"管理 |
| **导出 md/txt/html/docx/png** | Blob 下载 + 导出页整理 | pdf.html 工具页、html2canvas 已有；**无通用导出** | **新建（本期核心）** |
| 飞书 Webhook | 开源版已有 sendToFeishu | 邮件日报/周报已有；无 webhook 分发 | P1 新建 |
| 沉淀 Vault | IndexedDB + 500 条 LRU + 星标 | 本地 JSON+MD 剪藏库 | 桌面端复用后端库（推荐）；扩展端 Vault 为 P2 |
| 架构（消息总线/注册表） | 消息总线 + 平台/格式注册表 | 前后端 REST 分离 | 采用"注册表"思路做配置化平台/格式 |

**关键差异结论**：Foclip 走"浏览器内自动填入"路线（复赛才扩展到 8+ 平台，且该部分未开源）；**Clip 因有本地后端多模型，可走"后端代发"路线**，首期实现成本显著更低，且不依赖外部平台 DOM 适配。

## 3. 总体架构方案（双通道分发）

```
                    ┌──────────────────────────────────────────────┐
                    │                Clip 分发层                     │
                    └──────────────────────────────────────────────┘
  剪藏内容 ──► 分发引擎（平台/格式注册表 + Prompt 模板包裹）
                    │
        ┌───────────┴────────────┐
        │                        │
   通道A：内部投递            通道B：外部投递
   （推荐优先）               （复制+跳转）
        │                        │
  ┌─────▼─────┐          ┌───────▼───────┐
  │ 后端 AiService │      │ 剪贴板写入 + 打开平台 │
  │ DashScope/     │      │ 桌面: shell.openExternal│
  │ DeepSeek/路由  │      │ 扩展: tabs.create(+P2自动填入)│
  └─────┬─────┘          └───────────────┘
        │
  分析/总结/发散结果 ──► 回存剪藏（分析字段）
```

**核心设计决策**：
1. **通道A（内部投递）为默认**：复用后端 `AiService`（analyzeContent / generateSummary / generateDivergentSummary / processClipContent），前端与扩展统一通过 `POST /api/clip/...` 触发；结果写入剪藏记录，形成"剪藏 → 投递 → 结果回存"闭环。
2. **通道B（外部投递）为补充**：桌面端 `clipboard.writeText` + `shell.openExternal(平台URL)`；扩展端沿用 ClipFlow 已验证模式（剪贴板 + `pendingAIContent` + `tabs.create`），**平台页自动填入列为 P2**（依赖平台 DOM，维护成本高）。
3. **平台/格式注册表（数据驱动）**：仿 `AI_PLATFORM_CONFIG`，但改为**后端配置化**（JSON/数据库），前端渲染按钮、后端执行，避免前端硬编码与发版耦合；支持"自定义平台"（自定义 URL + 模板）。
4. **Prompt 模板**：在现有 PromptConfigService 上增加"分发模板"类型，变量 `{content}/{title}/{url}` 插值，按平台/场景（提问/总结/发散）选择。

## 4. 功能设计（分模块）

### 4.1 分发引擎（后端，核心）
- **数据模型**：`DispatchTarget`（平台名、类型[internal/external]、URL 模板、Prompt 模板、启用状态、图标）＋ 注册表接口
- **接口设计**：
  - `GET /api/dispatch/targets` —— 获取可用投递目标（内部模型 + 外部平台）
  - `POST /api/dispatch/{targetId}` —— 投递 {contentId, targetId, promptTemplateId, extraParams}
    - 内部目标：调 `AiService` 对应方法 → 返回结果 → 可选回存剪藏
    - 外部目标：返回"复制文本 + 平台 URL"，由前端执行跳转
  - `GET/POST /api/dispatch/prompt-templates` —— 分发模板 CRUD（复用 Prompt 配置体系）
- **投递记录**：`DispatchLog`（时间/目标/内容/结果摘要），支持"重新投递"

### 4.2 前端入口（桌面端 + 扩展端统一交互）
- 剪藏条目操作菜单新增「投递到…」「导出为…」
- 「投递到…」二级菜单：内部模型（分析/总结/发散，可选用模板）｜外部平台（复制+打开）
- 结果展示：模态/内联面板，打字机效果复用现有发散性总结交互；一键回存到剪藏"分析结果"字段
- 全局快捷键（P1）：剪藏页内 Alt+D 投递上次内容
- 托盘菜单（P1）：最近剪藏 → 投递/导出

### 4.3 导出模块
| 格式 | 方案 | 难度 | 说明 |
|---|---|---|---|
| md | Blob 下载（前端）/ fs 直写（Electron） | ★ | 内容即 Markdown 原文 |
| txt | 同上（strip Markdown 语法） | ★ | |
| html | 同上（marked 渲染后包装模板） | ★ | 含图片引用 |
| docx | 方案A：前端 `docx` npm 库；方案B：后端 Apache POI 生成 | ★★ | 待后续分析选型（中文/图片/表格保真为关键点） |
| png 卡片 | html2canvas（前端已有） | ★ | 知识卡片图，参照 Foclip"莫兰迪卡片" |

### 4.4 Prompt 模板设计
- 内置模板：通用提问、总结提炼、发散性分析、日报素材、周报素材（对齐 Clip 既有场景）
- 变量：`{content}` `{title}` `{url}` `{category}` `{tags}`；插值在后端执行，防注入与超长截断
- 平台/模板绑定：注册表中每个目标可指定默认模板，用户可覆盖

### 4.5 沉淀与记录（P1/P2）
- **P1**：投递结果自动回存剪藏（`clip` 增加 `dispatchResults` 字段，含目标/时间/结果摘要），支持"从结果再次投递"
- **P2**：扩展端 Vault（IndexedDB + 500 条 LRU + 搜索/标签/星标）—— 仅当扩展需要离线沉淀时实施；桌面端始终以后端剪藏库为准，避免双写

## 6. 实施路径

### P0 —— 首期（建议 1 周内）
- 后端：分发目标注册表 + `GET /api/dispatch/targets` + `POST /api/dispatch/{id}`（内部模型通道）
- 前端：剪藏条目「投递到…」菜单（内部模型 + 模板选择）+ 结果面板与回存
- 导出：md / txt / html（剪藏条目与专题编辑页）
- 验收：任一条剪藏可一键投递到 DashScope/DeepSeek 并回存结果；一键导出三种格式内容完整

### P1 —— 二期
- 通道B 外部投递（复制 + `shell.openExternal` / 扩展 `tabs.create`）
- docx 导出（先做选型验证）＋ png 卡片导出
- 飞书 Webhook 分发；投递记录与"重新投递"；全局快捷键 + 托盘入口；剪贴板监听（复制即入收件箱）

### P2 —— 三期（按需）
- 扩展端平台页自动填入（平台规则包 + 自动填入引擎）
- 扩展端 Vault（IndexedDB + LRU + 星标）
- Agent 能力层（REST/CLI 封装"抓取→投递"，供 AI 智能体调用，对齐 TODO/智能入库方向）

## 7. 验收标准

| 级别 | 验收点 |
|---|---|
| P0 | ① 剪藏任一条目可投递到任一已配置内部模型，返回分析/总结/发散结果并在界面展示；② 结果可一键回存剪藏；③ 可导出 .md/.txt/.html 且内容与剪藏正文一致；④ 分发目标与模板可在设置页维护 |
| P1 | ⑤ 外部平台投递 = 内容复制成功 + 平台页正确打开（桌面/扩展各验证 2 个平台）；⑥ .docx 导出中文/图片/表格保真；⑦ 飞书 webhook 测试发送成功；⑧ 快捷键/托盘可触发投递 |
| P2 | ⑨ 扩展端至少 3 个平台自动填入成功（含 SPA 场景）；⑩ Vault 500 条 LRU 与搜索/星标可用；⑪ Agent 可经接口端到端"抓取→投递" |

## 8. 待后续分析事项（下一轮"实现分析"输入）

1. **docx 库选型**：前端 `docx` vs 后端 Apache POI —— 中文、图片、表格保真实测；与现有打包链路的依赖影响
2. **平台规则包数据源**：内置 JSON vs 后端配置 vs 远程更新（Foclip 规划为远程可更新规则包）；扩展端自动填入的**平台兼容性矩阵**（textarea/contenteditable/ProseMirror 等实测清单）
3. **投递结果回存的存储形态**：剪藏 JSON 字段扩展 vs 独立 DispatchLog 关联；对现有检索/周报的影响
4. **Vault 与后端剪藏库的关系**：扩展端离线 Vault 与后端库的双写一致性方案（或明确不做扩展端 Vault）
5. **剪贴板监听策略**：Electron 轮询间隔 vs 系统事件；与现有剪藏入口（复制→粘贴→剪藏）的交互冲突
6. **模板变量边界**：超长内容截断策略、变量转义、多语言模板
7. **权限与隐私**：外部投递内容默认只复制不自动发送；敏感内容（密码等）投递前提示
