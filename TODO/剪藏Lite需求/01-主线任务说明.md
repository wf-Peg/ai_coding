# CutShelter Lite 剪藏轻量版开发计划

> 状态：设计审阅完成，建议按 Lite-MVP v2 执行
> 更新日期：2026-08-03（星期一）

## 目标

在现有 CutShelter 剪藏项目中新建 `lite/` 子目录，开发"剪藏 Lite"功能。Lite 版定位为离线、轻量、快速、低占用的本地文本编辑器与便签收集工具，可一键唤起完整版。Lite 版不依赖后端 Java 进程、不依赖 AI 服务、不依赖数据库，实现秒开秒用。

## 设计约束（用户确认）

- **完全离线**：无后端进程、无网络请求、无 AI 功能。
- **轻量快速低占用**：运行时仅保留 `iconv-lite` + `chardet`；Electron 与 electron-builder 只放在 `devDependencies`。
- **独立构建**：完全独立的 `lite/package.json`，自带 electron-builder 配置，不被完整版的 sharp/node-notifier/js-yaml 等依赖污染。
- **代码复制非共享依赖**：可复用部分采用复制/剪切代码方式实现，不建立共享依赖，以减少开发 token 消耗。
- **保留编辑器模块**：完整复用现有编辑器的 ACE 编辑器、多标签、文件树、编码处理、格式化、文本转换、diff、Markdown 预览、编辑历史、自动保存、主题、拖拽、滚轮缩放、快捷键体系。
- **支持快捷键操作**：沿用现有编辑器快捷键，新增全局快捷键。
- **从 Lite 版打开完整版**：自动探测完整版路径（开发模式 + 打包模式），失败时手动兜底选择 exe 路径并持久化保存。

## 本次审阅结论（Lite-MVP v2）

原方案可以落地，但存在三类会放大体积和开发 token 的冗余，按以下规则收敛：

1. **不做第二套笔记系统**：不新增 `note-service.js`、笔记列表面板和笔记专用 IPC。复用现有文件树、`Ctrl+N`、另存为和自动保存；Lite 启动时将 `{userData}/notes/` 作为默认工作区，普通 `.txt/.md` 文件即为笔记。
2. **复制后定点删减**：`editor.js` 仍从完整版复制，但只按已确认的 AI/Pet/剪藏区块做一次性删减，不重构编辑器核心；通过源文件快照校验漂移。
3. **只复制实际引用资源**：保留 ACE、`marked`、`diff`、`sql-formatter` 及其被页面实际加载的文件；不复制 `axios`、`html2canvas`、`mermaid`、mascot 和 vault 主题。
4. **主进程保持单文件**：配置仅保存一个 `fullVersionPath`，直接由 `main.js` 读写；不拆 `config-service.js`。`preload.js` 只暴露文件能力、启动完整版和窗口控制，IPC 通道采用固定白名单。
5. **不承诺固定包大小**：Electron 运行时占绝大多数体积，`~80MB` 只能作为单平台估算；以实际目标平台打包产物为准，业务资源目标约 1.5MB。

**推荐实现边界**：Lite 只解决“秒开编辑、快速记笔记、需要时启动完整版”三件事；不新增搜索、同步、AI、数据库、云端和第二套内容模型。

### 编辑器模块耦合点分析

以下功能与完整版后端/AI 存在耦合，需在 Lite 版中剥离：

| 耦合功能 | 调用方式 | 剥离策略 |
|---|---|---|
| 存入剪藏 | `fetch(API_BASE_URL/add)` | 移除按钮，改为本地笔记另存 |
| 加载剪藏 | `fetch(API_BASE_URL/{id})` | 移除 |
| AI 对话面板 | `editor-ai-chat-core.js` + SSE | 整块移除，不复制该文件 |
| Pet 看板娘 | mascot 图片 + BroadcastChannel | 移除，不复制 mascot 资源 |
| 右键 AI 菜单 | aiSearch/smartIngest/aiImportPassword | 移除相关菜单项和处理逻辑 |
| 分类下拉 | `fetch(API_BASE_URL/categories)` | 移除 |
| 启动遮罩 | 等待后端就绪 | 移除，秒开 |

- 格式化（JSON/XML/SQL）+ 文本转换（Base64/URL/Hex/MD5 等）
- 对比 diff + Markdown 预览 + 编辑历史 + 最近打开 + 收藏

## 架构选型

### 选择：Electron 精简壳

| 维度 | 选择 | 理由 |
|---|---|---|
| 运行时 | Electron（仅渲染层，无后端进程）| 复用现有代码成本最低；提供文件系统直访 + 全局快捷键 |
| 构建独立性 | 独立 `lite/package.json` | 不被完整版的 sharp/node-notifier 等依赖污染；体积更小 |
| 依赖 | 仅 `electron` + `iconv-lite` + `chardet` | 移除 sharp/serve-static/finalhandler/node-notifier/js-yaml |
| 前端 | 单页 `editor.html`（非 iframe）| 去掉 index.html 壳，直接加载编辑器，启动更快 |

### 与替代方案的权衡

| 方案 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| Electron 精简壳（选定）| 复用最大化；能力完整（文件系统+全局快捷键）| 运行时体积 ~70MB | **最优解** |
| Tauri | 更轻（~10MB）| 需 Rust 工具链；迁移成本高 | 不选 |
| 纯 Web（PWA）| 体积最小 | 无文件系统直访；无全局快捷键 | 不选 |

## "启动完整版"设计

### 探测优先级

```
1. 开发模式探测
   - lite/ 的上级目录存在 electron/main.js + package.json
   - 启动命令：使用 `process.execPath` 启动项目根目录，避免依赖 shell PATH
   - 判定依据：!app.isPackaged 且上级 package.json 的 name === "clip-demo"

2. 打包模式探测（按平台）
   - Windows:
     %LocalAppData%/CutShelter/CutShelter.exe
     Program Files/CutShelter/CutShelter.exe
   - macOS: /Applications/CutShelter.app
   - Linux: /opt/CutShelter/CutShelter 或 ~/CutShelter

3. 手动兜底
   - 前两者均失败 → 弹原生文件对话框选 exe/app
   - 保存路径到 lite/config.json 的 fullVersionPath 字段
   - 之后一键启动，不再询问
```

### 启动实现

```js
// main.js 核心逻辑（伪代码）
async function launchFullVersion() {
  let target = config.fullVersionPath;        // 用户手动指定过
  if (!target) target = detectDevModePath();  // 开发模式
  if (!target) target = detectPackagedPath();  // 打包标准路径
  if (!target) {
    const result = await dialog.showOpenDialog({...});
    if (result.canceled) return { ok: false };
    target = result.filePaths[0];
    config.fullVersionPath = target;
    saveConfig(config);
  }
  spawn(target.command, target.args, { detached: true, stdio: 'ignore' }).unref();
  return { ok: true, path: target };
}
```

### 关键决策

| 问题 | 决策 | 理由 |
|---|---|---|
| 是否检测完整版已运行？ | **不检测** | 跨平台进程检测复杂；完整版支持多实例时会自己处理 |
| 启动失败如何反馈？ | toast 提示 + 转手动选择 | 探测路径可能失效（如完整版被卸载/移动） |
| 路径持久化策略 | 仅手动选择的才保存 | 自动探测结果不缓存，避免完整版更新后路径变化失效 |
| 开发模式如何判定？ | 上级目录 package.json name=clip-demo | 可靠且无副作用 |

## 风险点

1. **editor.js 精简复杂度**：约 150KB 文件，AI/Pet/clip 相关逻辑散布多处；只做定点删除并以脚本检查残留引用，不做大规模重构。
2. **ACE worker 路径**：ACE 编辑器的 worker 路径配置需与新的 `libs/ace/` 目录对齐（复制时保持相对结构即可）。
3. **完整版探测失效**：打包后可能因安装路径变化失效——已用手动兜底覆盖。
4. **独立依赖兼容性**：`iconv-lite` 和 `chardet` 在 lite 独立 package.json 下固定版本，避免编码行为差异；Electron 不计入运行时依赖。

## 明确不做

- 不在 Lite 版中引入后端进程或 Java 依赖。
- 不在 Lite 版中引入 AI 功能（DashScope/DeepSeek）。
- 不在 Lite 版中引入数据库。
- 不在 Lite 版中引入云同步或网络请求。
- 不修改完整版 `electron/`、`frontend/`、`backend/` 中的任何现有代码。
- 不建立 Lite 与完整版之间的运行时共享依赖或代码引用（纯复制）；允许在开发期保留源文件快照校验脚本。
