# 设计文档：工具模块全局主题与后端就绪刷新

## 架构设计

主题链路：主框架 index.html（data-theme 唯一来源）→ postMessage(themeChange) → 工具模块 iframe（tools-core.js 应用自身 + forwardThemeToTool 转发）→ 工具运行 iframe（服务端注入的主题桥监听并覆盖 CSS 变量）。

后端就绪链路：Electron 主进程 backend-ready → 主框架 handleBackendReady → refreshAllSubPages 广播 {action:'refresh'}（含 iframe 加载竞态兜底补发）；手动启动路径经 setGlobalBackendState 广播 {action:'backendState', state:'ready'} → 工具模块统一处理，1 秒去重后刷新列表 + 重载运行中工具。

## 技术方案

### 2.1 滚动条主题化

- `frontend/styles/tools.css`：WebKit `::-webkit-scrollbar`（8px、圆角、background-clip 内缩）+ Firefox `* { scrollbar-width: thin; scrollbar-color: var(--app-border-strong) transparent; }`；深色主题细化 thumb 配色与 `.th-modal-mask` 遮罩。

### 2.2 嵌套 iframe 主题传递

- `frontend/js/tools-core.js`：`resolveTheme()` 与主框架/设置页一致解析 notion/regular/dark/system；`applyTheme(theme)` 支持接收消息携带的主题；`forwardThemeToTool()` 在工具 iframe 已加载时转发 `{action:'themeChange', theme}`；`openTool` 在 onload 补发保证打开即同步。

### 2.3 服务端主题桥注入

- `ToolRegistryService.java` 新增 `THEME_BRIDGE_SCRIPT`（文本块）与 `THEME_BRIDGE_MARKER = "__cut_shelter_theme"`；`getToolPage` 返回前调用 `injectThemeBridge()`：优先插 `</body>` 前，回退 `</html>` 前，再回退追加末尾；页面已含标记则不重复注入。
- 桥脚本逻辑：监听 `{action:'themeChange'}` → 计算 notion/regular/dark → 写 `html[data-theme=...]` 属性 → 以 id=`__cut_shelter_theme` 的 style 元素注入对应调色板（--bg/--surface/--border/--text/--primary 等工具页公共变量）+ 滚动条 CSS；同源时可读父框架 data-theme 兜底初始化。`html[data-theme=...]` 特异性高于工具页 `:root` 媒体查询，系统深色偏好与全局主题冲突时以全局主题为准。

### 2.4 后端就绪广播链路

- tools-core.js 统一消息处理：`{action:'refresh'}` 或 `{action:'backendState', state:'ready'}` → `onBackendReadyRefresh()`（`lastReadyRefreshAt` 1 秒去重）→ `loadTools()` + `refreshOpenTool()`（清空 src 后重设触发重载，onload 补发主题）。

## 接口定义

- 复用现有广播协议，无新增 REST API：
  - `postMessage({action:'themeChange', theme})`（主框架→工具模块→工具 iframe）
  - `postMessage({action:'refresh'})`（主框架→工具模块）
  - `postMessage({action:'backendState', state:'ready'})`（主框架→工具模块）

## 关键决策

- 工具页主题桥放服务端注入而非改内置 HTML 资源：内置页只在缺失时复制到用户目录、无版本机制，注入对存量副本/导入工具一律生效。
- 同时监听 refresh 与 backendState:ready：前者覆盖自动启动与竞态兜底路径，后者覆盖标题栏手动启动路径（该路径只发 backendState）。
- 注入去重标记：避免工具页被二次注入导致重复覆盖。
