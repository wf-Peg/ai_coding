# 软件更新分发渠道调研

> 调研日期：2026-02 · 适用项目：CutShelter 桌面客户端（Electron）
> 背景：当前更新包通过 GitHub Releases 发布，国内用户访问 `api.github.com`（版本检查）与 `objects.githubusercontent.com`（文件下载）速度慢、不稳定。
> 结论先行：**本期不做渠道迁移，GitHub 仍为权威发布源；客户端已实现 gh-proxy 镜像兜底下载**，其余渠道按需再接入。

---

## 一、现状（改造前）

| 环节 | 实现 | 国内体验 |
|------|------|---------|
| 版本检查 | 后端 `/api/update/check` 直连 `api.github.com/repos/wf-Peg/ai_coding/releases/latest`（改造后带 10 分钟缓存） | 慢 / 偶发超时，有缓存缓解 |
| 更新包下载 | 客户端直连 GitHub asset（302 重定向到 `objects.githubusercontent.com`） | 慢，大文件易中断 |
| 更新包体积 | 改造前 232.6 MB（含重复 JAR 88 MB + jre 61 MB） | 下载体验差 |

改造后更新包约为 **90 MB 左右**（剔除 `frontend/clip-backend.jar` 重复 JAR 与 `jre/`，保留 `TODO/` 产品概览），下载负担减半以上。

## 二、渠道对比

### 1. GitHub Releases（现状 / 权威源）
- **免费额度**：免费，单文件上限 2 GB，Release 数量不限。
- **API**：完善（`releases/latest`、asset `digest` 提供 sha256、`browser_download_url`）。
- **国内速度**：慢（api.github.com / objects.githubusercontent.com 经常被限速或干扰）。
- **结论**：保留为发布主流程（`gh release create` 一键发布），作为权威源与项目历史存档。

### 2. gh-proxy 类镜像（本期已实施）
- **原理**：第三方公益代理，把 GitHub 下载 URL 前缀化转发，例如 `https://ghproxy.com/https://github.com/wf-Peg/ai_coding/releases/download/v1.0.7/clip-update-1.0.7.zip`。
- **费用**：免费，无需账号、无需仓库。
- **国内速度**：明显快于直连 GitHub（走国内/香港节点）。
- **风险**：公共实例稳定性参差、域名可能变更或下线。
- **实施**：客户端 `update-manager.js` 内置默认镜像前缀列表（`ghproxy.com` / `mirror.ghproxy.com` / `ghfast.top`），下载失败自动按序回退；高级用户可在 `update-config.json` 的 `mirrorUrls` 数组中自定义（优先级高于默认值）。
- **结论**：零成本、立即可用的国内加速方案，作为默认兜底。

### 3. Gitee（码云）发行版 —— 备选，本期不实施
- **免费额度**：免费；公开仓库可匿名下载发行版附件；单文件大小限制以 Gitee 官方配额页为准（历史上约 100 MB/文件，改造后更新包约 90 MB 可满足，需实施时核实）。
- **API**：有 OpenAPI v5（创建发行版 + 上传附件 `attach_files`），需个人访问令牌；上传附件的端点/限制以实际响应为准。
- **国内速度**：快（国内 CDN）。
- **接入成本**：需先在 gitee.com 手工创建同名仓库（可设 Gitee 仓库默认拉取 GitHub 镜像），然后在发布脚本中加一步上传。
- **结论**：若 gh-proxy 实例持续不稳定，Gitee 是最优的国内主分发源；按本文档第五节接入即可。

### 4. jsDelivr
- **原理**：免费全球 CDN，可代理 GitHub 仓库文件，**国内有节点、速度快**。
- **限制**：只代理仓库源码文件（非 Release asset），且单文件 ≤ 20 MB。
- **适用场景**：更新包（90 MB）放不进去，但可放**小体积 manifest**（如 `update-manifest.json`）作为"快速检查源"，让检查请求完全绕过 GitHub API。
- **结论**：可作为未来"快速检查"优化项（本文档第五节描述），本期未实施。

### 5. Cloudflare R2 / Pages
- **免费额度**：R2 10 GB 存储 + 无出站流量费；Pages 免费静态托管。
- **国内速度**：默认域名（`*.r2.dev` / `*.pages.dev`）在国内不稳定；绑定自定义域名 + 国内可达 CDN 才能稳定加速（涉及备案）。
- **结论**：适合海外用户或"零账单"静态托管 manifest/更新包；国内场景不优先。

### 6. 腾讯云 COS / 阿里云 OSS（免费额度）
- **免费额度**：COS / OSS 均有新用户免费额度（有时限）；存量收费。
- **国内速度**：快（配合 CDN 加速更佳）。
- **成本**：需要实名认证，可能涉及备案；非永久免费。
- **结论**：用户量大后再考虑；适合做正式分发 + 版本管理。

### 7. 其他（不推荐 / 不适合程序化更新）
- **蓝奏云 / 123 云盘**：国内快，但无稳定公开 API/直链，不适合自动更新。
- **Backblaze B2**：10 GB 免费，但海外节点国内慢。
- **Telegram / 网盘**：不适合桌面应用自动更新。

## 三、推荐架构（本期）

```
GitHub Releases（权威源，发布主流程）
        │  gh release create 上传：exe / dmg / AppImage / clip-update-{v}.zip / .sha256
        ▼
客户端检查：后端 /api/update/check（10 分钟缓存）──不可达──▶ 客户端直连 GitHub API
        │
        ▼
客户端下载：GitHub 原地址 ──失败──▶ gh-proxy 镜像1 ──失败──▶ 镜像2 ...（按序回退）
        │                    （下载后 SHA-256 校验，防中间人/损坏）
        ▼
applyUpdate：仅替换更新包内 resources 条目（jre/ 保留）→ 重启
```

- 检查链路：本地后端（快）→ GitHub API（带缓存）；后端不可达时客户端直连 GitHub（代理优先）。
- 下载链路：多源回退 + SHA-256 完整性校验 + 进度/源名展示。
- 发布链路：`scripts/release.bat` / `release.sh` 交互确认版本号 → 构建 → 更新包（`node scripts/build-update-zip.js`，输出 `clip-update-{v}.zip` + `.sha256`）→ `gh release create`。

## 四、改造后更新包内容

| 条目 | 是否进更新包 | 说明 |
|------|------------|------|
| `app.asar` / `app.asar.unpacked` | ✅ | 主进程代码 |
| `backend/` | ✅ | 后端 JAR（随版本更新） |
| `frontend/` | ✅ | 前端页面/资源（**已剔除重复的 clip-backend.jar**） |
| `TODO/` | ✅ | 工作台导入的产品概览 JSON（随版本更新） |
| `jre/` | ❌ | 版本间不变，随安装包分发；需要时 `--with-jre` 打全量包 |

## 五、未来扩展（按需接入）

### 5.1 接入 Gitee 作为国内主分发
1. gitee.com 创建同名公开仓库，可在仓库设置中开启"从 GitHub 镜像同步"。
2. 生成 Gitee 私人令牌（`https://gitee.com/profile/personal_access_tokens`）。
3. 发布脚本在 `gh release create` 后调用 Gitee OpenAPI：
   - `POST /api/v5/repos/{owner}/{repo}/releases`（创建发行版，tag_name=vX）
   - `POST /api/v5/repos/{owner}/{repo}/releases/{id}/attach_files`（multipart 上传更新包 + sha256）
   - 若官方 API 不支持二进制上传，则按 Gitee 页面指引手动上传，或使用第三方同步工具（如 action-gitee-release）。
4. 客户端 `update-config.json` 的 `mirrorUrls` 加入 Gitee 下载地址（`https://gitee.com/{owner}/{repo}/releases/download/vX/clip-update-X.zip`），即完成国内主分发。

### 5.2 jsDelivr 快速检查源（绕过 GitHub API）
- 发布时额外生成 `update-manifest.json`（version / sha256 / size / urls），提交到仓库并推 GitHub。
- 客户端检查顺序：`https://cdn.jsdelivr.net/gh/wf-Peg/ai_coding@main/update-manifest.json` → 后端 → 直连。
- manifest 需 ≤ 20 MB（实际仅几 KB），国内节点快。

### 5.3 正式大规模分发（用户量大后）
- 腾讯云 COS / 阿里云 OSS + CDN，脚本上传（`coscmd` / `ossutil`），配合上面的 manifest 方案即可无缝切换。
