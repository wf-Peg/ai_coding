# CutShelter UI 重构设计规格说明书

> 版本：v1.0（设计稿阶段）
> 状态：仅设计，未进入开发
> 配套原型：`design-prototype/index.html`（单文件，浏览器直接打开体验）
> 对标对象：NoteGen

---

## 1. 背景与目标

### 1.1 问题诊断

CutShelter 后端已具备完整的收件箱工作流模型，但前端没有把它暴露成产品主线，导致：

1. **信息架构平铺**：标题栏 `编辑器/工作台/剪藏/工具/设置` 五个平级入口，之下再挂 13+ 个子页面，用户不知道"该去哪"。
2. **心智模型错位**：记录时被要求选择 `store-only / ai-text / link-ai / doc-ai` 等**技术术语**，而非"现在整理 / 稍后整理"这种用户语言。
3. **AI 分散**：剪藏页"问我的剪藏库"是弹窗，编辑器页有独立的 Pet 助手侧栏，两套交互不统一。
4. **动作密集**：剪藏页顶部 5 组操作按钮混排，高频动作与低频维护动作无区分。

### 1.2 目标

在不改动后端的前提下，把**已经模型化的能力**翻译成**产品语言**，收敛信息架构、统一 AI 入口、降低认知负担，并对齐 NoteGen"先记录、再整理"的心智模型。

### 1.3 关键后端事实（本设计的地基）

| 字段 | 取值 | 说明 |
|------|------|------|
| `workflowStatus` | `inbox`（待整理）/ `organized`（已整理）/ `archived` | `inbox → organized` 的流转已实现 |
| `type` | `store-only` / `ai-text` / `link-ai` / `doc-ai` | 记录方式，与 `workflowStatus` 强绑定 |

**强绑定规则**（[`normalizeWorkflowStatus`](file:///Users/pengwenfeng/Documents/gitRep/trae_demo/codex-project/backend/src/main/java/com/example/clip/service/ClipService.java#L1030-L1055)）：
- `store-only` → 自动进 `inbox`
- `ai-text` / `link-ai` / `doc-ai` → 自动进 `organized`
- 非 `store-only` 出现在 `inbox` 会被强制改为 `organized`

> 结论：本设计**不改后端**，只在前端把这个强绑定模型"升格"为产品主流程。

## 2. 总设计原则

1. **一条主线 + 两条价值线**：记录线（捕获 → 收件箱 → 整理 → 写作/画布）是主流程；沉淀线（知识库/图谱/Wiki/Vault）是差异化，保留。
2. **记录不做选择**：记录时只回答一个决策——"现在整理 / 稍后整理"，技术类型由系统自动映射。
3. **AI 成为桥梁**：单一 AI 助手贯穿记录与写作，回答附来源、可一键整理。
4. **低频让位**：高频动作留台面，低频维护动作收进命令面板/设置。
5. **设计沿用产品既有 token**：不推倒重来，复用 `design-tokens.css` 的颜色/圆角/阴影/动效体系。

## 3. P0 — 收件箱主线化（最高优先，后端零改动）

### 3.1 信息架构

**改动前**（平铺）：
```
标题栏：编辑器 | 工作台 | 剪藏 | 工具 | 设置
（其下：知识库/图谱/Wiki/Vault/待办/学习计划/PDF/数据观测…）
```

**改动后**（两条线）：
```
主流程（工作流组）
  收件箱（默认首屏，inbox）
  写作（编辑器）
  画布（图谱升级）

沉淀（沉淀组）
  知识库
  知识图谱

其它
  工具（PDF 等并入）
  设置
```

**变更清单**：
- 新增顶级"收件箱"视图，设为默认首屏。
- `工作台` 承载"数据观测"等元视角。
- `待办` 作为记录的一种类型并入收件箱流。
- 全局搜索（⌘K）、设置降为全局支点。

### 3.2 记录方式映射（核心技术翻译）

用户在记录时看到的是**动作**，系统映射到**后端枚举**：

| 用户动作 | 后端 `type` | 落点 `workflowStatus` | 说明 |
|---------|------------|-----------------------|------|
| 截图 | `store-only` | `inbox` | 默认延后 |
| 粘贴文本 | `store-only`（默认）/`ai-text` | `inbox`/`organized` | 可选立即整理 |
| OCR | `store-only` | `inbox` | 默认延后 |
| 链接 | `link-ai` 或 `store-only` | `organized`/`inbox` | |
| 文件 | `doc-ai` 或 `store-only` | `organized`/`inbox` | |
| 待办 | `store-only`（todo 语义） | `inbox` | 待办并入记录流 |

**关键交互**：记录弹层中，"现在整理 / 稍后整理"二选一，默认"稍后整理"。

### 3.3 收件箱视图组件规格

| 组件 | 规格 |
|------|------|
| 页头 | 标题"收件箱" + 计数 + 主按钮"快速记录" + 次按钮"AI 助手" |
| 状态分段控件 | `待整理(5)` / `已整理(4)` / `仅存储(3)`，映射 `inbox/organized/archived` |
| 标签折叠分组 | 按标签分组，可展开/折叠，空分组自动隐藏 |
| 记录卡片 | 类型徽章（色点/图标）+ 标题摘要 + 来源·时间 + 状态徽章；悬停显现操作 |
| 状态徽章 | `待整理`(橙点) / `已整理`(绿点) / `仅存储`(灰点) |
| 批量操作条 | 勾选后浮现："整理选中 / 移入知识库 / 删除 / 取消" |
| 空状态 | 三步引导（①截图 ②进收件箱 ③一键整理） |
| 每日回看 | 见 §6.1 |

### 3.4 状态流转（验收依据）

```
store-only ──► inbox（待整理）
inbox ──[整理]──► type=ai-text 且 workflowStatus=organized
organized ──[归档/删除]──► archived / 删除
```

### 3.5 P0 验收标准

- [ ] 首屏进入即见收件箱，`inbox` 与 `organized` 视觉分离，不再混排。
- [ ] 记录入口不再出现 `store-only/ai-text` 技术词，只出现"现在整理 / 稍后整理"。
- [ ] 待办作为记录类型出现在收件箱中。
- [ ] 现有 `GET /api/clip/inbox`、`/list?workflowStatus=inbox` 接口直接支撑，无新接口。

## 4. P1 — 统一 AI 助手（次高优先，复用编辑器已有实现）

### 4.1 面板统一

以编辑器 [Pet 助手侧栏](file:///Users/pengwenfeng/Documents/gitRep/trae_demo/codex-project/frontend/editor.html#L302-L346) 为母版，推广为全应用统一侧栏，三处归并：
- 剪藏页"问我的剪藏库"弹窗 → 迁入统一面板。
- 编辑器 AI 写作辅助 → 同一面板，上下文切换。
- Prompt 配置弹窗 → 面板内"设置"抽屉。

### 4.2 上下文模型（三种，非一种）

| 上下文类型 | 触发场景 | 数据来源 |
|-----------|---------|---------|
| 选中记录 | 收件箱选中 ≥1 条 | 该条 `content/bodyContent` |
| 全库 | 无选中 | 检索库 |
| 当前文档 | 编辑器 | 当前文档 |

面板顶部设 `context switch` 指示器，明示 AI "在看什么"。

### 4.3 闭环动作

回答附 **来源引用卡片**，卡片含：
- 类型徽章 + 标题 + 摘要片段 + "来自收件箱/知识库"角标
- "整理为笔记"按钮 → 调已有 organize 流程 → 生成 `ai-text` 笔记 → 推送编辑器并置 `organized`
- "查看"按钮 → 跳转原记录

### 4.4 P1 验收标准

- [ ] 三个场景共用同一面板组件，仅上下文不同。
- [ ] 回答来源可点、可跳转、"一键整理为笔记"可用。
- [ ] 剪藏页与编辑器不再各自维护一套 AI 交互。

## 5. P2 — 动作密度管理 + 视觉细节

### 5.1 动作分组

对剪藏页顶部 5 组操作按钮，按"频率 × 特性价值"分层：

| 层 | 动作 | 处理 |
|----|------|------|
| 保留（特色卖点） | 整理今日内容 / 生成周报 / 整理收件箱 | 留在首屏 |
| 降级（低频维护） | Git 配置 / 同步仓库 / Prompt 配置 | 收进 ⌘K 或设置 |

**表现统一**：`图标 + 文字` 主按钮组，去掉 emoji 按钮（⚙️🔄📚📊📥），改用统一 SVG 图标体系。

### 5.2 视觉规格

| 项 | 规格 |
|----|------|
| 记录卡片化 | 徽章 + 摘要 + 时间 + 来源，替换纯文本行 |
| 确认/复杂配置 | 删除用 toast + 撤销；配置改右侧抽屉 |
| 动效 | 面板/抽屉沿用 `--app-duration-*` + `--app-ease-*` |
| 空状态 | 统一"首条引导" |

### 5.3 P2 验收标准

- [ ] 特色动作可 1 次点击触达。
- [ ] 维护类动作不在首屏抢占注意。
- [ ] 弹窗数量从 6+ 降至 2 个以内，其余改抽屉/命令面板。

## 6. 补充设计

### 6.1 每日回看（治"收藏完就忘"）

- **入口**：收件箱顶部横幅"每日回看 · N 条沉底的旧收藏 · 开始回顾"。
- **交互**：点击进入回顾卡片流，单张展示，底部操作：
  - `跳过`（记 skip）
  - `归档`（记 archive）
  - `仍有用`（记 keep，主按钮高亮）
- **进度**：顶部细进度条 + `当前/总数` 计数。
- **完成态**：汇总"保留了 X 条 · 归档了 Y 条"。
- **数据来源**：优先推送 `store-only` 且长时间未整理、或 `organized` 但久未回看的内容。

### 6.2 数据可移植性与信任感

- **位置**：设置页新增"数据与隐私"分区。
- **核心卖点**：信任卡"你的数据，100% 属于你"——纯文本文件（Markdown/JSON）本地存储、不绑定云端账号。
- **三个信任点**：本地优先 / 纯文本可读 / 一键带走。
- **可操作项**：一键导出（打包 zip）、存储位置展示（可打开目录）、数据格式说明。
- **目的**：直接回答用户两个根本问题——"收藏的数据安不安全"、"换软件带不带走得了"。

### 6.3 品牌命名统一

- 现状：代码中混用"碎碎记 / CutShelter / 剪藏 / DSH"。
- 建议：统一为单一名称（中文或英文二选一），全界面、窗口标题、欢迎页一致。
- 原型中暂用"碎碎记"占位。

### 6.4 冷启动引导（已并入空状态）

- 收件箱空态即首条引导三步：①截图 ②自动进收件箱 ③一键整理。
- 无需独立 onboarding，降低实现成本。

### 6.5 明确不做

- **手机剪藏**：产品目前无此能力，本阶段不做（用户已确认）。

## 6A. 编辑器（写作区）——高频操作区设计

> 编辑器在收敛后 IA 中归入侧栏「工作流」组第二项**写作**，是主线四环 `收件箱 → 整理 → 写作 → 画布` 的第三环，也是"整理为笔记"的落点。作为高频操作区，原型已从占位升级为完整视图，结构对齐现有 [editor.html](file:///Users/pengwenfeng/Documents/gitRep/trae_demo/codex-project/frontend/editor.html#L18-L152)。

### 6A.1 视图结构

```
写作视图
├── 左侧文档列表（232px，可后续收进抽屉）
│   ├── 标题「文档」+ 新建按钮
│   ├── 文档搜索框
│   ├── 分组：最近（来自收件箱 ×3）/ 其它（手写）
│   └── 文档项 = 类型图标 + 文档名 + 「来自收件箱 · 时间」
├── 编辑器主体
│   ├── 工具栏（对齐现有 editor.html，按 P2 密度收敛）
│   │   ├── 文件组：新建 Ctrl+N / 打开 Ctrl+O / 保存 Ctrl+S（主色）
│   │   ├── 文档身份：保存态圆点 + 文档名 + 「来自收件箱」徽章
│   │   └── 工具组：语言选择 / Markdown 预览 / 导出 / 存入剪藏
│   ├── 标签栏（多文档切换，新建标签 Ctrl+T）
│   ├── 编辑器主体（Markdown 排版，居中限宽 780px，可编辑）
│   └── 状态栏：行列 / 语言 / 编码 / 「已保存 · 本地纯文本」
└── 右侧 AI 面板（共享）：进入写作自动切「当前文档」上下文
```

### 6A.2 高频区的设计要点

| 要点 | 设计 | 依据 |
|------|------|------|
| 从收件箱直达 | 左侧列表「来自收件箱」分组置顶，"整理为笔记"推送后立即出现在此 | 闭环：收件箱 → 写作 |
| 动作收敛 | 工具栏从现有 10+ 按钮收敛为 7 个 + 1 主按钮，格式化/对比/插入图片等低频操作收进溢出菜单 | P2 密度管理 |
| 一键存入剪藏 | 保留现有「存入剪藏」主按钮，写作 ↔ 收件箱双向回流 | 对齐现有 editor.html |
| AI 上下文联动 | 进入写作视图 / 切换文档时，AI 面板上下文自动置为「当前文档」 | P1 统一 AI |
| 本地可信 | 状态栏常驻「已保存 · 本地纯文本」 | 信任感设计 |

### 6A.3 验收标准

- [ ] 从收件箱「整理为笔记」后，文档出现在写作左侧「最近」分组并可打开。
- [ ] 写作视图打开即见当前文档（无需手动加载文件）。
- [ ] 进入写作时 AI 上下文自动切到「当前文档」。
- [ ] 工具栏高频动作 ≤ 8 个，低频动作收进溢出菜单。
