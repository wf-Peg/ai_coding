# 收件箱回顾 + 剪藏体验 Bug 修复计划

## 概览（大白话对齐）

你反馈的 5 类问题，经过排查定位，我先把每类的**根因**讲清楚，再讲我怎么改。

### 1. 每日回看（收件箱回顾）这块一堆毛病
- **「归档」逻辑没补全**：现在点「归档」其实只是调 `deleteClip` 把剪藏彻底删了，跟删没区别，而且没做任何"归档整理"动作。
- **你说不需要归档**：同意。我的方案是**把「归档」按钮直接去掉**，回看只保留两个动作：**「跳过」**（今天先不看，明天还会再捞出来）和 **「仍有用」**（标记这条我看过了、留着，不再反复提醒）。
- **无法显示完整全文**：现在回看只显示摘要的**前 120 个字**，根本没给你看原文。改成显示**完整原文（可滚动）+ 配图**。
- **「仍用无效」**：现在点「仍有用」只偷偷记一个数字，什么都不发生，你当然觉得没用。改成：保留的条目会被**记录下来，之后不再重复推荐**，并且回看结束时列出来给你看。
- **今日回看完成图标太大 / 页面设计要调整**：完成页的大对勾图标没有尺寸限制，被撑得巨大。改成**小图标 + 简洁的统计卡**。
- **导出周报素材信息不全 / 你认为没必要**：这个功能确实把回看复杂化了，而且只导出一串数字没啥用。同意，**把「导出周报素材」按钮和那套「本周回顾」统计卡一起移除**，回看就是简单回看。以后真要做周报，走后台现有的 `/weekly-report` 单独做，不为回看做铺垫。

### 2. 剪藏「通过写作打开」慢、卡顿
根因找到了一个很明确的点：编辑器页面 `editor.html` 只预加载了 `javascript/python/yaml/css/html` 这 5 种语法高亮文件，但**没有预加载 `markdown/text/json/xml/sql`**。而剪藏默认就是 markdown —— 每次点开剪藏，ACE 都要**临时动态去加载 markdown 语法文件**，这就是卡顿的主要来源。

改法：
- 在 `editor.html` 里把这 5 个缺失的语法文件也**静态预加载**（跟其他 5 个一样），打开剪藏即点即开。
- 打开剪藏时，把「渲染 AI 侧栏」「刷新反链」这些**非必须的活挪到首屏画出来之后**再干，别挡住正文渲染。
- **大文件**：项目已有 `applyLargeFileMode`（>2MB 关 worker、>5MB 关换行/选中高亮）。再补一条：超大的文件（比如 >6MB）直接**降级成纯文本模式**，不跑完整 markdown 高亮，避免打字时一直卡。

### 3. 剪藏列表按标签分组没必要
现在列表把"每个标签的第一条"当成一个**可折叠的分组头**（`clip-group-head`）。你要的是：**直接按时间倒序平铺**，最新在最前面，不要分组。

改法：去掉 `renderClipList` 里的分组逻辑，列表项直接平铺（排序逻辑已经在 `fetchClips` 里按创建时间倒序了）。顺手清掉不再用的分组 CSS（`clip-group`/`clip-group-head`/`clip-group-body`）。

### 4. 删除不实时 + 「更多功能」菜单被隔壁剪藏盖住
- **删除不实时**：现在删完是先播个动画、然后**重新去后端拉整张列表**再渲染，所以感觉慢。改成：删掉动画结束后，**直接从本地已有列表里去掉这一条重新渲染**，瞬间消失；后台再静默刷新兜底。
- **更多菜单被盖住**：`更多功能` 的下拉（`.fan-drawer`）z-index 不够，当你把鼠标往隔壁那条剪藏的卡片上挪时，隔壁卡片把它盖住，按钮点不到了。改法：打开下拉时给**这条剪藏卡片提一个高层级**（`.more-open { z-index: 50 }`），关闭时还原，保证下拉永远浮在上面。

### 5. 剪藏图片不能放大/下载 + 导出不带图
根因：剪贴板截图这类剪藏，正文里只有一个**文字「剪贴板图片」**，真正的图片存在 `imagePaths` 里，列表只把它当缩略图显示，正文里**根本没渲染出图**，自然没法放大/下载/带图导出。

改法：
- 剪藏「原文」区：把该条剪藏的图片（`imagePaths` + 正文内嵌的 media 图）**真的渲染成 `<img>`**。
- 点正文里的图片 → 弹出**大图预览**，放大时带一个**下载按钮**（同一个效果也覆盖正文 markdown 里的图片）。
- 导出（md/html）：导出前**把图片读成 base64 内嵌进文件**，这样剪贴板截图导出的文件里是真实的图，不是那句「剪贴板图片」。

- 新增一个简洁的**图片预览弹窗容器**（大图 `<img>` + 下载按钮 + 关闭），供图片点击使用。

**`frontend/styles/clip.css`**
- 新增大图预览层与下载按钮样式（深色/浅色跟随主题）。

## 假设与决策

1. **移除「归档」按钮**：按你的意见，回看不再需要归档（原行为=删除，且无整理价值，容易误删）。
2. **移除「导出周报素材」按钮 + 完成页本周统计卡**：按你的意见，不为回看做周报铺垫；周报走独立后台能力。
3. **「仍有用」用本地标记实现**（localStorage 记 keep/skip，避免误删且改动最小）。不新增后端字段/接口，最稳、最少 bug。若你后续要跨设备同步"保留"状态，再单独加后端。
4. **大文件 text 降级阈值取 6MB**：高于此值跳过 markdown 高亮以避免卡顿；低于 5MB 保持现状。
5. 图片放大/下载/带图导出**仅作用在剪藏列表详情**，不扩展到知识模块（控制范围、少 bug）。

## 验证步骤

1. **回看**：初始化几条旧剪藏 → 打开「今日回看」→ 确认显示完整原文+图片、可滚动；点「跳过」明日还能再出，点「仍有用」后不再推荐且完成页小图标+保留/跳过统计正常；确认已无「归档」和「导出周报素材」按钮。
2. **编辑器提速**：点任意剪藏「在编辑器打开」→ 用 `devtools Performance`/肉眼确认正文立即出现、无语法加载延迟；`Ctrl+N` 新建 markdown 标签同样顺畅；用 >6MB 文本验证降级为 text 不卡。
3. **列表平铺**：列表刷新后确认按时间倒序平铺、无 `clip-group-head`，各分组/折叠失效不影响勾选、展开、删除。
4. **删除**：删一条 → 立即消失不闪回；展开另一条「更多功能」→ 鼠标横跨隔壁卡片确认下拉不被盖住、按钮可点。
5. **图片**：剪贴板截图剪藏 → 详情原文出现真实图片；点图弹大图预览，点下载能存图；「导出」md 文件里是 base64 图片而非「剪贴板图片」文字。
6. 确认 `commit_history.log` 按要求追加提交记录。
