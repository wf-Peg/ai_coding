# 修复写作区面包屑路径定位文件浏览器

## 摘要

修复编辑区顶部面包屑（全路径）两个缺陷：
1. **目录段点击后提示「空目录或无法访问」** —— 根因是面包屑逐级累加路径时**丢失了根前缀**（Unix 缺 `/`、Windows 缺盘符），把 `/Users/...` 累加成了 `Users/...` 相对路径，主进程 `editor-list-directory` 查询 `exists:false`。
2. **面包屑定位目录污染「📁 文件浏览器」按钮的默认行为** —— 点击面包屑段把目录写入 `fileTreeDir` 长期缓存，关闭后再点文件浏览器按钮仍打开缓存的目录，而不是当前文件的父目录。

改动全部收敛在 `frontend/js/editor.js`（单文件），无主进程 / preload / HTML / CSS 改动。

- CSS 侧 `.breadcrumb-seg` 已具备 `cursor:pointer` 与 hover 样式，无需改动。

## 修改方案（全部在 frontend/js/editor.js）

### 改动 1：`renderBreadcrumb` 构造完整绝对路径前缀

位置：L1039-1057。将 `acc` 循环累加替换为按平台前缀构造每个目录段的完整路径：

```js
const parts = filePath.split(/[/\\]+/).filter(Boolean);
if (!parts.length) return;
const isWinAbs = /^[a-zA-Z]:[/\\]/.test(filePath);
const isUnixAbs = filePath.startsWith('/');
for (let i = 0; i < parts.length - 1; i++) {
  // 目录段完整绝对路径：保留盘符 / 根前缀，避免相对路径定位不到
  let target;
  if (isWinAbs) {
    target = i === 0 ? parts[0] + '/' : parts[0] + '/' + parts.slice(1, i + 1).join('/');
  } else if (isUnixAbs) {
    target = '/' + parts.slice(0, i + 1).join('/');
  } else {
    target = parts.slice(0, i + 1).join('/'); // 相对路径保底（理论不出现）
  }
  const seg = document.createElement('span');
  seg.className = 'breadcrumb-seg';
  seg.textContent = parts[i];
  seg.title = '在文件树中打开 ' + target;
  seg.addEventListener('click', function () { openBreadcrumbDir(target); });
  // ... 其余 sep/file 逻辑不变
}
```

效果：`/Users/pengwenfeng/a.md` → 段依次可打开 `/Users`、`/Users/pengwenfeng`；`C:\Users\a\b.md` → `C:/`、`C:/Users`、`C:/Users/a`。

### 改动 2：`openBreadcrumbDir` 先登记目录再开面板，消除竞态并标记来源

位置：L1066-1074。

```js
function openBreadcrumbDir(dirPath) {
  if (!featureOn('breadcrumbBar')) return;
  const api = getElectronAPI();
  if (!api || typeof api.listDirectory !== 'function') return;
  // 先登记目标目录与一次性来源；未打开时再 toggle，loadFileTree 命中缓存直接加载，
  // 避免与 getFileDirectory 异步链形成竞态
  fileTreeDir = dirPath;
  fileTreeDirSource = 'breadcrumb';
  if (typeof toggleFileTree === 'function' && !fileTreeOpen) {
    toggleFileTree();
  } else {
    loadDirectory(dirPath);
  }
}
```

## 假设与决策

- **手动「选择目录」会话持久保留**：用户主动选择的位置视为持久定位，关闭再打开仍恢复；仅面包屑（文件头路径段）定位为一次性会话，关闭即清。这是对「与文件浏览器按钮隔离」的最贴切解读 —— 隔离对象是「文件头定位的缓存」。
- **默认会话每次唤起重新解析当前文件父目录**：default 会话（从未手动选择目录）不再复用旧的 `fileTreeDir` 缓存，严格满足「默认以当前文件父路径打开」。
- 无需改动主进程：前缀修复后传入的均为合法绝对路径，`editor-list-directory` 原样可用。
- 面包屑文件段（文件名）保持不可点击，与现状一致。
