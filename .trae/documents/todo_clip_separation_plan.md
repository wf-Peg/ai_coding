# 待办事项与剪藏功能分离重构计划

## 1. 现状分析

当前项目结构：
- `/workspace/frontend/index.html` - 包含剪藏功能和待办事项功能
- `/workspace/backend/` - 后端服务

问题：两个功能混合在同一个 HTML 文件中，布局相互影响，难以独立维护和扩展。

## 2. 重构目标

将页面分为两个独立的 HTML 文件：
- **待办事项页面**：占三分之一竖屏，独立的 HTML 文件
- **剪藏页面**：占三分之二竖屏，独立的 HTML 文件

## 3. 重构计划

### 3.1 创建独立的待办事项页面

**文件**：`/workspace/frontend/todo.html`

**内容**：
- 完整的待办事项时间线功能
- 基于 `timeline-todo.html` 的设计
- 包含优先级、筛选、编辑等功能
- 独立的样式和脚本

### 3.2 创建独立的剪藏页面

**文件**：`/workspace/frontend/clip.html`

**内容**：
- 完整的剪藏功能
- 保留原有的剪藏功能和样式
- 独立的样式和脚本

### 3.3 保留主入口页面

**文件**：`/workspace/frontend/index.html`

**内容**：
- 作为导航页面
- 提供两个功能的入口链接
- 简单的布局说明

### 3.4 后端调整

**文件**：无需修改

**说明**：后端 API 已经支持两个功能，无需任何调整。

## 4. 技术实现

### 4.1 待办事项页面 (`todo.html`)

- 完整复制 `timeline-todo.html` 的设计
- 集成后端 API 调用
- 保持与原待办功能相同的 API 接口

### 4.2 剪藏页面 (`clip.html`)

- 从 `index.html` 中提取剪藏相关的代码
- 保留所有剪藏功能和样式
- 确保 API 调用正常

### 4.3 导航页面 (`index.html`)

- 创建简单的导航界面
- 添加两个功能的入口链接
- 响应式设计，在小屏幕上自适应

## 5. 预期效果

- 两个功能完全分离，互不影响布局
- 每个页面专注于单一功能，提高可维护性
- 保持原有的所有功能不变
- 提供清晰的导航入口

## 6. 风险评估

**低风险**：
- 只是文件分离，不涉及核心功能修改
- 后端 API 保持不变
- 前端功能逻辑保持不变

**需要注意**：
- 确保两个页面的 API 调用路径正确
- 确保样式和脚本的独立性
- 确保导航链接正确

## 7. 实施步骤

1. 创建 `todo.html` 文件，实现完整的待办事项功能
2. 创建 `clip.html` 文件，实现完整的剪藏功能
3. 修改 `index.html` 为导航页面
4. 测试两个功能页面的正常运行
5. 验证导航页面的链接功能

## 8. 预期交付

- `/workspace/frontend/todo.html` - 独立的待办事项页面
- `/workspace/frontend/clip.html` - 独立的剪藏页面
- `/workspace/frontend/index.html` - 导航页面
