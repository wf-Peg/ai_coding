# 标题栏超出主窗口画布：根因实测与修复落地

> 范围：Windows 路径。macOS（`hiddenInset` + 系统交通灯）零改动。
> 说明：本文件是首版方案《标题栏超出主窗口排查与无边框最大化边界校正方案》**经真机实测修正后**的最终结论，
> 原方案中"Windows 最大化隐形边框导致标题栏被裁"的假设被实测**证伪**，最终修复点已按实测结论调整（见第四、五节）。

---

## 一、Summary（结论）

1. **真正的根因**：窗口"可见内容区"的**顶边落在屏幕工作区之上（y 为负）**，此时窗口内容顶部被屏幕裁掉，
   表现就是自定义标题栏被切掉一截、右侧全局搜索胶囊只露出下半部分。
   - 真机实测：把窗口顶到 `y=-16` → `getContentBounds() = {x:0,y:-16,w:1200,h:672}`，`overTop=16`；
     截图（533px 高 ÷ 672 内容高 = 0.792 缩放）反推出的标题栏上移量 ≈16px，两者吻合。
   - 该状态由偶发边界事件引入：显示器拔插 / 分辨率或 DPI 变化 / OS 会话恢复 / 原生全屏（F11）退出后的边界残留 /
     系统 Aero Snap 或外部程序改位。既有 `ensureWindowVisible()` 只在 创建时、`display-metrics-changed`、
     `leave-full-screen`、`show`/`focus`（250ms 去抖）触发，**漏掉了 `unmaximize` 与窗口被移动（Aero Snap）这两条路径**。
2. **被证伪的假设（原方案）**：Windows 最大化时 `getBounds()` 确实四边各外扩 8 DIP，但那是**不可见调整边框**，
   `getContentBounds()` 正好等于工作区 —— **最大化不会裁掉标题栏**；且最大化态 `setBounds()` 会被系统立即覆盖（无效）。
   因此原方案里的"最大化后校正 bounds"被删除，降级为只输出诊断日志。
3. **顺带修掉的真实缺陷（渲染层）**：主页面 `index.html` 缺 `box-sizing: border-box` 且用 `100vh` 换算，
   `.titlebar` 实占 39px 而 `.app-layout` 按 `calc(100vh - 38px)` 计算 → 多出 1px、页面可被程序化滚动
   （`overflow:hidden` 只禁用户滚动，不禁 `focus()/scrollIntoView`）。已改为 100% 高度基准 + `border-box`，整页零溢出。

## 二、实测取证（Electron 36 真机，1280×672 工作区 @150% 缩放）

用于取证的临时脚本放在 `.tmp/`（验证后已删除），每轮均以 JSON 打印窗口/内容区/工作区/渲染层度量。

### 第一轮：最大化前后对照

| 状态 | `getBounds()` | `getContentBounds()` | `workArea` | 渲染层 `innerHeight` |
|---|---|---|---|---|
| 普通窗口 | `40,0,1200×672` | `40,0,1200×672` | `0,0,1280×672` | 672 |
| 最大化（原生） | `-8,-8,1296×688` | **`0,0,1280×672`** | `0,0,1280×672` | 672 |
| 最大化 + `setBounds(workArea)` | `-8,-8,1296×688`（**未生效**） | `0,0,1280×672` | `0,0,1280×672` | 672 |

结论：最大化态内容区**正确贴合工作区**，不需要也不能通过 `setBounds` 校正。

### 第二轮：候选修复手段比对

| 手段 | 结果 | 判定 |
|---|---|---|
| `unmaximize()` + `setBounds(workArea)` | `bounds=0,0,1280×672`，`maximized=false` | 有效但改变最大化语义，**不采用** |
| 最大化 + `setResizable(false)` + `setBounds` | `getContentBounds()=0,0,1266×658`（**反而缩小 14px**） | **明确避免** |
| 非最大化态 `y=-15`（模拟越界） | `getContentBounds()=0,-16,1200×701`，`overTop=16` | **命中用户现象** |

### 第三轮：修复有效性 A/B

| 检查项 | 修复前（还原旧 CSS / 人为越界） | 修复后 |
|---|---|---|
| `.titlebar` 实测高度 | 39px | **38px** |
| `.app-layout` 顶边 | 39px | **38px** |
| 整页 `scrollHeight - clientHeight` | 1px（被 body 裁掉，页面可程序化滚动） | **0** |
| 窗口顶到 `y=-16` 后 `overTop` | 16px | 走钳制逻辑后 **0px**（`contentBounds=0,0,1200,672`） |

## 四、最终变更清单（已落地）

### 变更 1：`electron/main.js` —— 内容区越界钳制 + 触发时机补齐

1. 新增 `measureContentOverflow(win)`：以 **`getContentBounds()`**（用户真正看到的内容区）为基准，计算
   `overTop / overLeft / overBottom / overRight`；`overXxx > 0` 即表示该方向被屏幕裁掉。
   > 关键：判定必须用 `getContentBounds()`，用 `getBounds()` 会把最大化态的 8px 隐形边框误判成"溢出"。
2. 新增 `logContentOverflowDiag(win, reason)`：仅在 `WINDOW_DIAG=1` 时打印
   `bounds / contentBounds / workArea / scale / maximized / overTop…` 对照，默认零噪音（对齐既有 `SHORTCUT_DEBUG=1` 约定）。
3. `ensureWindowVisible()`：
   - 非最大化：保持原有"顶/左侧越界 → 对齐工作区原点；整体离屏 → 主屏居中"，日志追加 `overTop/overLeft` 便于回溯；
   - 最大化：**只记诊断日志，不做 setBounds**（实测无效且无必要）；
   - 全屏：跳过（系统接管）。
4. `unmaximize` 事件：延迟 300ms 校准（还原后边界可能残留在屏外）。
5. `move` 事件：400ms 静默去抖后校准（覆盖 Aero Snap / 拖拽 / 外部改位；拖动过程不干预）。
6. `maximize` 事件：延迟 200ms 输出诊断；注释写明"若日志出现 `overTop/overBottom > 1`，需改为应用侧自管最大化"。

### 变更 2：`electron/main.js` + `electron/preload.js` + `frontend/index.html` —— 诊断链路

- `frontend/index.html`：`reportTitlebarDiag(tag)` 采集 `innerSize / outerSize / screenPos / dpr /
  titlebarTop / titlebarHeight / scrollTop / overflowY`；在"启动 + 最大化状态变化"时上报。
- `electron/preload.js`：新增 `windowDiagReport(payload)`、`onWindowDiagEnabled(cb)`。
- `electron/main.js`：`did-finish-load` 时按 `WINDOW_DIAG=1` 下发 `window-diag-enabled`；
  新增 `ipcMain.on('window-diag-report')`，把渲染层度量与主进程 `bounds/workArea/scale` 合并打印为 `[WindowDiag]`。

### 变更 3：`frontend/index.html` —— 布局精确化（消除 1px 溢出）

- 新增 `html { height: 100%; overflow: hidden; }`（视口高度基准 + 禁整页滚动）；
- `body`：`height: 100vh` → `height: 100%`；
- `.titlebar`：新增 `box-sizing: border-box`（38px 含 1px 下边框）；
- `.app-layout`：`height: calc(100vh - var(--titlebar-height))` → `calc(100% - var(--titlebar-height))`。

## 六、风险与取舍

1. `move` 去抖钳制只纠正"顶/左侧越界"，不会动窗口尺寸，也不会在拖动过程中抢焦点；
2. 不采用 `setResizable(false)+setBounds`（实测会让内容区缩小 14px），不采用最大化态 `setBounds`（实测被系统覆盖）；
3. 保持 `frame: false` + 自绘窗口按钮（延续上一版决策），不回退 `titleBarOverlay`；
4. 诊断日志默认静默，需要时 `WINDOW_DIAG=1`（与 `SHORTCUT_DEBUG=1` 一致），只读、不改变行为，可长期保留。
