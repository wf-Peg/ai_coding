# 「纪念日 / 倒计时」模块设计方案（设计沟通版，不开发）

> 目标：一个**纯前端、自包含、单文件**的纪念日/倒数日模块。可作为「碎碎记」工具中心的一个工具**嵌入**（桌面），也能作为**移动端 PWA**（把 HTML 添加到手机桌面快捷方式）独立使用；数据**完全独立**存储（localStorage）+ **JSON 导入/导出**，保证桌面与手机数据互通。
>
> 关键词：纪念日 / 倒数日 / 通知提醒 / PWA / 工具模块嵌入 / 数据导入导出 / 工作台临期卡片

---

## 一、现状分析（基于代码库探索）

| 维度 | 现状 | 说明 |
|---|---|---|
| 前端形态 | 多 HTML 单页模块（`frontend/*.html` 约 18 个） | `index.html` 为主框架，其余为独立页面 |
| 工具中心 | `frontend/tools.html` + `js/tools-core.js` | 两种嵌入方式：**导入工具**在 overlay iframe 中运行（`/api/tools/{id}/page`）；**顶层模块子工具**（如学习计划、数据观测台）通过 `postMessage({type:'navigateModuleTool'})` 跳主框架视图 |
| 主题令牌 | `frontend/styles/design-tokens.css` 统一 `--app-*` | 三主题（notion/regular/dark），组件一律消费 `--app-*` |
| 静态服务 | Electron 主进程用 `serve-static` 托管 `frontend/`，入口 `index.html`，SPA 回退 | 开发/打包均走 `http://127.0.0.1:3001`（**非 file://**） |
| 桌面系统通知 | `package.json` 已依赖 `node-notifier`；Electron 主进程 | 已用于剪藏同步等，**具备桌面系统级通知能力** |
| PWA 基础 | **无** manifest、无 Service Worker | 移动端需要新增 |
| 公网部署 | `website/` 经 `wrangler pages deploy website --project-name=cutshelter` 部署到 Cloudflare Pages（HTTPS） | 移动端 PWA 承载首选 |

**关键结论**：Electron 内 iframe 与主框架同源（`127.0.0.1:3001`），因此 `anniversary.html` 嵌入后与主应用**共享同一 localStorage 源**；而手机 PWA（`pages.dev` 域）是另一源。两域数据只能靠**导入导出 JSON 打通**，这正好契合「数据同时兼容桌面与手机」的诉求。

## 四、通知能力设计（关键取舍）

> 已与用户确认：**本地提醒为主**。在此基础上分端细化。

### 桌面端（Electron 嵌入）——支持真正的系统级通知
Electron 具备原生能力 + `node-notifier`，即使窗口最小化/托盘也能弹通知。这是手机做不到的优势。
- **方案 A（推荐，零主进程改动）**：iframe 内用浏览器 `Notification API` + `node-notifier` 的网页版调用路径。Electron 渲染层 `new Notification()` 原生支持系统通知（跨平台），无需新增 IPC。
- **方案 B（更强，需小幅主进程/IPC）**：通过 `document` 运行态走主进程 `node-notifier`，最小化到托盘也能弹。作为 P1 增强，不动首版。

实现要点：临期判定用**纯函数**（给定 `today` 与条目日期 → 返回「今天/已过N天/剩余N天/临期」），在页面打开、定时器、窗口获得焦点时执行一次；命中「今天或临期(≤7天且未通知过)」即弹通知，并用 `localStorage` 记 `lastNotified` 去重，避免每次打开重复弹。

### 移动端（PWA）——本地提醒为主
- 纯前端 + 不放公网推送服务，**无法做到关闭浏览器后的后台定时推送**（iOS Safari 对 PWA 尤其受限）。
- 实现能力：
  - 页面打开时：顶置横幅 + 高亮徽标 + 卡片排序，直观「临期置顶」；
  - 支持 `Notification.requestPermission()`：在**页面打开/切回**时弹系统通知；
  - 分层「今天 / 临期(≤7天) / 已过 / 未来」视觉区。
- 说明文案内置：对用户提示「想及时收到提醒，请保持页面/浏览器打开」。

## 五、数据存储与数据模型

### 存储选型（完全独立，已确认）
- **单一来源**：`localStorage`，key 固定为 `anniversary_data_v1`，值为一个 JSON 对象（整库一个 key，便于一次性导出/迁移）。
- 无后端、无 SQLite 依赖；嵌入时与主应用同源（桌面）或 PWA 独立源（手机）。
- **版本化**：数据结构带 `ver`，加载时做轻量迁移（`ver` 递增），为 P1 字段扩展留开关。

### 数据模型（JSON 结构草案）
```jsonc
{
  "ver": 1,
  "updatedAt": "2026-09-14T08:00:00.000Z",      // 导出/导入校验用
  "entries": [
    {
      "id": "a1b2c3",
      "type": "anniversary",                      // "anniversary" 纪念日(已过) | "countdown" 倒数日(未来)
      "title": "我们在一起",
      "date": "2022-05-20",                       // 起始日期
      "category": "恋爱",                          // 分类标签
      "pinned": true,                             // 置顶
      "remind": 7,                                // 临期/提前提醒天数（0=当天）
      "note": "",                                  // 备注（P1 用，预留）
      "createdAt": "2026-09-14T08:00:00.000Z",
      "updatedAt": "2026-09-14T08:00:00.000Z"
    }
  ]
}
```
- `type` 决定计时方向：`anniversary` → 按「已过 N 天」；`countdown` → 按「剩余 N 天」。
- `pinned` 置顶条目恒在最前；同级按 `date` 远近排序。
- 天数计算用**纯函数** `anniversary-shared.js`：`daysBetween(today, date)` / `toReminderState(entry, today)` → `{ label, cls, upcoming }`，桌面手机共用同一逻辑保证口径一致。
- **日期解析规则（开源通行做法，防差一天）**：日期字符串按**本地日历日**解析——手动拆分 `Y-M-D` 后 `new Date(y, m-1, d)`，禁止直接 `new Date('YYYY-MM-DD')`（JS 将其按 UTC 零点解析，在 UTC 负时区会显示早一天）；天数差用「两日期归零时分秒后按自然日差取整」，不用毫秒除 86400000（避夏令时/闰秒漂移）。

### 导入/导出
- **导出**：`JSON.stringify(整库)` → 触发浏览器下载 `anniversary-backup-YYYYMMDD.json`（iframe 内用 `Blob + a[download]`，Electron 支持）。
- **导入**：`<input type=file accept=".json">` 读取 → 校验 `ver` 与 `entries` 结构 → 覆盖式或**合并式**导入（默认合并、按 id 去重），成功 toast。
- 入口：页面右上角「导出」「导入」按钮，桌面/手机完全一致 → 实现「桌面导出 → 手机导入」的数据互通。

## 六、桌面嵌入 + 工作台卡片接入（含你补充的两点）

### 嵌入方式（桌面工具中心）
- 采用**导入工具**模式：注册一个内置工具卡片，点击后 overlay iframe 加载 `anniversary.html`。
- 需在 `frontend/js/tools-core.js` 增加一条 `SYSTEM_TOOLS`/内置项：`{ id:'anniversary', name:'纪念日', icon:'🎂', builtin:true, system:true, src:'anniversary.html', category:'生活工具' }`，并让 `openTool()` 对这类 `src` 工具走 iframe（新增一个轻分支，不动现有导入工具逻辑）。
- 主题同步沿用 `forwardThemeToTool()` 的 `postMessage({action:'themeChange'})`，页面监听后 `documentElement.setAttribute('data-theme', …)`（与现有工具一致）。
- 打包：`anniversary.html` + `js/anniversary-shared.js` 放 `frontend/`（随 `extraResources` 打包，无需改 package.json 配置，只加文件）。

### 移动端 PWA（独立页）
- 新增 `website/anniversary.html`（或复用同一文件经构建复制），随现有 `wrangler pages deploy` 上公网（HTTPS），用户在手机浏览器打开 → 「添加到主屏幕」。
- 新增 `website/manifest.webmanifest`（name「纪念日」、图标、`display: standalone`、`theme_color` 取主色）——仅在移动端接入，桌面 Electron 不用；`apple-touch-icon` 让 iOS 添加桌面时使用图标。
- 支持离线：轻量 Service Worker 缓存 `anniversary.html` 与 shared.js（可选 P1，首版在线即可）。**注意**：PWA 缓存与 iframe 共享文件需避免版本冲突，用固定文件名+`Cache-Control` 处理。

### 工作台临期卡片接入（数据接口预留，P1）
目标：在工作台（`workspace.html` / 首页）能读到「临期记录」并渲染卡片，且不破坏模块的自包含独立性。
- **只读数据接口**：`js/anniversary-shared.js` 导出
  - `AnniversaryStore.load()` / `.save(data)`：封装 `localStorage` `anniversary_data_v1` 的读写（**源无关**：桌面 iframe 与主框架同源可直读；若今后跨源再加 postMessage/桥）。
  - `AnniversaryCalc.getUpcoming(entries, today, days)`：返回「临期/今天」条目的 `[{id,title,date,label,cls}]`。
  - 工作台引入 shared.js，调用 `getUpcoming` 渲染「🕰 临期纪念」卡片区；点击可跳转/浮层展开工具页。
- **约定**：工作台只读，不写；写操作始终收敛在 `anniversary.html` 内。保证模块可独立运行、也可被聚合消费。
- 首版**不做**，仅完成 shared.js 接口形态与文档，P1 接入。

## 七、UI / 交互设计（贴合全局主题规范）

- **页面结构**（单页）：
  - 顶栏：标题「🎂 纪念日」+ 右侧「导出 / 导入」+ 搜索（可选）。
  - 主体：卡片列表，按 `置顶 > 今天/临期 > 未来(倒计时) > 已过(纪念日)` 分区，每类带小标题；窄屏单列、桌面多列（CSS grid `repeat(auto-fill, minmax(240px,1fr))`）。
  - 卡片：图标 + 标题 + 大字天数（如 `1234 天`）+ 日期 + 分类徽标(badge) + 状态点（今天=primary、临期=warning、已过=normal）。
  - 底部浮动「＋ 新增」按钮（移动端 FAB）。
- **新增/编辑弹窗**：类型切换（纪念日/倒数日）、标题、日期（`<input type="date">`）、分类、置顶开关、提前提醒天数。
- **删除**：继承内存惯例——**带 `240ms` 淡出+右侧收缩动画**后再刷新列表，并 toast 提供「撤销」（6s）（复用现有 `clip` 的删除动画与撤销范式，见项目内存规范）。
- **样式**：一律用 `design-tokens.css` 的 `--app-*`（禁硬编码色值），支持 notion/regular/dark 三主题；动画时长用 `--app-duration-fast/normal` 与 `--app-ease-smooth`。
- **响应式**：`≤768px` 单列卡片、FAB、紧凑顶栏（对齐现有窄屏惯例）。

## 九、假设与决策（记录）

| # | 决策 | 影响 |
|---|---|---|
| 1 | 本地提醒为主，移动端无后台推送 | 符合纯前端、零后端；文案告知用户 |

| 7 | 单一 `localStorage key`（`anniversary_data_v1`）整库存 | 便于版本迁移与一键导出 |

## 十、验收标准（Verification）

P0 功能验证：
1. 桌面嵌入：工具中心出现「纪念日」卡片，点击 iframe 打开，主题随全局切换，新增/编辑/删除正常。
2. 桌面通知：设置临期条目，打开页面/刷新时对应状态触发系统通知；去重（不重复弹）。
3. 手机 PWA：`website/anniversary.html` 上公网后手机浏览器打开 → 「添加到主屏幕」→ 以独立窗口打开、显示图标；`manifest` 生效。
4. 数据互通：桌面导出 `anniversary-backup-*.json` → 手机导入 → 数据完整一致；再反向导出导入验证。
5. 天数计算正确：`anniversary` 显示已过 N 天，`countdown` 显示剩余 N 天；今天/临期状态正确。
6. 深色/浅色：三主题下读写正常，无硬编码色块残影。
7. 发版打包：`frontend/` 新增文件随 `extraResources` 打入，无构建报错。

P1 预留验证：工作台 `getUpcoming` 返回临期数据，卡片可渲染（接入后在验收清单补充）。
