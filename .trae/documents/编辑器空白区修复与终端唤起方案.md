# 编辑器空白区修复与终端唤起方案

## 一、需求摘要

1. **修复空白区**：编辑模块的编辑区画布下方存在一段多余空白占位区，需查明根因并修复。
2. **唤醒系统终端**：仿照 JetBrains IDE（IDEA）的 Terminal 功能，在编辑器里唤起一个**外部系统终端窗口**，并定位到当前打开文件所在目录；若没有打开文件（或目录无效），则回退到系统设置中的存储路径（知识库根目录）。需支持 **Windows、macOS、Linux** 三平台，其中 macOS 为本次确认补充。

## 二、现状分析

### 2.1 空白区根因（已确认）

- DOM 结构：[editor.html](file:///l:/归档/30_Projects (行动项目)/31_Work (主要工作)/code/ai_coding/frontend/editor.html#L106-L119) 中 `.backlinks-pane` 位于 `.main-pane` 之前的 `.editor-workspace` 内。
- `.editor-workspace` 是 grid 容器（`grid-template-columns: 0fr minmax(0,1fr) 0fr`，见 [editor.css](file:///l:/归档/30_Projects (行动项目)/31_Work (主要工作)/code/ai_coding/frontend/styles/editor.css#L339-L347)）。
- 抽屉面板定位规则（[editor.css](file:///l:/归档/30_Projects (行动项目)/31_Work (主要工作)/code/ai_coding/frontend/styles/editor.css#L363-L385)）中，`grid-column: 1; grid-row: 1` 的显式定位**只覆盖了 `filetree-pane / history-pane / recent-pane / fav-pane`，漏掉了 `backlinks-pane`**。
- 由于 `.backlinks-pane` 无 `grid-row: 1` 定位，浏览器将其放入隐式网格行（第 2 行），从而在编辑区下方撑出一整行空白占位。

> 修复即：把 `.backlinks-pane` 加入该定位选择器列表。这是纯 CSS 一行改动。

### 3.2 唤起系统终端（跨平台）

#### 3.2.1 后端：新增 IPC 处理器

**文件**：`electron/main.js`

在现有 `editor-get-file-directory`（L1979）之后新增一个 `editor-open-terminal` handler：

```javascript
// 唤起系统终端，定位到当前文件目录；无则回退知识库根目录（跨平台）
ipcMain.handle('editor-open-terminal', async (event, payload) => {
  try {
    const config = loadConfig();
    // 1) 优先使用当前打开文件所在目录
    let cwd = null;
    const fileToken = payload && payload.fileToken;
    if (fileToken) {
      try {
        const fp = editorFileService.resolveToken(fileToken);
        const dir = path.dirname(fp);
        if (fs.existsSync(dir) && fs.statSync(dir).isDirectory()) cwd = dir;
      } catch (e) { /* 忽略，回退 */ }
    }
    // 2) 无有效文件目录 → 回退知识库根目录（系统设置中的存储路径）
    if (!cwd) cwd = resolveVaultRoot(config);
    if (!cwd || !fs.existsSync(cwd)) {
      return { success: false, message: '无法确定有效目录' };
    }

    // 3) 跨平台唤起系统终端
    if (process.platform === 'darwin') {
      // macOS：open -a Terminal <dir> 以该目录为工作目录打开新窗口
      spawn('open', ['-a', 'Terminal', cwd], { detached: true, stdio: 'ignore' })
        .unref();
    } else if (process.platform === 'win32') {
      // Windows：优先 Windows Terminal，失败回退 cmd.exe
      try {
        spawn('wt.exe', ['-d', cwd], { detached: true, stdio: 'ignore' }).unref();
      } catch (e) {
        spawn('cmd.exe', ['/k', 'cd', '/d', cwd], { detached: true, stdio: 'ignore' }).unref();
      }
    } else {
      // Linux/其它：x-terminal-emulator（多发行版通用），以 cwd 为工作目录
      spawn('x-terminal-emulator', [], { detached: true, stdio: 'ignore', cwd }).unref();
    }
    log.info('[EditorTerminal] opened terminal at', cwd);
    return { success: true, cwd };
  } catch (err) {
    log.error('[EditorTerminal] open failed:', err.message);
    return { success: false, message: err.message };
  }
});
```

**说明**：
- 复用已有 `resolveVaultRoot`（3.2.1 前文已存在于同一 `setupIpc` 作用域，可直接调用）。
- `spawn` 需从 `child_process` 引入（确认 main.js 顶部已有 `const { spawn } = require('child_process')`，若无则补一行）。
- `detached: true + unref()`：让终端进程独立于 Electron 生命周期，避免随窗口关闭被回收。
- 返回 `{ success, cwd }` 供前端提示。

function openTerminalInDir() {
  const token = getCurrentFileToken(); // 复用现有取当前文件 token 的逻辑
  window.electronAPI.openTerminal({ fileToken: token })
    .then((res) => {
      if (res && res.success) showToast('已在 ' + res.cwd + ' 打开终端');
      else showToast((res && res.message) || '打开终端失败');

## 四、假设与决策

- **终端为外部系统窗口**：按用户意图（"唤醒 terminal"，区别于 IDEA 内嵌面板）唤起独立系统终端，非编辑器内嵌面板。
- **回退目录**：无打开文件或目录无效时，回退到 `resolveVaultRoot(config)` 解析出的知识库根目录（即系统设置中的存储路径体系）。
- **快捷键**：采用 `Alt+T`（Terminal），贴近但不等同于 IDEA 的 Alt+F12，避免与其它功能冲突。
- **macOS 终端**：用 `open -a Terminal <dir>` 唤起默认 Terminal.app，并以其目录为工作目录。
- **Windows 终端**：优先 `wt.exe`（Windows Terminal），失败回退 `cmd.exe /k cd /d <dir>`。
- **Linux**：使用 `x-terminal-emulator`（多数发行版通用符号链接）。
- 不新增内嵌终端/面板，不做过度设计。

5. **回归**：确认文件树/历史/最近/收藏/反链/AI 面板的抽屉交互、对比/预览模式均不受影响。
