# 画布模块对标幕布（大纲 ⇄ 画布）实施方案

> 用户输入：`/plan 画布模块调用对齐：https://mubu.com/home`
> 澄清结论：**"调用对齐" = 设计与功能层面对标幕布（大纲笔记 + 一键生成思维导图），并作为画布模块的产品最终方向**；`mubu.com/home` 是参考产品（其首页即「文档列表」，说明多画布是幕布范式的一环）。
> 补充要求：复杂点先做 MVP、分阶段实现；任务完成情况实时对齐更新；优先检索开源项目迁移实现、不重复造轮子；兼顾性能。

---

## 一、Summary（要做什么）

把「碎碎记」现有的**自由画布**（单文档、卡片自由摆放）升级为**幕布式「层级大纲 ⇄ 画布」双视图笔记模块**，四项能力全做，按 MVP 分阶段落地：

| 能力 | 幕布对应 | 本方案落点 |
|---|---|---|
| 层级大纲模式 | 极简大纲笔记（无限层级、折叠、纯键盘） | 画布页新增左侧大纲面板，`canvas_node` 增 `parent_id/order_index` |
| 一键大纲 ⇄ 画布 | 一键生成思维导图 | 用 `d3.tree` 分层排版写回 `x/y`；内容改任一侧即时同步 |
| 多画布文档列表 | mubu.com/home 文档列表 | 新增 `canvas_doc` 表 + `doc_id`，画布页内新增「文档列表」视图 |
| 输入与导出细节 | 快捷键 / Markdown / LaTeX / 导出 | 键盘范式对齐 + 导出 Markdown/OPML/PNG；LaTeX 见 M4 |

**范围铁律**：本方案**不动 `index.html`、不动知识图谱 `knowledge-graph.*`、不动后端 Java 逻辑**（后端快照是 Map 透传，仅补一个 `putIfAbsent`）。画布页仍是主框架 `canvas` 视图内的 `graphFrame`。

## 三、统一模型与关键决策（先定规矩，避免返工）

### 3.1 一份数据，两种视图（"单源"）

- **结构真源 = `canvas_node.parent_id / order_index`**（由大纲编辑维护）。
- **位置 = `canvas_layout.x/y`**（视觉缓存，可随时重算；大纲排版只是"批量写坐标"）。
- 画布上**拖动卡片不改结构**；在大纲上**缩进/移动只改结构**，随后可选择"按大纲重新排版"刷新坐标。
- 内容（`text/title`）两侧共用一份，编辑任一侧即时同步另一侧视图。

### 3.2 多文档隔离

- 新增 `canvas_doc`；`canvas_node/canvas_edge/canvas_group` 加 `doc_id`；`canvas_layout` **不加** `doc_id`（`node_id` 全局唯一，按文档取坐标用 JOIN，避免冗余与双写不一致）。
- 旧数据：v7 迁移时创建默认文档 `doc:default`（标题「我的画布」）并把全部历史画布数据挂上去，`order_index` 按 `created_at` 递增，`parent_id` 全 NULL（=平铺根节点，视觉与现在一致）。
- 每个画布页只加载**当前文档**的节点/连线/分组/坐标。

### 3.3 编辑器内不新增主框架视图

文档列表、大纲面板都做成**画布页内部的视图状态**（不改 `index.html` 的 `viewMap/VIEW_IFRAME`），沿用仓库《无限画布》文档"不另开入口"原则。

## 四、Proposed Changes（文件级改动清单）

### M1 · 数据层 + 单文档大纲闭环（MVP 主批次）

#### 1) `electron/sqlite/init.js`（改）

- 新增 `SQL_V7`：
  ```sql
  CREATE TABLE IF NOT EXISTS canvas_doc (
    id TEXT PRIMARY KEY, title TEXT, sort_index INTEGER, created_at TEXT, updated_at TEXT
  );
  CREATE INDEX IF NOT EXISTS idx_canvas_node_doc ON canvas_node(doc_id, parent_id, order_index);
  CREATE INDEX IF NOT EXISTS idx_canvas_edge_doc ON canvas_edge(doc_id);
  CREATE INDEX IF NOT EXISTS idx_canvas_group_doc ON canvas_group(doc_id);
  ```
- 新增 `addColumnIfMissing(db, table, column, ddl)`（读 `PRAGMA table_info` 判断后再 `ALTER TABLE ... ADD COLUMN`，保证幂等），为 `canvas_node` 补 `doc_id / parent_id / order_index`，为 `canvas_edge / canvas_group` 补 `doc_id`。
- 新增回填：确保 `doc:default` 存在 → `UPDATE canvas_node SET doc_id='doc:default' WHERE doc_id IS NULL`（edge/group 同理）→ `UPDATE canvas_node SET order_index = <按 created_at 的行号> WHERE order_index IS NULL`。
- `migrate()` 中在写版本号之前插入 `if (current < 7) { db.exec(SQL_V7); ...回填... }`；`SCHEMA_VERSION` → `7`。
- 顶部注释补 v7 说明（沿用现有「vN：……」注释风格）。

#### 2) `electron/sqlite/canvas-doc.js`（新建）

镜像 `canvas-group.js` 的写法（纯函数 + `dbConn` 入参 + JSDoc）：

- `listDocs(dbConn)` → `[{id,title,sortIndex,createdAt,updatedAt}]`（按 `sort_index`）
- `createDoc(dbConn, {title})` → `{id:'doc:'+uuid, title}`（`sort_index` = max+1）
- `renameDoc(dbConn, id, title)`、`deleteDoc(dbConn, id)`（事务级联删 node/edge/group/group_member/layout）
- `ensureDefaultDoc(dbConn)`（迁移与启动兜底共用）、`touch(dbConn, id)`
- `DEFAULT_DOC_ID = 'doc:default'`

#### 3) `electron/sqlite/canvas-node.js`（改）

- `listNodes(dbConn, docId)`：支持按 `doc_id` 过滤并返回 `parentId / orderIndex / docId`；不传 `docId` 时保持原行为（兼容测试）。
- `createNode(dbConn, opts)`：新增 `docId / parentId / orderIndex`（缺省 `docId=默认文档`、`parentId=null`、`orderIndex=` 同 doc 最大值+1）。
- `updateNode`：不变（`text/title`）。
- **新增 `saveStructure(dbConn, docId, entries)`**：`BEGIN` 事务内批量 `UPDATE canvas_node SET parent_id=?, order_index=?`，只写传进来的行，先做**环检测**（父链回溯，非法则整体拒绝并返回 `{success:false}`），返回 `{success,saved}`。→ 这是大纲"每次缩进/移动只发一次 IPC"的性能关键。
- `deleteNode`：改为**连带删除子树**（事务内递归收集子孙 + 清理 `canvas_layout/edge`），返回 `{deleted, subtree}` 供 UI 提示"将同时删除 N 个子节点"。

#### 4) `electron/main.js`（改，仅新增 handler，不改现有语义）

- `local-index:canvas:list-docs|create-doc|rename-doc|delete-doc`（最后一个文档禁止删除，返回 `{success:false,message}`）
- `local-index:canvas:state`（入参 `{docId}`）→ `{success, doc, nodes:[{id,kind,text,title,parentId,orderIndex,x,y}], edges, groups}`：nodes 由 `canvasNode.listNodes(docId)` + `canvasLayout.positions()`（JOIN 语义在 SQL 里做或 JS 合并）拼装；**页内不再需要 `graph()` + filter，也不再需要单独的 `list-groups` 调用**（一次拿全，减少 IPC 往返）。
- `local-index:canvas:update-structure`（入参 `{docId, entries}`）→ 调 `saveStructure`，成功才 `schedulePush()` 一次。
- 现有 `canvas:create-node / delete-node` 透传新字段；所有写操作保持"一写一次防抖 push"的既有节奏。

#### 5) `electron/preload.js`（改）

`localIndex` 下新增：`listCanvasDocs / createCanvasDoc / renameCanvasDoc / deleteCanvasDoc / canvasState({docId}) / saveCanvasStructure({docId,entries})`，`createCanvasNode` 注释补 `docId/parentId/orderIndex`（与文件既有 JSDoc 风格一致）。

#### 6) `electron/canvas-sync.js`（改，向后兼容是硬要求）

- `SNAPSHOT_VERSION = 2`；`buildSnapshot` 增加 `docs`，`nodes/edges/groups` 带 `docId`（`canvas_state` 所需）。
- `restoreSnapshot`：
  - v2 快照 → 恢复 `canvas_doc` 及各表 `doc_id`；
  - **v1 快照（无 `docs/docId`）→ 全部归入 `doc:default` 后恢复**（保证老用户跨端数据不丢）；
  - `wipe()` 改为清空四表数据但保留 `canvas_doc`（随后按快照重建 + `ensureDefaultDoc`）。
- `updatedAt` 取各表最大值，逻辑不变（`canvas_doc.updated_at` 一并纳入比较）。

#### 7) 后端（仅 1 行）

`CanvasStateService`：`defaultSnapshot()` 与 `readState()` 的 `putIfAbsent` 链各补 `docs → emptyList()`。**其余 Java 零改动**，`/api/canvas` 契约不变（仍只要求 `updatedAt`）。

#### 8) `frontend/canvas.html`（改）

- `nav` 左侧插入：**文档切换器**（当前文档名 + 下拉：切换/新建/重命名/删除/打开文档列表）+ **视图切换三态**（`大纲 / 分栏 / 画布`，默认 `分栏`，状态存 `localStorage.canvas_view_mode_v1`）。
- 新增 `<aside class="outline-panel" id="outlinePanel">`：头部（折叠全部/展开全部 + 导出菜单）+ `#outlineTree` 滚动容器。
- 新增 `<div class="doc-list-mask" id="docListMask">`：文档列表视图（卡片式：标题 + 节点数 + 更新时间，操作：打开/重命名/删除/新建）。
- 新增 `<link rel="stylesheet" href="styles/canvas.css">`（新 UI 样式单独成文件，**不动现有内联 `<style>`**，降低回归风险）。
- 页面内 `<script src="js/canvas-outline.js">`（在 `canvas.js` 之前，暴露 `window.CanvasOutline`）。

#### 9) `frontend/styles/canvas.css`（新建）

- 只写新 UI：`.outline-panel / .outline-row / .outline-caret / .outline-drop-line`、`.doc-switcher`、`.doc-list-*`、`.view-switch`。
- 全部走 `--app-*` 令牌（明暗主题自适应，满足 `scripts/smoke-theme.js` 的令牌检查口径）。

#### 10) `frontend/js/canvas-outline.js`（新建，核心新模块）

职责边界：**只管树模型与大纲 DOM，不碰 SVG 画布**；通过回调与 `canvas.js` 交换数据。

- `init({ getNodes, onContentChange, onStructureChange, onCreate, onDelete, onSelect })`
- 树构建：`parentId` → 森林（`roots`），行内 HTML：`caret`（有子节点才显示）+ 类型图标（note/ref/link/image）+ `contenteditable` 文本行。
- **键盘范式（对齐幕布，行聚焦时生效，均 `preventDefault`）**：

  | 按键 | 行为 |
  |---|---|
  | `Enter` | 在本行后插入同级兄弟并聚焦 |
  | `Tab` | 降级为上一个兄弟的最后一个子节点 |
  | `Shift+Tab` | 升级为父节点的下一个兄弟（首个根节点除外） |
  | `Alt+↑ / Alt+↓` | 与相邻兄弟交换顺序（不动层级） |
  | `Ctrl/Cmd+↑ / ↓` | 折叠 / 展开当前节点 |
  | `Backspace`（空行） | 合并到上一行；若为子节点则先升级 |
  | `Esc` | 退出编辑、取消选中 |
  | `Ctrl/Cmd+B / I` | 加粗 / 斜体（M4，MVP 不做富文本） |

- 折叠：点 caret 切换（折叠状态先内存态，与 `groupCollapsed` 口径一致）；双击行进入编辑，单击选中并联动画布高亮。
- 落库：文本编辑 → `updateCanvasNode`（防抖 300ms）；结构变更 → 本地即时重排 + `saveCanvasStructure`（防抖 300ms，**批量一次**）。
- 性能：**按 `id` 复用 DOM 行的增量渲染**（只改变化的行，禁止每次整树 innerHTML 重建）；`>500` 行时先只渲染已展开分支并在头部提示（虚拟滚动排 M4）。
- 导出：`导出 Markdown`（层级 → 嵌套列表，`- ` 前缀）+ `复制到剪贴板`（`navigator.clipboard` 失败回退临时 textarea）。

#### 11) `frontend/canvas.js`（改）

- 新增状态 `currentDocId / docList / viewMode`；`loadData()` 改为：`canvasSync()` → `canvasState({docId})` → 组装 `allNodes/allEdges/allGroups`（**不再走 `bridge.graph` 取画布卡片**）→ `renderCanvas()`。
- `bridge.graph({})` **保留但用途收窄**：仅用于「引用已有内容节点」选择器的 `refNodes` 候选（懒加载：第一次打开引用弹窗时再取）。
- 与大纲的联动：
  - 文本/标题编辑、删除、新建 → 调用 `CanvasOutline.syncFromCanvas()`（局部更新对应行，不全树重建）；
  - 节点选中 → `CanvasOutline.highlight(id)`，双向高亮。
- 新增「按大纲排版」按钮：`canvas_node.parent_id` → `d3.stratify()`/`d3.hierarchy()` + `d3.tree().nodeSize([120, 260])` → 得到坐标数组 → 一次 `saveLayout` → `renderCanvas()`；无层级（全平铺）时按 `order_index` 竖排，保证幂等可用。
- 导出图片：文件名带文档标题（`<文档标题>-画布.png`）。
- 画布数据规模保护：节点 `>300` 时在 nav 给出提示（增量渲染排 M4）。

### M2 · 一键大纲 ⇄ 画布（完整闭环）

- 排版按钮扩展：`横排（右向树）/ 竖排（下向树）`两种方向（`d3.tree` 的 `nodeSize` 轴序互换即可）。
- 视图切换的"分栏"模式做**联动高亮 + 滚动定位**（大纲行 ↔ 画布卡片双向定位，复用现有 `zoomBehavior.transform` 居中）。
- 画布上"引用卡（ref）"与大纲同源，不再单独维护两套（`ref` 节点即大纲中的一个叶子行）。

### M3 · 多画布文档列表

- `docs` 列表视图：新建 / 打开 / 重命名 / 删除（二次确认，至少保留 1 个）/ 排序（按 `sort_index`）。
- 文档切换器切换即：保存当前 → `canvas:state` 拉新文档 → 双视图重渲染；`canvasSync` 全局快照无需按文档拆（仍是一份快照含全部文档）。

## 五、Assumptions & Decisions（已定，不再另选）

1. **后端零逻辑改动**（仅 `putIfAbsent("docs")`），画布数据仍走 Electron SQLite 为真源 + 后端快照为"文件为真"的既有链路。
2. **`canvas_layout` 不加 `doc_id`**：`node_id` 全局唯一，按文档取坐标用 JOIN，避免冗余与双写不一致。
3. **结构以大纲为准**：画布拖动不改结构；"从连线反推结构"是显式动作且排 M4，避免双源冲突。
4. **默认视图 = 分栏**（左大纲右画布），默认文档「我的画布」，默认节点 `kind='note'`。
5. **折叠状态先内存态**（与现有 `groupCollapsed` 一致），不为它加字段。
6. **不新增主框架视图**：文档列表与大纲都是画布页内部状态，`index.html` / `knowledge-graph.*` 零改动。
7. **DOM id 命名不一致（`graphView/graphFrame` vs `canvas`）本期不动**：改名会牵扯 `index.html` 多处引用，属独立清理项，不进本批。
8. **不搬 GPL 源码**：只复用已 vendored 的 MIT/BSD 件（d3、marked、html2canvas 等）与公开交互约定。
9. **进度实时对齐**：本批实施时新建 `TODO/画布对标幕布（大纲与画布）/03-实施任务.md`、`04-验收清单.md`（按仓库 `TODO/<需求>/0N-*.md` 约定），**每完成一项立即勾选更新**（会话内同时用 todo 列表同步）；收尾按 `feature-points.json` 约定补产品概览数据。
