# L4 埋点管道补齐：编辑器打开/保存/切换 + 标签变更事件

## Context（背景）

按工作台推荐顺序（L4 → L5 → L6 → P0）推进，先做 L4 埋点补齐。计划 §9 L4 原标称"扩展编辑器打开/保存/切换文件、待办创建/完成、标签变更事件"。经代码核实，**待办创建/完成实际已由 TodoController 接入**（todo_created / todo_completed 等），**真正缺失的只剩两块**：

1. **编辑器内容打开/切换/保存**：编辑器打开本地 .md 文件走 IPC（`electronAPI.openFileByPath` / `saveMarkdownFile`），不经后端，故 `content_opened` / `content_edited` 无采集。
2. **标签变更**：前端标签集合变更（剪藏表单/知识编辑/编辑器存剪藏）未单独记 `content_tagged`。

后端 `EventTypes` 枚举已含所需全部事件类型，且已有**通用事件上报接口** `POST /api/clip/event`（body `{type, contentId, metadata}`，metadata 值为字符串；`ContentStateService`…实际为 `UserActionEventRecorder` 白名单过滤未知类型，失败无副作用）。因此本批**后端零改动**，仅在前端补一个轻量上报 helper 并在上述触发点插桩（fire-and-forget，不阻塞业务）。

## 方案

### 1. 新建前端上报 helper
`frontend/js/action-events.js`（IIFE，暴露 `window.CutShelterActionTracker.track(type, contentId, metadata)`）：
- 内部 `fetch('http://127.0.0.1:8081/api/clip/event', {POST, {type, contentId, metadata}})`，`.catch(()=>{})` 静默。
- 对 metadata 的非字符串值统一 `String(...)` 化（后端字段是 `Map<String,String>`）。
- 无防抖/无共享状态，每页面 window 各自一份。

### 2. 编辑器插桩（frontend/js/editor.js）
- **content_opened**：`openFileTreeFile`(L6972) 成功块 `recordRecentFile(...)` 后；`openRecentFile`(L7495) 成功分支 `showToast` 后；`switchToTab`(L608) 函数结束处（覆盖标签切换）。contentId 用 `file.path` / `state.displayPath || state.fileName`。
- **content_edited**：`saveFile`(L1576) 主保存成功分支 `showToast('已保存…')` 后 → `track('content_edited', state.displayPath)`。

### 3. 标签变更插桩（保存成功后才上报，value 用 `JSON.stringify(tags)`）
- editor.js `submitClip`(L4837) 成功块后 → `content_tagged`（contentId=`state.clipId`）。
- knowledge-editor.js `doSaveKnowledge`(L488) PUT/POST 成功分支 L519 后 → `content_tagged`（contentId=`editId || saved.id`）。
- 剪藏表单提交（clip-shared.js，`/add` 成功且返回体含 id 时）→ `content_tagged`。
- 说明：`clip-form.js` 的 `toggleTagInput/addTag/removeTag`(L478-508) 只改内存 `currentTags`、不落库，**不在此时上报**。

### 4. 页面引入（在各目标 html head/底部在既有本地脚本前加一行）
- `frontend/editor.html`（`js/editor.js` 前）
- `frontend/clip.html`（`js/clip-shared.js` 前）
- `frontend/knowledge-editor.html`（`knowledge-*.js` 前）
