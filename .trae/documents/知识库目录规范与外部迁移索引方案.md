# 知识库目录规范与外部迁移索引方案

> 目标：借鉴 Obsidian「迁移目录后重开本地知识库 → 自动重建索引」的机制，让「用户手动复制/迁移进来的 md 知识库文件或目录」能被本软件稳定索引到；同时以设置模块的「存储根目录」为唯一主目录，梳理存储路径分类统一问题，提供只读的目录规范体检 + 面向手动迁移用户的规范建议入口。

## 一、Obsidian 借鉴点分析（结论先行）

| 维度 | Obsidian 的做法 | 本软件现状 | 借鉴落点 |
|---|---|---|---|
| 迁移后重建索引 | 认「vault 根」为唯一边界，重开时对整棵 vault 重扫，文件即真相，索引只是缓存 | 已是「文件为真、库为缓存」模型（[db.js](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/electron/sqlite/db.js#L25-L45)、[indexer.js](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/electron/sqlite/indexer.js#L147-L188)），启动时用签名门控决定是否全量重建 | 已具备，无需重做 |
| 新内容自动纳入 | vault 内任意新增目录/文件即时可见 | **存在盲区**：`startMarkdownWatcher` 的 roots 是启动时一次性快照，新增的**顶层** md 目录不被监听 | **补齐运行期自动发现**（WS1） |
| 索引可手动重建 | 命令面板「Rebuild vault cache」 | 只有 `local-index:rebuild` IPC，前端无入口 | **设置页暴露「重新索引知识库」**（WS1） |
| 目录/命名约定 | 无强约束，纯文件夹 | 无任何约定或体检能力 | **只读目录规范体检 + 建议入口**（WS2/WS3） |

**当前"外部目录被复制进来"的收敛路径**（[index-service.js](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/electron/sqlite/index-service.js#L105-L154)、[index-service.js](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/electron/sqlite/index-service.js#L229-L265)）：

```
外部文件夹复制/移动到 storagePath
  ├─ 已在被监听 root 内 → fs.watch → 800ms 防抖 → rescanMarkdown → 收录（正常）
  ├─ 新增「顶层目录」 ──→ 无人监听 → 需等下次 rescan 或重启（盲区 ✗）
  └─ 重启 ─────────────→ getStorageSignature 变化 → 门控失效 → 全量重建（正常）
```

本次要消灭的就是中间的盲区。

## 二、现状分析（已核实事实）

### 2.1 存储根目录的唯一性链路

```
设置页「存储根目录」(#storagePath)
  → Electron config.json: storagePath      （main.js DEFAULT_CONFIG.storagePath = APP_DIR）
  → generateApplicationYml()               （main.js L762-805，唯一桥接点）
      clip.storage.path            = {ROOT}/clip-storage

      clip.clip-weekly-report.path = {ROOT}/weekly-report
```

关键事实：
- Electron 侧配置为纯 JSON（`{userData}/config/config.json`），后端另有一份 `~/.cut-shelter/config/app-config.json`，二者通过 `save-config` 双向同步（[settings.js](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/frontend/js/settings.js#L638-L708)）。

### 2.3 临时/缓存目录的区分（三处 `tmp`，最易混淆）

存储树里其实并排存在多个"临时"目录，职责与生产者都不同，体检与规范速览里必须分开讲，否则容易把编辑器临时目录误当成可索引知识库：

| 目录 | 完整路径 | 谁创建/使用 | 用途 | 是否被索引 |
|---|---|---|---|---|
| 剪藏侧 tmp | `{ROOT}/clip-storage/tmp` | Java 侧不主动 `mkdir`，仅在 [getSyncDirs()](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/backend/src/main/java/com/example/clip/service/FileStorageService.java#L1243-L1252) 声明为「同步范围」候选（`exists` 可能为 false） | 预留的剪藏临时区，随同步面板展示 | 否（父 `clip-storage` 更上一层即被排除） |
| 编辑器默认目录 | `{ROOT}/tmp` | Electron [getEditorDefaultDirectory()](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/electron/main.js#L3946-L3952) | 编辑器「另存为/导出 md」默认落点（真实用户内容） | **是（本期改后，见 D7 / WS1-1b）** |
| 编辑器缓存 | `{ROOT}/.tmp/editor/cache.json` | Electron [editor-save-cache](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/electron/main.js#L4066-L4084) | 未保存标签页恢复缓存 | 否（`.` 开头，天然被跳） |

要点：
- **`clip-storage/tmp`（在剪藏库内部）与根下的 `tmp`（编辑器默认保存目录）是两个不同层级、不同生产者的目录，不可混为一谈。**
- 三个里只有根下的 `tmp` 需要进搜索（它是用户真实存出的 md）；本期把它从两处排除集移出（WS1-1b）。`clip-storage/tmp` 与 `.tmp` 维持排除——前者属剪藏内部、后者是缓存。
- 体检模块不再把 `tmp` 当"不可索引"提示；对 `tmp`/`.tmp`/`clip-storage/tmp` 这三处**默认识别为合法目录、不误报**（white-list 放行），只在用户自建目录名与 `tmp` 撞名时按 `P06` 提示。

## 四、实施方案

### WS1 — 索引侧：外部迁移目录自动纳入 + 手动重索引

#### 1. [electron/sqlite/index-service.js](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/electron/sqlite/index-service.js)

**改 `startMarkdownWatcher(storagePath, onDelta)`**（现 L229-265）：
- 维护 `attached: Map<root, watcher>`，改为**增量挂载**而非启动快照：
  - `attach()`：`scanner.discoverMarkdownRoots(storagePath)` → 过滤存在的目录 → 对未挂载的 root 新建 `fs.watch(root, {recursive:true})`（失败降级非递归）；对已消失的 root 关闭并移除。
  - 首次进入调用一次 `attach()`。
- **新增顶层监听**：`fs.watch(storagePath)`（非递归）→ 回调里先 `attach()` 再走 800ms 防抖的 `rescanMarkdown`。这一条即消灭"新增顶层目录"盲区。
- **新增轮询兜底**：`setInterval(attach, 60000)`（对齐 Java [VaultWatchService](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/backend/src/main/java/com/example/clip/service/wiki/VaultWatchService.java#L45-L58) 的 60s 轮询约定），覆盖网络盘/平台 watch 失效场景；仅 `readdirSync` 顶层，成本可忽略。定时器 `unref()`。
- 返回值扩展为 `{ started, roots, refresh, stop }`，`refresh()` 即 `attach()`，`stop()` 需同时关闭 root 监听、顶层监听与轮询定时器。

**新增导出 `reindexMarkdown(storagePath)`**：
- 语义 = 对 md 库做一次"全量比对式重扫 + prune"（直接复用 `indexMarkdown` + `rebuildFts`），返回 `{added, removed, count}`。供手动按钮使用，比 `rebuild()` 轻（不重扫 clip/实体）。

**新增导出 `reindexAll(storagePath)`**：
- 先处理库绑定：`db.getBoundPath() !== storagePath` 时 `db.closeFast()`（见 WS1-3），再 `initLocalIndex(storagePath, {force:true})`。返回全量重建结果。供"重新索引知识库"按钮。

| `P04_INDEXED_ROOT_SHADOWED` | 顶层含 .md 的目录名命中 `MD_EXCLUDED_DIR_NAMES`（如 `docs`/`test`/`build`） | 该目录递归存在 `.md` | warn | `rename`（改为未被排除的语义名） |
| `P05_DEPTH_EXCEEDED` | md 根内目录深度 > `MAX_DEPTH`(=3) | 递归深度超限 | info | `move`（上提层级） |
| `P06_DIR_NAME_STYLE` | 目录名含空格/全角/`#%&{}`/首尾点/长度 > 40/全大写 | 逐段匹配 | info | `rename` → kebab-case 建议名 |

| `P08_EMPTY_ROOT` | 顶层 md 根目录下无任何 .md | 递归计数为 0 | info | `trash` 或忽略 |
| `P09_CLIP_MD_MIRROR` | `clip-organized/clips/` 下存在与已索引 clip 同名的导出 md | 目录存在且有 .md | info | 提示"搜索会出现同内容双命中"，建议下期纳入排除 |
| `P10_HIDDEN_LEFTBACK` | 内容根下存在 `.obsidian` / `.index` / `.tmp` 之外的自定义 `.xxx` 目录 | 一级隐藏目录白名单外 | info | 提示（仅说明） |

- 新增 `TMP_DIR_NAMES = ['tmp', '.tmp']` 白名单（配合 `clip-storage/tmp` 的段级识别）：体检时**不把这三处合法临时目录误报**为「命名不合规 / 空目录」，仅当用户自建一级目录名与 `tmp`/`.tmp` 撞名时按 `P06` 提示改名（见 2.3）。
- `MAX_DEPTH`、`NAME_LENGTH_LIMIT`、`DUP_HASH_MAX_BYTES`、`CANONICAL_DIRS` 以模块级常量导出，便于测试与后续调整。
- **严格只读**：只调用 `readdirSync`/`statSync`/`createReadStream`，模块内不出现任何 `writeFile`/`mkdir`/`rename`/`unlink`。在文件头注释中明确声明该约束。
