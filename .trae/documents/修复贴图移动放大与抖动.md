# 修复截图工具「贴图」移动时渐渐放大与强烈抖动

## 一、现状分析

用户报告：截图工具的 **贴图（F2 粘贴的置顶图片窗口）** 在 **拖动移动** 时，图片会 **渐渐放大** 且 **抖动的厉害**，体验对标 Snipaste。

相关文件（已确认现状，打包版 app.asar 时间戳晚于源文件，即用户运行的就是当前源码，bug 仍存在）：

- 渲染层：`electron/screenshot/paste-window.html`（贴图窗口，含全部拖动/缩放逻辑）
- 主进程：`electron/screenshot/screenshot-service.js`（`paste:move-to` / `paste:zoom-at` IPC 处理器）

### 根因定位（两处真实 bug）

1. **拖动抖动（主因）**：`paste-window.html` 的 `pointermove` 用 **窗口相对坐标 `e.clientX`** 计算拖动目标：
   ```js
   dragStartWin  = { x: window.screenX, y: window.screenY };  // 窗口绝对位置
   dragStartCursor = { x: e.clientX, y: e.clientY };          // 窗口相对坐标 ← 错误
   targetPos = dragStartWin + (e.clientX - dragStartCursor);  // ← 混用坐标系
   ```
   `e.clientX` 是相对窗口的，而窗口本身在被拖动（`setPosition` 移动），因此 `e.clientX - dragStartCursor` 并不等于光标的屏幕位移，而是 **光标屏幕位移 − 窗口已累计位移**。消息公式：
   ```
   targetPos = Win0 + cursorScreenMove − accumulatedWindowMove
   ```
   正确应为 `Win0 + cursorScreenMove`。`− accumulatedWindowMove` 形成 **负反馈**：窗口每走一帧就又被拉回一帧 → 窗口以「移动−停顿−移动−停顿」的节奏抖动，且始终落后光标约一帧。这完全对应「抖动的厉害」。

2. **拖动时渐渐放大（次因）**：窗口用 `setPointerCapture` 捕获指针，而 `lostpointercapture` 也被当作结束拖动的信号。在 Windows 上，当 `setPosition` 移动无边框窗口时，Chromium 可能触发 `lostpointercapture` → `endDrag()` 把 `moving` 置 false。于是：
   - 拖动中途 `moving` 变 false，窗口不再跟随光标；
   - 滚轮缩放不再被 `if (moving) return` 拦截 → 用户微微滚轮/触控板即触发 `paste:zoom-at` → 图片 **渐渐放大**。

> 附带隐患：`screenshot-service.js` 对贴图窗口设置了 `setAspectRatio(iw/ih)`，而 `paste:zoom-at` 用 `setBounds` 同时给宽高，带宽高比锁定时 setBounds 可能被系统按比例微调，导致渲染层 `scale` 与实际窗口尺寸逐步漂移（多滚几次尺寸越长越大）。

## 二、目标行为（对标 Snipaste）

- 拖动贴图：**平滑跟手、无抖动、无滞后反弹**，拖动过程中图片尺寸恒定不变。
- 滚轮缩放：以光标为锚点、步进、范围 0.1–4；**拖动中绝不触发缩放**。
- Ctrl+滚轮 调透明度、双击关闭、右键菜单、拖动不放大——保持现有能力不变。

## 三、修改方案

### 文件 1：`electron/screenshot/paste-window.html`（渲染层，核心修复）

**1. 重写拖动逻辑（消除抖动 + 消除拖动中放大）：**

- `pointerdown` 时记录 **绝对屏幕坐标** 作为光标起点：
  ```js
  dragStartCursor = { x: e.screenX, y: e.screenY };  // 绝对坐标
  dragStartWin    = { x: window.screenX, y: window.screenY }; // 绝对坐标
  ```
- `pointermove` 用绝对坐标差：
  ```js
  const dx = e.screenX - dragStartCursor.x;
  const dy = e.screenY - dragStartCursor.y;
  targetPos = { x: Math.round(dragStartWin.x + dx), y: Math.round(dragStartWin.y + dy) };
  ```
  这样无论窗口被移到哪，`e.screenX − dragStartCursor.x` 恒等于光标的真实屏幕位移，无反馈项，窗口严格跟手，消除抖动。
- **拖动状态机更健壮**（不再因 `lostpointercapture` 误结束）：
  - 保留 `setPointerCapture` 保证光标移出窗口边缘仍能收到 pointermove；
  - **移除** `lostpointercapture` 作为结束拖动的事件；改为在 `pointermove` 内用 `!(e.buttons & 1)` 检测按键已松开 → `endDrag()`；
  - `pointerup` / `pointercancel` / `window blur` → `endDrag()`；
  - 若 `lostpointercapture` 触发但按键仍按住，则重新 `wrap.setPointerCapture(e.pointerId)` 续抓指针。
- `endDrag()` 结束时**冲刷最后一帧位置**（`if (targetPos) invoke('paste:move-to', targetPos)`），保证停点精确。
- 保留 RAF 节流（`rafMove`），目标为绝对坐标，天然收敛。

**2. 滚轮缩放守卫加强：**

- 保留 `if (moving) return;`，并追加 `if (e.buttons & 1) return;` 双保险（即使 moving 状态异常，按住左键时也绝不缩放）。
- 其余缩放逻辑（`wheelAccum` 累积、`WHEEL_STEP=100`、`zoomTo` 锚定）保持不变。

### 文件 2：`electron/screenshot/screenshot-service.js`（主进程，消除尺寸漂移）

- **移除** 贴图窗口的 `win.setAspectRatio(iw / ih);`（第 346 行）。尺寸完全由 `paste:zoom-at` 的 `setBounds` 控制，避免比例锁导致宽高被系统微调、渲染层 `scale` 与实际尺寸漂移。
- `paste:move-to` / `paste:zoom-at` 处理逻辑本身正确，**保持不变**（渲染层不再发错误目标后即无竞态；缩放锚定公式 `nx = wx + anchorX*(1-r)` 正确）。

## 四、验收与部署

### 验证步骤

1. 语法检查：`node --check electron/screenshot/paste-window.html` 不适用于 HTML，改为对行内 `<script>` 抽检或直接 `node --check` 提取出的脚本；主进程 `node --check electron/screenshot/screenshot-service.js`。
2. 手动验证（F2 贴一张图）：
   - 快速来回拖动 → 图片严格跟手、无抖动、**尺寸恒定**；
   - 拖动中滚轮 → 图片不缩放；
   - 松开后滚轮 → 以光标为锚点正常缩放，多次缩放尺寸不漂移；
   - Ctrl+滚轮调透明度、双击关闭、右键菜单均正常。
3. 由于用户运行的是打包版，需**重新打包**让修改生效：
   - 快速重建解包目录：`npx electron-builder --win --dir`（生成/刷新 `dist-electron/win-unpacked`，含新 `app.asar`）；若需完整安装包再跑 `npm run build:win`。
   - 提醒：贴图窗口为全局快捷键 F2 触发，改完需重启应用（或重启后按 F2）验证。

## 五、假设与决策

- 问题范围限定在 **贴图窗口（paste-window）** 的拖动/缩放，截图选区覆盖层不在本次范围。
- 保留现有 Snipaste 风格交互（锚定缩放、透明度、双击关闭、右键菜单、RAF 节流），只做「消除放大与抖动」的稳健化修复，不过度重构。
- 为避免 setBounds 漂移，移除 `setAspectRatio`（该锁对尺寸完全自控、`resizable:false` 的贴图窗口是冗余的）。

## 六、后续修复记录

### 6.1 拖动仍变大（已实锤 OS 层）
日志（用户提供）显示 `paste external resize: 451x307 -> 505x366` 共 35 次，`zoomAt=never`，无任何 `[paste-zoom]`/`zoom blocked`——**滚轮与缩放代码全程未执行**。根因是 Windows 对 `frameless + resizable:false` 窗口调用 `setPosition` 纯移动时，系统每帧微调窗口矩形，误差单向累积（每帧 +1~2px）。
修复（`screenshot-service.js`）：`paste:move-to` 弃用 `setPosition`，改用 `setBounds({x,y,width,height})` 显式钉住 `__lockedSize`；`paste:zoom-at` 缩放后同步更新 `__lockedSize`；窗口创建初始化 `__lockedSize`。任何来源的尺寸漂移下一帧即被纠正。

### 6.2 贴图内容应为「截图选区」而非全屏（对标 Snipaste）
原数据流：`captureScreen` 把全屏存 `lastCapture`，`handleConfirm` 裁剪出选区 `cropped` 后不回写缓存，`pasteFromClipboard` 兜底用 `lastCapture`（全屏）→ F3 贴全屏。
修复（`screenshot-service.js`）：
- 新增 `lastSnip`（最近截图选区缓存）；
- `handleConfirm` 统一 `lastSnip = cropped`（任何动作：复制/保存/OCR/贴图）；
- `pasteFromClipboard` 兜底顺序：剪贴板图 → `lastSnip`（选区）→ `lastCapture`（极端兜底）；
- `screenshot:copy-last`（贴图右键复制）改为 `lastSnip || lastCapture`，与贴图语义一致。

### 6.3 对标 Snipaste：剪贴板内容贴图 + 真透明 + 选区标注
- **文本贴图（F3/Ctrl+V 贴剪贴板内容）**：`pasteFromClipboard` 用 `clipboard.availableFormats()` 判断剪贴板类型——图片=>`clipboard.readImage()`；文本=>渲染层 `renderTextToImage` 用 canvas 排成白底黑字 PNG 走图片全链路（缩放/透明度/保存/OCR），并经 `paste:text-ready` 让主进程精确 resize。
- **窗口级真透明**：Ctrl+滚轮从 `wrap.style.opacity`（元素变淡、透出黑底，像"变亮度"）改为主进程 `paste:set-opacity`→`BrowserWindow.setOpacity`，整个窗口半透明，真正透出底下内容。
- **选区标注（方框/箭头/马赛克）**：截图覆盖层新增 `#anno`（已提交）与 `#annoFloat`（绘制预览）两个物理分辨率 canvas，工具栏追加标注按钮与颜色循环点。标注工具激活时在选区内拖拽绘制：方框=`strokeRect`、箭头=`line+三角头`、马赛克=`原图缩小再放大`（像素化）。确认时 `composeAnno` 把背景选区+标注合成 PNG dataURL 交给主进程，`handleConfirm` 用 `nativeImage.createFromDataURL` 替代纯 crop。`resetOverlay` 清空标注以支持窗口复用。

### 6.4 Snipaste 复刻（文字标注 / Ctrl+T 贴图 / 贴图阴影）
- **截图标注文字工具**：工具栏新增「Ｔ 文本」，在选区内拖出矩形（预览框）→ 弹出 `#annoText` 输入框 → 实时预览文字到 `annoFloat` → Enter/失焦提交到 `anno`、Esc 取消。文字 `drawTextLayer` 自动换行并缩放字号填满矩形框（Snipaste 风格），颜色随 `annoColor`。
- **截图后 Ctrl+T 直接贴图**：截图覆盖层 keydown 增加 `Ctrl/Cmd+T → confirm('paste')`，等价于点「📌 贴图」。
- **贴图外圈阴影**：`#wrap` 加常驻黑色 `box-shadow`；点贴图 body 加 `selected` 类转蓝色描边阴影（`0 0 0 3px #3f8cff`），失焦自动取消。
