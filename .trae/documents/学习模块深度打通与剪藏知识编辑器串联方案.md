# 学习模块深度打通：与剪藏、知识、编辑器的串联方案

## 摘要

学习计划模块目前是**孤岛**：仅做学习计划的 CRUD、阶段进度、掌握度与导出，与剪藏、知识、编辑器**无任何字段级关联**，不参与「剪藏 → 知识 → 图谱」的数据流。本方案借鉴 Obsidian 的双链/反链、Notion 的数据库关联思路，以**阶段级关联**为核心，把学习计划接入既有数据流：

1. **学习计划 ↔ 知识/剪藏**：阶段可关联知识条目与剪藏（`Phase.linkedKnowledgeIds` / `Phase.sourceClipIds`），形成「学习阶段 → 学习素材」的引用关系。
2. **反链**：知识详情页、剪藏详情页展示「被哪些学习阶段引用」，点击跳转学习计划。
3. **图谱**：学习计划节点 + `plan_links` 边纳入知识图谱（借鉴 Obsidian 全库图谱）。
4. **编辑器**：阶段说明 `detailMarkdown` 一键在编辑器新标签打开编辑（复用 `openTextData` 机制）。

范围已确认：**核心打通**（不含学习日志/打卡），编辑器联动为**编辑器中打开阶段说明**。

## 一、现状分析（调研结论）

### 1.1 学习模块现状
- **模型** `LearningPlan`（`backend/.../model/LearningPlan.java`）：`id/title/level/goal/hoursPerWeek/totalWeeks/phases/mermaidDiagram/category/tags/mastery/nextReviewAt/reviewCount/builtin`。`Phase` 含 `phaseNumber/title/goal/estimatedWeeks/detailMarkdown/videos/knowledgeQuiz/practiceTasks/progress/completed`。
- **接口** `LearningPlanController`（`/api/learning-plan`）：CRUD、`PUT /{id}/phase/{phaseNum}`（进度/完成）、`PUT /{id}/mastery`、`POST /{id}/review`（间隔复习）、`batch-delete`、`open-folder`、`export-pdf`。
- **前端** `frontend/learning-plan.html`（单文件 1636 行）：列表 + 详情（Mermaid 路线图 + 阶段卡片 `renderPhaseCard` L1310）+ 新建弹窗 + 批量管理。阶段卡片含推荐资源 `renderResources`、知识作业 `renderQuizzes`、实战任务 `renderTasks`。
- **能力**：AI 生成分阶段路线、Exa 真实资源搜索（降级 AI）、阶段进度、掌握度+间隔复习、内置计划播种、Markdown/PDF 导出。

### 1.2 与其它模块的关联现状
- **与剪藏/知识**：仅通过 `ContentIndexService` 元数据索引（`ContentRef` type=`learning-plan`，`ContentRefMapper.fromLearningPlan` L68）与 workspace 过滤产生**元数据级**关联，**无字段级引用、无互相跳转、无联动**。
- **与编辑器**：无直接联动，仅 Markdown 导出复用编辑器默认保存目录。
- **数据流**：学习模块不参与「剪藏 → 知识 → 图谱」数据流。

### 1.3 既有可复用机制（关键）
- **图谱**：`GraphService`（`backend/.../service/GraphService.java`）已支持 `derived_from`（clip→knowledge）与 `linked_to`（knowledge→knowledge）两类边，`recordKnowledgeRelations` 幂等写入、`syncRelations` 全量重建、`getGraph` 组装节点+边。学习计划节点**已出现在图谱**（经 content-index），但 `summary/linkedCount/sourceCount` 均为空。
- **反链/双链**：知识已支持 `[[wikilink]]` 双向链接（`manageBidirectionalLinks`）；`GET /api/knowledge/by-clip/{clipId}` 已实现剪藏反查知识。
- **编辑器打开机制**：编辑器监听 `{type:'openTextData'}` → `openTextDataInNewTab(text,title)` 新标签打开（`frontend/js/editor.js` L3184）；`index.html` 有 `sendToEditor()` 转发通道。
- **模块导航**：`index.html` 统一监听子页面 postMessage 并 `renderView` 切换 + 设置 iframe `src`（如 `navigateKnowledge` L732-737）；学习计划 iframe 为 `learningPlanFrame`，路由 `/learning-plan`。

### 1.4 调研中发现的问题（记录，不在本次范围）
- **两套知识模型断层**：图谱**节点**来自 content-index.json（基于旧 `KnowledgeEntry`），**边**来自 relation-index.json（基于主模型 `Knowledge`），两套 ID 体系不保证一致，可能导致图谱知识节点与关系边对不上。本次不处理，仅记录；建议后续单独梳理。

## 二、设计思路：借鉴 Obsidian / Notion

| 借鉴点 | 落地设计 |
|--------|---------|
| Obsidian 双链（`[[知识]]`） | 学习阶段以 `linkedKnowledgeIds` 引用知识，形成「阶段 → 知识」引用 |
| Obsidian 反链面板（Backlinks） | 知识详情/剪藏详情新增「被学习计划引用」区块，展示引用它的阶段并跳转 |
| Obsidian 全库图谱 | 学习计划作为新节点类型（绿色三角）+ `plan_links` 边进入知识图谱 |
| Notion 数据库关联 | 阶段卡片内嵌「关联知识 / 关联剪藏」区块，弹窗多选关联（Notion 式 picker） |
| Obsidian 编辑器联动 | 阶段说明一键在编辑器新标签打开编辑，编辑结果可回存 |

## 三、数据模型变更

### `backend/src/main/java/com/example/clip/model/LearningPlan.java`
在 `Phase` 内部类新增两个字段（阶段级关联，作为**唯一真源**）：

```java
private List<Long> linkedKnowledgeIds = new ArrayList<>();  // 关联的知识条目 ID
private List<Long> sourceClipIds = new ArrayList<>();       // 关联的剪藏 ID
```

> 决策：关联放在 **Phase 级**而非 Plan 级，因为反链要精确到「哪个阶段引用了这条知识/剪藏」；图谱边由 `GraphService` 从各阶段聚合出 plan 级 `plan_links` 边。

## 四、后端变更

### 4.1 `LearningPlanService.java`（新增方法）
- `updatePhaseLinks(Long planId, int phaseNum, List<Long> linkedKnowledgeIds, List<Long> sourceClipIds)`：定位阶段 → 覆盖两字段 → 保存 → 调 `graphService.recordPlanRelations(plan)`。
- `getPlansByKnowledge(Long knowledgeId)`：遍历所有计划，返回 `[{planId, planTitle, phases:[{phaseNumber, phaseTitle}]}]`（过滤 `phase.linkedKnowledgeIds` 含该知识）。
- `getPlansByClip(Long clipId)`：同上，过滤 `phase.sourceClipIds` 含该剪藏。
- 在 `createPlan` / 更新流程末尾调用 `graphService.recordPlanRelations(plan)`（幂等）。

### 4.2 `LearningPlanController.java`（新增端点）
| 方法 | 路径 | 说明 |
|------|------|------|
| PUT | `/api/learning-plan/{id}/phase/{phaseNum}/links` | body `{linkedKnowledgeIds:[], sourceClipIds:[]}`，更新阶段关联并写图谱 |
| GET | `/api/learning-plan/by-knowledge/{knowledgeId}` | 反查引用该知识的学习阶段 |
| GET | `/api/learning-plan/by-clip/{clipId}` | 反查引用该剪藏的学习阶段 |

### 4.3 `GraphService.java`（新增/修改）
- 新增 `recordPlanRelations(LearningPlan plan)`：幂等移除 `learning-plan:{id}` 的所有旧边，再遍历各阶段写入 `plan_links` 边：
  - `learning-plan:{id} --plan_links--> knowledge:{kid}`
  - `learning-plan:{id} --plan_links--> clip:{cid}`
  - relationType=`plan_links`，source=`learning_plan_link`
- 新增 `removePlanRelations(Long planId)`：删除知识时清理。
- 修改 `syncRelations()`：在遍历知识后，追加遍历 `getAllLearningPlans()` 调 `recordPlanRelations`。
- 修改 `getGraph()`：当 `ref.type()=="learning-plan"` 时，加载计划，填充 `summary`（=goal 或 title）、`linkedCount`（各阶段 linkedKnowledgeIds 去重数）、`sourceCount`（各阶段 sourceClipIds 去重数）。
- 修改 `deriveRelationsFromKnowledge` 兜底逻辑：同样把学习计划关系纳入兜底派生（或保持现状，仅靠 sync 写入）。

### 4.4 涉及文件清单（后端）
- `backend/src/main/java/com/example/clip/model/LearningPlan.java`（改）
- `backend/src/main/java/com/example/clip/service/LearningPlanService.java`（改）
- `backend/src/main/java/com/example/clip/controller/LearningPlanController.java`（改）

## 五、前端变更

- **阶段卡片**（`renderPhaseCard` L1310）新增两个区块：

## 六、数据流转图（打通后）

```
[学习计划 LearningPlan]
   Phase.linkedKnowledgeIds ──plan_links──> knowledge:{kid}   （阶段→知识）
   Phase.sourceClipIds     ──plan_links──> clip:{cid}         （阶段→剪藏）
        │
        ├─ 反链：knowledge-detail / clip 展示「被学习计划 X · 阶段 N 引用」→ 跳转学习计划
        ├─ 图谱：learning-plan 节点(绿三角) + plan_links 边(绿线) 与剪藏/知识节点同图
        └─ 编辑器：阶段说明 detailMarkdown → openTextData → 编辑器新标签编辑
```

---

## 七、假设与决策

1. **阶段级关联为唯一真源**：`Phase.linkedKnowledgeIds/sourceClipIds` 存于 LearningPlan JSON；图谱 `plan_links` 边是其可查询投影（与 `derived_from`/`linked_to` 同模式）。
2. **`plan_links` 为新增关系类型**：不混用 `derived_from`（语义是「知识来源于剪藏」），保持关系语义清晰。
3. **反链 API 用遍历实现**：数据量小（学习计划数量有限），直接遍历 `getAllLearningPlans()` 过滤，不引入新索引。
4. **编辑器联动为单向打开**：阶段说明在编辑器新标签打开编辑，编辑结果由用户手动「存入剪藏」或复制回学习计划，不做双向同步（符合「核心打通」范围）。
5. **图谱节点已存在**：学习计划节点经 `ContentRefMapper.fromLearningPlan` 已进入 content-index，无需改索引层，仅增强 `getGraph` 的字段填充。
6. **两套知识模型断层**：记录为已知问题，本次不处理。
