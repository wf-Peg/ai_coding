# 浏览器插件保存剪藏报错修复方案

## 摘要
后端 `POST /api/clip/add`（type=store-only）在保存剪藏时抛出 `UnsupportedOperationException`，
导致浏览器插件剪藏失败。根因有二，均在 `FileStorageService`：
1. 单对象（旧格式）剪藏文件 `hobby\260719.json` 被 `readClipArrayFromFile()` 以
   `List.of(...)`（不可变列表）返回，`saveClip → removeClipFromAllFiles → removeIf` 对不可变
   集合调用导致崩溃。
2. `product-dev\records.json` 是 Dispatch 记录文件（id 为 UUID 字符串），被 `getAllJsonFiles()`
   误当作剪藏数据扫描，报 `Long` 反序列化警告并污染剪藏列表。
下游的 `NullPointerException`（`addClip` 第 139 行）只是 `saveClip` 返回 null 的连带症状。

## 当前状态分析
- [FileStorageService.java](file:///f:/30_Projects%20(行动项目)/31_Work%20(主要工作)/ai_coding/backend/src/main/java/com/example/clip/service/FileStorageService.java)
  - `readClipArrayFromFile()` 第 392 行 `return List.of(objectMapper.treeToValue(root, ClipContent.class));`
    返回 `List.of`（不可变），是所有外层 `removeIf` 崩溃的源头。
  - `removeClipFromAllFiles()`（503–518）、`replaceClip()`（629）、`deleteTodoFromAllFiles()` 等
    均对 `readClipArrayFromFile \ readTodoArrayFromFile` 结果调用 `removeIf`，不可变列表必崩。
  - `getAllJsonFiles()` 依赖 `EXCLUDED_DIR_NAMES`/`EXCLUDED_FILE_NAMES` 排除非剪藏数据；
    目前未排除 `records.json`，因此 `product-dev\records.json`（DispatchRecord，UUID id）被混入剪藏数据源。
- [ClipController.java](file:///f:/30_Projects%20(行动项目)/31_Work%20(主要工作)/ai_coding/backend/src/main/java/com/example/clip/controller/ClipController.java)
  第 138–139 行直接对 `clipService.saveClip(request)` 结果做 `clip.getId()`，未判空 → NPE。
- [ClipContent.java](file:///f:/30_Projects%20(行动项目)/31_Work%20(主要工作)/ai_coding/backend/src/main/java/com/example/clip/model/ClipContent.java)
  `id` 为 `Long`，与 DispatchRecord 的 UUID `id` 不同模型，本就是两类数据。
- 浏览器插件 `clip.js` 调用即为 `/api/clip/add`，payload 为 `type=store-only, useAiTags=false`，
  与现接口一致，无需改插件；本次是后端存储扫描与数据格式未对齐。

## 变更方案

### 1) 修复不可变列表崩溃（主修复）
**文件**: `backend/src/main/java/com/example/clip/service/FileStorageService.java`
**位置**: `readClipArrayFromFile()` 第 390–392 行（object 分支）
**改法**: 不再用 `List.of(...)`，改用可变 `ArrayList`，保证外层 `removeIf` 可用：
```java
// 单对象（旧格式）剪藏：返回可变列表，避免 removeIf 对不可变集合抛 UnsupportedOperationException
List<ClipContent> single = new ArrayList<>();
single.add(objectMapper.treeToValue(root, ClipContent.class));
return single;
```
说明：该文件其余分支（array/`clips` node）已返回 `new ArrayList<>()`（可变），仅此分支需修正。

### 2) 存储扫描对齐：排除非剪藏文件
**文件**: 同上，`EXCLUDED_FILE_NAMES`（第 319–321 行）
**改法**: 追加 `records.json`、`feature-points.json`（product-dev 归档与 Dispatch 记录，属独立数据类型，
id 为 UUID 字符串，不应按剪藏扫描，否则反复出现 `Long` 反序列化警告并污染剪藏列表/ID 分配）：
```java
private static final Set<String> EXCLUDED_FILE_NAMES = Set.of(
        "model-config.json", "app-config.json", "vaults.json", "vault-meta.json",
        "records.json",                       // 产品需求/开发记录（DispatchRecord，UUID id）
        "feature-points.json"                 // 功能点归档（独立数据类型）
);
```
说明：`product-dev` 仍是合法分类目录，其下日期文件（如 `260907.json`）继续作剪藏正常扫描；仅按文件名排除
这两类非剪藏归档。

### 3) 控制器判空防御（连带 NPE 修复）
**文件**: `backend/src/main/java/com/example/clip/controller/ClipController.java` 第 138 行
**改法**: `addClip` 中 `saveClip` 返回 null 时返回 500，避免 `clip.getId()` NPE：
```java
ClipContent clip = clipService.saveClip(request);
if (clip == null) {
    log.error("[API] /add 保存剪藏失败, type={}", request.getType());
    return ResponseEntity.internalServerError().body(Map.of("status", "error", "message", "剪藏保存失败"));
}
```
说明：防御性兜底，正常运行不再触发（#1 修复后 saveClip 正常返回），但提升健壮性。

## 假设与决策
- 假设: 浏览器插件 payload 无需改动，报错纯由后端存储逻辑引起（日志已证明插件请求正确到达）。
- 决策: 采用「最小改动」——不改动单对象数据文件本身，仅将读取结果改为可变列表，兼容旧格式数据。
- 决策: 采用文件名级排除 `records.json`/`feature-points.json`，而非排除整个 `product-dev` 目录，
  保留该分类下真实剪藏的正常存取。
