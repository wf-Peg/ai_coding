# 收件箱模块优化对齐方案

## Summary（结论先行）

本次对齐收件箱/剪藏模块的 3 个体验问题，共 4 个根因、6 处改动：

| # | 用户反馈 | 根因 | 改动 |
|---|---|---|---|
| 1 | 图片类型剪藏在编辑器打开只显示「剪贴板图片」 | 剪贴板图片剪藏的 `content` 只有文字 `剪贴板图片`，图片只存在 `imagePaths`；编辑器把 `bodyContent \|\| content` 当纯文本塞进 Ace，天然看不到图 | 改动 1（editor.js 补图片 Markdown 引用 + 自动进预览）+ 改动 2（列表原文去重） |
| 2 | more-actions「OCR提取文字」提示「操作正在保存 OCR 结果…」，等很久才反应（其实卡在 AI 总结），要和「快速AI整理」区分 | `ocrClipImage` 的顺序是「OCR → AI 总结（大模型，慢）→ 才 showLoading(保存)」；OCR 与 AI 整理在视觉/流程上完全无法区分 | 改动 5（OCR 结果弹窗，OCR 纯本地 + AI 总结独立触发）+ 改动 6（保存后留在收件箱） |
| 3 | 快速记录选「插图/OCR」后点「OCR 提取文字」，只有提示没有结果展示/反馈，只有添加到剪藏后才能看到结果 | `runImageOcr` 把识别结果直接 append 进 `#content`，没有任何结果区/阶段反馈；用户视线在图片工具栏，感知不到 | 改动 4（表单 OCR 结果面板） |
| 3' | 「在编辑器打开原文」没有用新编辑器窗口打开（Ctrl+T 后是空窗口） | more-action `edit-in-editor` 发的是 `openClipInEditor` → `loadClip`（覆盖当前标签），不是 `openClipInNewTab` → `loadClipInNewTab`（新标签） | 改动 3（clip-list.js 改发 `openClipInNewTab`） |

**关键决策（已与用户确认）**
- 图片剪藏在编辑器：**自动补 `![图片](media/...)` 引用 + 自动进 Markdown 预览**（用户可 Ctrl+Shift+M 回源码）。
- OCR：**纯本地识别，AI 总结独立触发**。流程为「OCR 识别 → 结果展示 → （可选）点「AI 总结」→ 结果里加上总结 → 用户确认「应用/保存到原文」」。**不点总结则直接以 OCR 结果作为原文**。
- 「在编辑器打开原文」：**新标签打开**（不覆盖当前编辑内容）。
- 对已保存剪藏做 OCR 后：**留在收件箱**（不自动标记「已整理」）。

## Proposed Changes（改动方案）

### 改动 1：编辑器打开图片剪藏时展示图片 — `frontend/js/editor.js`

**做什么**：打开剪藏时，若该剪藏有图片，则把 `imagePaths` 里未被正文引用的路径补成 Markdown 图片引用写入正文，并自动进入 Markdown 预览态。

**怎么改**：
1. 在 `loadClip`/`loadClipInNewTab` 附近新增两个纯函数（IIFE 顶层，紧邻 `loadClip` 之前）：
   ```js
   // 正文中已有的 media 图片相对路径
   function collectContentMediaRefs(content) {
     const refs = [];
     const re = /!\[[^\]]*\]\((media\/\d{4}\/[\w.-]+\.\w{1,10})\)/g;
     let m;
     while ((m = re.exec(content || ''))) { if (refs.indexOf(m[1]) < 0) refs.push(m[1]); }
     return refs;
   }
   // 把 imagePaths 中未被正文引用的图片补成 Markdown 引用（前置，保持「图在前、文字在后」）
   function ensureClipImageRefs(content, clip) {
     const paths = (clip && Array.isArray(clip.imagePaths)) ? clip.imagePaths.filter(Boolean) : [];
     if (!paths.length) return content || '';
     const existing = collectContentMediaRefs(content);
     const missing = paths.filter(function (p) { return existing.indexOf(p) < 0; });
     if (!missing.length) return content || '';
     const refs = missing.map(function (p) { return '![图片](' + p + ')'; }).join('\n');
     var body = content || '';
     return body ? refs + '\n\n' + body : refs;
   }
   function clipHasImages(clip) {
     return !!(clip && Array.isArray(clip.imagePaths) && clip.imagePaths.length)
       || /media\/\d{4}\/[\w.-]+\.\w{1,10}/.test((clip && clip.content) || '');
   }
   ```
2. `loadClip`（约 L4912-4925）与 `loadClipInNewTab`（约 L4967-4980）中：
   - 把 `let editorContent = (clip.bodyContent && clip.bodyContent.trim()) ? clip.bodyContent : (clip.content || '');` 之后，补一行
     `editorContent = ensureClipImageRefs(editorContent, clip);`
   - `format` 兜底改为：有图时优先 `'markdown'`，即
     `const format = clip.contentFormat || (clipHasImages(clip) ? 'markdown' : EditorCore.detectLanguage(clip.sourceFileName || clip.title, editorContent));`
3. 打开完成后自动进预览（有图时）：在 `renderTabBar();` 之后（`loadClipInNewTab` 里在 `renderTabBar()` 与 `mainEditor.focus()` 之间）插入
   ```js
   if (clipHasImages(clip) && typeof toggleMarkdownPreview === 'function') {
     setTimeout(function () { toggleMarkdownPreview(true); }, 0);
   }
   ```
   `setTimeout 0` 是必须的：切换标签会退出预览态（见 [editor.js L641](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/frontend/js/editor.js#L641) 附近「切换标签时退出对比和 Markdown 预览模式」），置后执行可保证预览态最终生效。

**为什么**：正文含图片引用后，源码态可见 `![图片](media/...)`，预览态直接看到图片；同时避免编辑器保存时 imagePaths 被 `extractImagePathsFromContent` 清空。

**涉及**：`frontend/js/editor.js`（新增 3 个函数 + 2 处 `editorContent` 处理 + 2 处自动预览）。

### 改动 2：剪藏列表「原文」图片去重 — `frontend/js/clip-list.js`

**做什么**：`buildExtraImagesHtml` 只补「正文里还没引用的图片」，避免改动 1 之后同一张图渲染两遍。

**怎么改**：在 `buildExtraImagesHtml(clip)` 里先算出正文已引用的路径集合，再过滤 `imagePaths`：
```js
const body = clip.bodyContent || clip.content || '';
const already = [];
const re = /media\/\d{4}\/[\w.-]+\.\w{1,10}/g;
let m; while ((m = re.exec(body))) { if (already.indexOf(m[0]) < 0) already.push(m[0]); }
const imgs = clip.imagePaths
  .filter(function (rel) { return rel && already.indexOf(rel) < 0; })
  .map(...)  // 原逻辑不变
```
**为什么**：正文已含引用时，`renderContent` 已渲染图片，补图区应只兜底「正文无引用」的剪藏（剪贴板截图类历史数据）。

**涉及**：`frontend/js/clip-list.js` `buildExtraImagesHtml()`。

### 改动 4：表单/快速记录的 OCR 结果面板 — `frontend/clip.html` + `frontend/styles/clip.css` + `frontend/js/clip-form.js`

**做什么**：`runImageOcr` 不再直接写 `#content`，改为把识别结果显示在图片区内的结果面板；面板提供「AI 总结」（独立触发）与「插入到内容」（确认落正文）。

**怎么改**：

1. `frontend/clip.html`：在 `#image-upload-area` 内、`#image-previews` 之后新增面板（沿用现有类名风格）：
   ```html
   <div id="image-ocr-panel" class="image-ocr-panel" style="display:none;">
       <div class="image-ocr-head">
           <span class="image-ocr-title">OCR 识别结果（本地）</span>
           <span class="image-ocr-count" id="image-ocr-count"></span>
           <button type="button" class="image-ocr-close" id="image-ocr-close-btn" onclick="closeOcrResultPanel()">✕</button>
       </div>
       <textarea id="image-ocr-result" class="image-ocr-result" placeholder="识别结果将显示在此处…"></textarea>
       <div class="image-ocr-status" id="image-ocr-status"></div>
       <div class="image-ocr-actions">
           <button type="button" class="image-ocr-btn" id="image-ocr-summarize-btn" onclick="summarizeOcrResult()" title="调用大模型生成总结（可选，会较慢）">✨ AI 总结</button>
           <button type="button" class="gbtn" id="image-ocr-apply-btn" onclick="applyOcrResultToContent()">✔ 插入到内容</button>
       </div>
   </div>
   ```
   并把 `#image-ocr-btn` 的 `title` 改为「本地识别图片文字（不调用大模型）」以和「快速AI整理」区分。
2. `frontend/styles/clip.css`：新增 `.image-ocr-panel / -head / -title / -count / -result / -status / -actions / -close` 样式，复用 `.image-ocr-btn` 与 CSS 变量（`--surface --border --text-secondary --primary`），支持 `html[data-theme="dark"]`。
3. `frontend/js/clip-form.js`：
   - `runImageOcr()` 改为：取图与守卫（上传中提示「请等待图片上传完成后重试」）逻辑不变；识别阶段按钮 `disabled` + 文案「识别中…」+ `#image-ocr-status` 显示「本地识别中…」；成功后把文字写入 `#image-ocr-result`、更新字数、显示面板并 `#image-ocr-panel.scrollIntoView({block:'nearest'})`，**不写 `#content`**；失败沿用 `recognizeImage` 的提示。
   - 新增 `summarizeOcrResult()`：读 `#image-ocr-result` 文字 → `#image-ocr-status` 显示「正在生成 AI 总结…」+ 按钮 disabled/loading → 调 `requestTextSummary`（`POST /api/clip/text-summary`）→ 成功则把 `\n\n**AI 总结**：<summary>` 追加进 `#image-ocr-result`，失败提示且保留 OCR 原文。
   - 新增 `applyOcrResultToContent()`：`const text = #image-ocr-result.value.trim()`；为空则提示；否则 `#content.value = 现有内容 ? 现有内容 + '\n\n' + text : text`（**追加**，保留上传时已插入的 `![图片](media/...)`），`dispatchEvent(new Event('input'))`，关闭面板并 `showToast('已插入识别结果')`。
   - 新增 `closeOcrResultPanel()`：隐藏面板并清空 `#image-ocr-result`/`#image-ocr-status`（不改 `#content`）。
   - `clearForm()` 追加 `closeOcrResultPanel()` 调用，避免残留结果串到下一条。

**为什么**：让 OCR 结果「当场可见、可编辑、可确认」，AI 总结变成用户主动触发的第二步；OCR 与「快速AI整理」在按钮文案/流程上明确分层。

**涉及**：`frontend/clip.html`、`frontend/styles/clip.css`、`frontend/js/clip-form.js`（`runImageOcr` + 3 个新函数 + `clearForm`）。

## Assumptions & Decisions（假设与决策）

- **决策**：不改 `openClipInEditor` 本身。知识详情页与「快速AI整理 → 去写作」仍走当前标签覆盖；仅把剪藏列表 more-action 切到新标签（用户明确指向的行为）。若后续要全局统一，可再单独评估。
- **决策**：OCR 结果「插入/保存」采用**追加**语义（保留上传时已写入正文的 `![图片](media/...)`），不覆盖用户已输入的内容。
- **决策**：AI 总结失败不阻塞主流程——保留 OCR 原文，仅提示失败；用户仍可「插入到内容 / 保存到原文」。
- **决策**：同一会话多次 OCR 时，结果面板以**最新一次识别结果为准**（覆盖 `#image-ocr-result` 内容），不做多结果堆叠。
- **假设**：`recognizeImage` / `requestTextSummary` / `loadImageDataUrl` 在 clip.html 内是全局函数，`clip-actions.js` 可直接调用（同一经典 script 作用域，已核实）。
- **假设**：`GET /api/clip/{id}` 返回的剪藏对象含 `imagePaths`（已核实 [ClipContent.java L99](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/backend/src/main/java/com/example/clip/model/ClipContent.java#L99)）。
- **假设**：历史剪藏若 `content` 缺图片引用，需在**下次打开时**（改动 1）或**下次列表渲染时**（改动 2 的兜底）才补齐；本次不做存量数据迁移脚本。
- **兼容性**：`OrganizeClipRequest` 新字段为可选且默认为 null，旧调用方与旧前端请求行为不变。

### 手工回归（桌面客户端）
7. **问题 1**：收件箱选中一条剪贴板图片剪藏 → more-action「在编辑器打开原文」→ 应在**新标签**打开，且**默认已进 Markdown 预览**并看到图片；Ctrl+Shift+M 回源码可见 `![图片](media/...)`。再 Ctrl+S 保存后回列表，缩略图仍在（验证 imagePaths 未被清空）。
8. **问题 2**：对图片剪藏执行 more-action「OCR提取文字」→ 应**秒级**弹出「OCR 识别结果」弹窗展示识别文字（此阶段无大模型调用）；弹窗内点「✨ AI 总结」才出现「正在生成 AI 总结…」；点「保存到原文」→ 提示成功且**该剪藏仍留在收件箱**；列表「原文」中图片**只出现一次**，且含识别文字。
9. **问题 3**：收件箱快速记录点「OCR」→ 选图 → 上传完成 → 点「✨ OCR 提取文字」→ 图片工具栏下方出现结果面板并显示识别文字与字数（不点「插入到内容」时正文不变）；点「✔ 插入到内容」→ 正文追加识别结果且保留 `![图片](...)`；不点 AI 总结直接提交 → 剪藏原文为「图片 + OCR 文字」。
10. **守卫回归**：选图后立刻点 OCR → 提示「请等待图片上传完成后重试」；无图时点 OCR → 提示「请先上传图片再执行 OCR」；OCR 引擎不可用 → 提示「OCR 不可用：{reason}」。
11. **AI 总结失败降级**：断开/模拟 `/text-summary` 失败 → 面板保留 OCR 原文并提示失败，仍可「插入到内容 / 保存到原文」。
12. **不受影响路径**：more-action「快速AI整理」「编辑」与收件箱批量「整理收件箱」行为不变（仍标记为已整理）。
