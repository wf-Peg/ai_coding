# 画布与知识图谱拆分对齐方案

## 一、目标

当前「工作流 · 画布」与「知识区 · 画布」共用同一个 `knowledge-graph.html`（力导向图 + 手动画布卡片杂交），导致两块打架、界面混乱。本次拆分并重新对齐：

1. **工作流「画布」**：独立成 NoteGen 式「自由画布」（绝对坐标自由摆放的卡片，无 force 自动布局），复用现有 `canvas_node / canvas_edge / canvas_layout / canvas_group` 持久化与 IPC 桥，**后端零改动**。
2. **知识区「画布」**：重命名为「知识图谱」，重构为**纯只读语义关系图**（剪藏/知识/计划节点 + 自动语义连线），删除手动画布卡片、手动连线、右键菜单、AI 流程、分组。

用户已拍板三项决策：
- 画布首版＝**完整版**（便签/链接/图片/引用 + 手动连线 + 分组 + 缩放平移 + 右键新建 + 双击编辑）。
- 知识图谱＝**纯只读**（不保留手动拖拽定位）。
- **本轮不做 AI** 排版/流程图。

## 三、改动清单

### 3.1 新增 `frontend/canvas.html`（NoteGen 式自由画布页）

以 `knowledge-graph.html` 的 `<style>` 为模板，只保留画布相关样式（`.canvas-menu`、`.canvas-modal`、`.node` 卡片、`--link-manual`、`.minimap`、`.legend` 等），删除图例里 force 语义类型。结构：

- `<head>`：引入 `libs/d3.min.js`、`styles/design-tokens.css`、`styles/ui-common.css`、`js/theme-core.js`、`js/theme-bridge.js`（与 knowledge-graph.html 相同的主题初始化脚本）。
- 顶部栏：标题「画布」+ 操作提示（右键新建 / 双击编辑 / 选中节点右键连线 / 拖动定位自动保存 / 空格+拖动平移 / 滚轮缩放）。
- 主体：`.canvas-container` + d3 SVG。
- 悬浮层：右键菜单（空白／节点／连线／分组）、新建/编辑/引用弹窗、小地图、图例（便签/链接/图片/引用）。

### 3.2 新增 `frontend/canvas.js`（自由画布逻辑，无 force）

从 `knowledge-graph.js` 抽取并精简以下能力（**纯绝对坐标摆放，不用 force simulation**）：

1. **数据加载** `loadCanvas()`：
   - 先 `bridge.canvasSync()` 拉最新后端快照（进图即同步）。
   - `bridge.graph({})`（REST `/api/graph` 兜底）→ `canvasNodes = nodes.filter(n => n.canvas)`、`refNodes = nodes.filter(n => !n.canvas)`（供「引用已有节点」选择器）、`edges = links.filter(l => l.type === 'manual')`。
   - `bridge.listGroups()` → 分组。
2. **渲染**：d3 SVG + `d3.zoom`（`scaleExtent([0.1, 10])`），节点按 `x/y` 绝对定位绘制卡片（复用 `renderCanvasCard` / `canvasCardSize` / `wrapLines` / `getNodeColor` 的画布分支）；连线画直线；分组画 frame。**无 `forceSimulation`**。
3. **交互**（复用并简化）：
   - 拖拽节点 → 更新 `x/y`，`persistPositionsDebounced` 里调用 `bridge.saveLayout([{id,x,y}])`。
   - 空白右键 → `openCanvasMenu`（新建便签/链接/图片/引用）。
   - 双击节点（非 ref）→ 编辑内容。
   - 节点右键 → 新建连线 / 编辑 / 删除 / 组成分组。
   - 连线右键 → 删除。
   - 分组右键 → 重命名 / 解散。
   - 多选（框选）→ 组成分组。
4. **持久化调用（全部复用现有桥）**：`createCanvasNode / updateCanvasNode / deleteCanvasNode / createCanvasEdge / deleteCanvasEdge / createGroup / renameGroup / dissolveGroup / saveLayout / listGroups / canvasSync`。
5. **小地图**：移植 `renderMinimap / updateMinimapViewport / minimapBounds / minimapJumpTo` 等（去掉 force 相关）。
6. **引用卡片**：`ref` 节点 `text` 存被引用语义节点 id、`title` 存其标题；卡片显示标题（本轮不做深链跳转，省 token，与现状对齐）。

> 说明：`buildGraph` 里的 `fx/fy` 钉位逻辑不再需要（自由画布无 force，节点本就按坐标摆），拖拽直接改 `x/y` 并落库。

## 四、假设与决策

1. **后端/IPC/Schema 零改动**：自由画布复用现有 `canvas_*` 层与 `local-index:*` 桥 + `canvas-sync`。
2. **知识图谱＝纯只读**：节点不可手动拖拽移位置，位置由 force 自动布局决定；不写 `canvas_layout`。
3. **术语对齐**：工作流视图名保持「画布」；知识区视图名改为「知识图谱」；品牌名「碎碎记 / CutShelter」不变。
4. **AI 与深链本轮不做**：自由画布不含 AI 排版/流程图；`ref` 引用卡片仅显示标题、不跳转详情（省 token）。
5. **文件拆分为新建 canvas.html/js + 原地精简 knowledge-graph**，不新增第三个入口，避免入口分裂（沿用 `TODO/无限画布` 文档的「不另开入口」原则，此处「画布」与「知识图谱」本就是两个已有入口的拆分）。
