# 剪藏列表展示数据逻辑分析与修复计划

## 问题描述
用户反馈剪藏列表中多显示了待办事项的数据，需要分析并解决这个问题。

## 现有数据流程分析

### 1. 后端数据获取流程
- **API 端点**: `/api/clip/list` (ClipController.java:141-145)
- **调用链**: `ClipController.getClipList()` → `ClipService.getAllClips()` → `FileStorageService.getAllClips()` → `FileStorageService.getAllJsonFiles()`
- **过滤逻辑**: FileStorageService.java:143 已添加过滤: `.filter(path -> !path.toString().contains("todolist"))`

### 2. 前端数据获取与过滤
- **API 调用**: `fetchClips()` 函数调用 `/api/clip/list`
- **前端过滤**: clip.html:2159-2163 有过滤逻辑:
  ```javascript
  const filteredClips = clips.filter(clip => {
      return !clip.type || clip.type !== 'todo' && !clip.content?.includes('前完成') && !clip.content?.includes('待办');
  });
  ```

### 3. 待办事项存储逻辑
- **存储路径**: `storagePath.resolve("todolist")` (FileStorageService.java:326)
- **文件结构**: 待办事项存储在 `todolist` 目录下的日期文件中

## 问题根因分析

### 可能的根因
1. **后端过滤逻辑未生效**: 虽然代码中已添加过滤逻辑，但可能存在执行问题
2. **待办事项数据存储位置异常**: 待办事项可能存储在非 `todolist` 目录中
3. **数据类型标识问题**: 待办事项数据的 `type` 字段可能不是 'todo'
4. **前端过滤逻辑不完整**: 前端过滤条件可能不足以识别所有待办事项
