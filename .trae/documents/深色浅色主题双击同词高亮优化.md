# 深色/浅色主题「双击同词高亮」优化方案

## Summary（概述）

优化编辑器中「双击选中文本后，全文相同文本的高亮提示」的显示效果：深色主题下当前几乎不可见、浅色主题下不够明显，改为基于主题主色（`--app-primary`）的自适应样式，使高亮清晰可见且与整体主题设计一致。

## Current State Analysis（现状分析）

1. **功能来源**：双击选词高亮是 ACE 内置的 "Highlight Selected Word" 功能，在 [editor.js](file:///l:/归档/30_Projects (行动项目)/31_Work (主要工作)/code/ai_coding/frontend/js/editor.js#L314-L331) 的 `createEditor()` 中通过 `highlightSelectedWord: true` 开启。
2. **渲染机制**：ACE 用一个动态 marker 渲染所有匹配词，class 为 `ace_selected-word`，位于 `.ace_marker-layer` 内（见 Ace 源码 `session.highlight()` → `new d(null,"ace_selected-word","text")`）。
3. **当前样式（问题根源）**：
   - 浅色主题（`ace/theme/textmate`，由 editor.js L362 应用）内嵌 CSS 定义了：
     `.ace-tm .ace_marker-layer .ace_selected-word { background: rgb(250,250,255); border: 1px solid rgb(200,200,250); }`
     —— 背景接近纯白、边框淡蓝，几乎不可见。
   - 深色主题（`ace/theme/tomorrow_night`）仅定义 `border: 1px solid #373B41;`，**完全没有背景色**，深底上加深灰边框，基本看不到。
   - 项目内没有任何针对 `ace_selected-word` 的覆盖样式（已全库检索确认）。
4. **既有设计约定**（`frontend/styles/editor.css` L685-L699）：
   - 主选中区 `.ace_selection` 用 `color-mix(in srgb, var(--app-primary) 28%/16%, transparent)` + `!important` 覆盖主题默认值。
   - 对比窗同步词标记 `.sync-word-marker` 同样基于 `--app-primary` 做「边框 + 半透明底 + 圆角」。
   - 主题色令牌（`styles/design-tokens.css`）：浅色系 `--app-primary: #2383e2`，深色 `--app-primary: #61a6ff`。
5. **主题作用域**：editor 页面在 `document.documentElement` 上设置 `data-theme`（dark / regular / notion 等，见 editor.js L358），CSS 可用 `html[data-theme="dark"]` 区分深浅。

## Proposed Changes（修改方案）

### 唯一修改文件：`frontend/styles/editor.css`

在现有 `.ace_selection` 规则块（L685-L691）之后、`.sync-word-marker`（L693）之前，新增 `ace_selected-word` 覆盖规则：

```css
/* ── 双击选词的相同文本高亮（ACE highlightSelectedWord 动态标记） ── */
.ace_editor .ace_marker-layer .ace_selected-word {
  border: 1px solid color-mix(in srgb, var(--app-primary) 58%, transparent) !important;
  border-radius: 3px;
  background: color-mix(in srgb, var(--app-primary) 20%, transparent) !important;
}

html[data-theme="dark"] .ace_marker-layer .ace_selected-word {
  border: 1px solid color-mix(in srgb, var(--app-primary) 78%, transparent) !important;
  background: color-mix(in srgb, var(--app-primary) 32%, transparent) !important;
}
```

**为什么这样写（决策依据）**：

- **契合主题**：直接消费主题令牌 `--app-primary`，浅色主题是 #2383e2 蓝、深色主题是 #61a6ff 亮蓝，两种主题自动适配，与「ai_coding」整体蓝调设计统一（与 `.ace_selection` 的做法一致）。
- **深色提高可见度**：深色主题用更高透明度的边框（78%）与背景（32%），亮蓝点缀在深底上清晰醒目；浅色主题 20% 底 + 58% 边框，明显但不刺眼。
- **与选中区区分**：与 `.ace_selection`（28%/16%）拉开层次——被选中的那个词因叠加两层高亮而稍强，其余同词呈次级提示，符合「选中词 vs 其他匹配」的视觉层级。
- **圆角**：3px 圆角与 `.sync-word-marker`（2px）、diff 词级标记的圆角风格统一，观感更精致。
- **覆盖优先级**：ACE 主题把样式注入为运行时 `<style>`（`.ace-tm .ace_marker-layer .ace_selected-word`，特异性 0-3-0），本规则用 `.ace_editor .ace_marker-layer .ace_selected-word`（0-3-0）外加 `!important` 确保稳定覆盖，不受样式注入顺序影响；深色规则 `html[data-theme="dark"] + 2 类` 特异性更高。

### 不做的事（范围约束）

- 不改动 `frontend/libs/ace/` 下的第三方主题文件。

## Assumptions & Decisions（假设与决策）

- 「双击文本高亮」指的是双击选词后全文同词高亮的 UI，即 ACE 的 `ace_selected-word` 标记；用户反馈的「相同文本高亮的前端显示」与此一致。
- 高亮沿用主题主色（蓝）而非黄/绿等荧光色，遵循既有 `--app-primary` 设计规范，符合「设计契合主题」的要求。
- 判定明暗主题的依据为 `html[data-theme="dark"]` 属性，与编辑器页面主题机制一致。

## Verification（验证步骤）

1. 前端服务运行中时，刷新/重启（editor.html 已引入 design-tokens.css 与 editor.css，改动即时生效）。
2. 打开编辑模块，粘贴一段含重复词语的文本（如多次出现 `function` 或某中文词），双击其中一个词：
   - 深色主题（Dark）：所有同词出现处显示清晰的亮蓝边框 + 半透明蓝底，选中的那个词叠加选中底色，一眼可辨。
   - 浅色主题（regular / Notion）：同词出现处有明确可见的蓝底与边框，对比修改前（近白色）明显增强。
3. 在 DevTools Elements 面板确认 `.ace_selected-word` 元素命中新增规则（勾选未覆盖时计算样式 background/border 来自 editor.css 而非 ACE 注入的主题样式）。
4. 回归检查：普通拖选高亮（`.ace_selection`）、对比窗同步词（`.sync-word-marker`）、行级差异标记（diff 系列）显示均无回归。
5. 文件为纯 CSS 改动，无需 node --check；确认无语法错误、无多余改动（`git diff` 仅含 editor.css 一份）。
