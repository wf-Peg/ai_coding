# 工作台漏斗卡 + 多工作台独立布局

## Context（为什么做）

1. 组件系统（`workbench-widgets.js`）的「来源统计条 / 内容来源标记 / 规则分组渲染 / 排除列表」前端已实际完成（`workspace.js` 的 `detailStats`、`renderExpression`、`renderExclusions`、`renderDetailContents`），开发计划文档 L2 未勾选项只是没更新。不应重复做 L2 前端。
2. 后端 `GET /api/workspace/{id}/resolution` 已返回 `visibleCount / ruleMatchedCount / manualCount / relationCount / excludedCount`，但尚未以「工作台漏斗」可视化形态进入「全部概览」组件板。
3. 组件板目前是全局一张布局（键 `workspace_widget_layout_v1`），无法做到“每个工作台各摆各的组件板”。

目标（用户已确认）：
- 新增一张「工作台漏斗」组件卡，进入“添加组件”面板，**关注单个工作台、卡内可下拉切换**，数据不上 localStorage。
- 实现「多工作台独立布局」：每个工作台可拥有自己的一套组件布局，与「全部概览」默认板共存。

## 改动范围（3 文件）

### 1. `frontend/js/workbench-widgets.js`（引擎，最小扩展）
新增公开方法 `setLayoutKey(key)`，用于在不重建引擎的前提下切换整套布局的持久化命名空间：
- 内部：退出编辑态（`editing=false` → `applyEditControls`）→ 更新 `STORAGE_KEY = key` → `loadLayout(null)`（无该键存档时自动回落 `defaultLayout()`）→ `buildCards()` → `relayout()`。
- 保持现有 `mount` 不变（默认仍用全局键），避免影响「全部概览」首次装载与旧存档兼容。
- 复用现有 `loadLayout/buildCards/relayout/persist`，不新增状态。

### 2. `frontend/js/workspace.js`
- **工作台独立布局**：组件板顶部新增工作台上下文选择 UI，绑定逻辑：
  - 加载工作台列表（复用 `loadWorkspaces` 拉到的列表）。
  - 切换“全部概览”→ 调 `WB.setLayoutKey('workspace_widget_layout_v1')`（全局板）；切换某工作台 → `WB.setLayoutKey('workspace_widget_<wsId>_v1')`（该工作台专属板）。
  - 切换时先保存上一份布局（引擎 `persist` 已随交互落盘），再换键重载新板。
- **漏斗卡注册**（新增 `renderFunnelWidget`，注册到 `registerOverviewWidgets`）：
  - `id: 'workspace-funnel'`，`title: '工作台漏斗'`，`defaultSize {w:2,h:2}` / `minSize {w:1,h:1}`。
  - `render(el,ctx)`：读取默认工作台（无则取列表第一个 active）的 `/{wsId}/resolution`，用 SVG 漏斗图 + 数字展示 `规则命中 → 手动 → 关系 → 排除 → 可见`；卡内一个下拉切换工作台，change 时重新 fetch 并重绘。
  - 数据只存内存（组件实例变量），不上 `localStorage`；拉取失败显示友好空态。
  - 复用现有 `loadWorkspaces` 的工作台缓存与 `escapeHtml`。

### 3. `frontend/workspace.html` + `frontend/styles/workbench-widgets.css`
- 组件板 hero 区新增工作台上下文下拉容器（`id` 如 `widgetWsCtx`），含「全部概览」+ 各工作台选项。
- 新增漏斗卡样式（`.wb-funnel` 漏斗条、各级数字、下拉），沿用 `--ws-*`/`--app-*` token，适配深浅主题；复用 `.av-box/.ov-dash-card` 的风格基调保持一致。

## 关键复用
- 引擎：`setLayoutKey` → `loadLayout/buildCards/relayout/persist`（现有）。
- 后端：`GET /api/workspace/list`（工作台下拉）、`GET /api/workspace/{id}/resolution`（漏斗计数，已有 `visibleCount/ruleMatchedCount/manualCount/relationCount/excludedCount`）。
- 前端：`loadWorkspaces` 缓存、`escapeHtml`、`window.WB.register/mount/setLayoutKey`。

## 不做（克制）
- 不把组件板搬进「工作台详情」视图（避免与内容/规则/排除 tab 抢空间）。
- 不改后端；发现接口返回字段不符时记录问题，不临时造数据。
- 漏斗卡不做“跨工作台聚合”形态（用户已选单工作台 + 卡内切换）。

## 落地记录（2026-09-17）
- 引擎 `workbench-widgets.js` 新增公开方法 `setLayoutKey(key)`：切换持久化命名空间前先落盘当前布局，换键后 `loadLayout(null)`（无存档回落默认布局）→ `buildCards` → `relayout`；`mount` 保持不变，默认仍用全局键。
- `workspace.js` 在 `loadWorkspaces` 后填充/绑定组件板工作台下拉（`widgetWsCtx`），change 时调 `setLayoutKey('workspace_widget_<wsId>_v1' / 'workspace_widget_layout_v1')` 实现每工作台独立布局；列表就绪后 `refreshAll()` 刷新组件。
- `workspace.js` 注册 `workspace-funnel` 组件卡（`renderFunnelWidget`/`renderFunnelInto`/`fetchFunnel`）：读 `/{wsId}/resolution` 的 `ruleMatchedCount/manualCount/relationCount/excludedCount/visibleCount`，卡内下拉切换工作台，数据仅存内存不上 localStorage，失败显示友好空态。
- `workspace.html` hero 区新增「组件视图」下拉（`.wb-ws-ctx`）；`workbench-widgets.css` 新增 `.wb-ws-ctx` 与 `.wb-funnel*` 样式（`--ws-*`/`--app-*` token），窄屏折叠标签。
- 语法校验：`node --check` 两文件均通过。

## 验证
1. `node --check frontend/js/workbench-widgets.js` 与 `frontend/js/workspace.js` 语法通过。
2. 前端（3001）+ 后端（8081）启动后，进入「工作台」→「全部概览」：
   - 「自定义 → 添加组件」面板出现「工作台漏斗」卡；添加后显示默认工作台的 5 级来源漏斗；卡内切工作台后数字刷新、无数据残留。
   - 组件板顶部工作台下拉：切到某工作台显示其独立布局（可各自拼装、刷新/切回后各自保留）；「全部概览」仍为原全局布局。
3. 深浅主题切换下漏斗卡与下拉视觉正常。
4. 后端不可用时漏斗卡显示友好空态，不阻塞组件板其它卡片。
