# 「快捷键检测」工具接入工具模块

## 一、Summary（目标）

在应用「工具模块」（`frontend/tools.html` 加载的 `frontend/js/tools-core.js`）中新增一个系统工具「快捷键检测」，把**碎碎记自己的全部快捷键**（主进程菜单 accelerators、全局快捷键、编辑器键位表）列出来，检测组合键冲突、以内置面板展示，帮助用户/开发者快速发现重复绑定并去设置里改掉。

不引入第三方 npm 库，自实现轻量检测（调研结论：keymash/modkey/use-kbd 均只做"同 key 去重"，本规模自建 `Map<x, entry[]>` 分组 + normalize 足够）。

**大白话用途**：一个组合键（如 `Cmd+Shift+F`）可能被"全局搜索"和"编辑器文档大纲"两处都想接 → 按下到底触发哪个会打架。本工具把碎碎记内菜单/全局/编辑器三组快捷键列出来，把"同一键被多个不同功能占用"处标红，方便去设置里改。

**检测范围（已与用户确认）**：应用内全部快捷键冲突检测 + 系统级占用提示。即：
- ✅ 检测碎碎记内部三种来源的重复键冲突（菜单/全局/编辑器）。
- ✅ 系统占用：对每个全局快捷键调 `globalShortcut.isRegistered(acc)`，返回 `false` 说明被系统或其它 App 抢占，标橙提示。
- ❌ 不做"枚举其它 App 快捷键做跨应用全系统扫描"（Electron 内核拿不到其它 App 的键位数据；类似 macOS HotkeyClash 的跨应用扫描需另装外部工具/辅助功能权限，跑在应用外，不纳入本方案）。

## 二、当前状态分析（Exploration 结论）

应用快捷键分布在三处，均需纳入检测：

| 来源 | 位置 | 内容 |
|------|------|------|
| 菜单 accelerators | `electron/main.js` `buildMenu()`(2563–2620) | `CmdOrCtrl+K` 命令面板、`CmdOrCtrl+;` AceJump、`globalSearchAccelerator`(默认 `CmdOrCtrl+Shift+F`,447 行模块变量，可由 `shortcut:set-global-search` 动态改,2635–2643)、`CmdOrCtrl+,` 设置、`CommandOrControl+F12` DevTools |
| 全局快捷键 | `electron/main.js` `registerGlobalShortcut()`(4888) `shortcutAccelerator`(4884,默认 `Alt+X`,config 默认 `CommandOrControl+Shift+Z`) + `electron/screenshot/screenshot-service.js`(截图 F1、贴图 F2,`registerShortcuts()` 79 行) | 全局唤起窗口、截图、贴图 |
| 编辑器键位 | `frontend/js/editor-shortcuts.js` `DEFAULTS`(49–63) ，存 `localStorage['editor_shortcuts_v1']` | 12 个 action（globalSearch/fileTree/outline/tags/backlinks/quickOpen/history/recent/favorite/overview/aceJump/posBack/posForward） |

关键事实：
- 编辑器已有同域去重函数 `EditorShortcuts.findConflicts()`(201 行) 与 `normalizeCombo`，但 **tools.html 未加载 editor-shortcuts.js**，无法在工具模块直接复用 `window.EditorShortcuts`。
- `tools.html` 以 iframe 内嵌于 `index.html`(`toolsFrame`,1183 行)，**同源**，可直接读 `localStorage['editor_shortcuts_v1']`；主进程能力经 `(window.parent && window.parent.electronAPI) || window.electronAPI` 调用（tools-core.js 63 行已验证此模式）。
- `globalSearchAccelerator`(447)、`shortcutAccelerator`(4884) 为 main.js 模块级变量，新增 IPC handler 可直接读取；截图快捷键经 `screenshotService.getShortcuts()` 读取（preload `screenshot:get-shortcuts` 已暴露）。
- 已有一个 `getShortcutConfig`/`setShortcutConfig` IPC 与 `shortcut:set-global-search` IPC，preload.js 684/299 行已暴露 —— 新增收集 IPC 可复用现有 preload 暴露风格。

## 三、冲突判定规则（Decisions）

1. **「冲突」定义** = 同一**规范化组合键** 绑定 **≥2 个不同 feature**。将全局搜索、AceJump 这类「同一功能在菜单与编辑器各绑一份」判定为**同功能重复**（正常，仅在报告提示「同功能已在 N 处绑定」），不算冲突，避免误报。
2. **规范化**：把 Electron accelerator token（`CmdOrCtrl`/`CommandOrControl`/`Cmd`/`Ctrl`）与编辑器写法统一映射——mac 上平台主修饰符统一为 `Cmd+`，字母大写、修饰符排序固定。跨平台：mac 用 `Cmd`，Windows/Linux 用 `Ctrl`（与编辑器键位形一致）。
3. **系统级占用**：对每个全局快捷键调用 `globalShortcut.isRegistered(acc)`；返回 `false` 视为「占用风险」（可能被系统或其它应用抢占），橙色提示。
4. **role 型菜单项**（undo/copy 等）无显式 accelerator 或非业务快捷键，不纳入收集。

## 四、改动方案（文件级）

### 1) `electron/main.js` — 新增 `shortcut:audit` IPC 收集
- 在模块近快捷键区新增 handler（放在 `registerGlobalShortcut` 之后 4915 行附近）：
  - `ipcMain.handle('shortcut:audit', ...)`，返回：
    - `menu`：`Menu.getApplicationMenu().items` 递归收集带 `accelerator` 的项 → `{ feature: item.label, accelerator, scope:'menu' }`
    - `global`：静态登记 `[{feature:'全局唤起窗口', accelerator:shortcutAccelerator}, {feature:'全局搜索', accelerator:globalSearchAccelerator}, ...screenshotService.getShortcuts() 的截图/贴图]`，并逐项 `globalShortcut.isRegistered(acc)` 得到 `registered` → `{ feature, accelerator, scope:'global', registered }`
- menu 需要读：`const { Menu } = require('electron')` 已在 11 行 destructure 中。

### 2) `electron/preload.js` — 暴露收集接口
- 在现有 shortcut API 附近（684 行 `getShortcutConfig` 一带）新增：
  - `auditShortcuts: () => ipcRenderer.invoke('shortcut:audit')`

### 3) `frontend/js/shortcut-audit.js` — 新建检测模块（供 tools.html 使用）
- `init(parentApi)` → 缓存 `parentApi`。
- `collect()`：
  - `const p = window.parent.electronAPI || window.electronAPI`；`p.auditShortcuts()` 取 menu/global 两组。
  - 直接 `JSON.parse(localStorage['editor_shortcuts_v1'] || '{}')` 取编辑器覆盖；对 `DEFAULTS` 的 12 个动作取生效值（覆盖 or 默认），`feature` 用中文标签，标 `scope:'editor'`。DEFAULTS 中文标签常量内联到本模块（该模块自身不依赖 editor-shortcuts.js）。
- `normalize(acc)`：解析 `+` 分隔；替换 `CmdOrCtrl`/`CommandOrControl`/`Cmd`−(mac→`Cmd`)`Ctrl`→mac 平台 `Cmd`；键名 `F1..F12`/方向键/字母大写保持；重新按 [修饰符稳定序, key] join。
- `detect(entries)`：`Map<normalized, {features:Set, list:entry[]}>`；分组后 `features.size>1` → 冲突组；`features.size===1` 但 `list.length>1` → 合并提示组。
- `report()`：返回 `{ total, conflicts: [{combo, features:Array<{feature,scope}>}], duplicates: [...], osRisks: [{feature,acc}] }`。
- 暴露 `window.ShortcutAudit`.

### 4) `frontend/tools.html` — 加载模块
- `<head>` 区（theme 脚本后）加 `<script src="js/shortcut-audit.js"></script>`。

### 5) `frontend/js/tools-core.js` — 新增工具卡片与面板
- `SYSTEM_SCREENSHOT` 后新增：
  ```js
  const SYSTEM_SHORTCUT_AUDIT = {
    id: 'shortcut-audit-system', name: '快捷键检测', icon: '⌨️',
    category: '系统工具', description: '扫描菜单 / 全局 / 编辑器快捷键冲突与占用风险',
    keywords: ['快捷键','快捷键冲突','hotkey','shortcut','加速键'], builtin: true, system: true
  };
  const SYSTEM_TOOLS = [SYSTEM_SCREENSHOT, SYSTEM_SHORTCUT_AUDIT];
  ```
- `openSystemTool(t)` 开头新增分支：
  ```js
  if (t.id === 'shortcut-audit-system') return renderShortcutAudit(t);
  ```
- 新增 `renderShortcutAudit(t)`：
  - `const p = window.parent.electronAPI || window.electronAPI`；`const r = await window.ShortcutAudit.report()`（内部经 `p.auditShortcuts`）。
  - 渲染到 `$('promptContent')`（复用现有弹框容器样式），含：
    - 顶部摘要行：`已登记 X 个绑定` / `发现 M 处冲突`（红）/ `N 处全局占用风险`（橙）/ `K 组同功能合并`（灰）。
    - **冲突区块**：每组冲突一行，左「组合键」红色高亮 + 右侧每个竞争功能卡片（功能名 + scope 标签：`菜单`/`全局`/`编辑器`）。
    - **全局占用风险区块**：`isRegistered===false` 的项，提示「可能被系统或其它应用占用，建议更换」。
    - **同功能合并区块**：同功能多绑定的正常提示。
    - 空态：无冲突时显示「未发现快捷键冲突 🎉」。
    - 底部操作：`重新检测` 按钮（重调 report 重渲染）、`去设置页更换`提示文案。
  - 用 `showToast` 兜底错误。
  - 沿用现有 `openSystemTool` 的关闭清理模式（`closeBtn.onclick` 还原）。

### 6) `electron/shortcut-audit.test.js` — 单测（新增）
- 纯函数测试：`normalize`（`CmdOrCtrl+K`→mac `Cmd+K`、大小写、modifier 顺序）、`detect`（同形同功能放行、同形异功能判冲突、菜单/编辑器跨 scope 同 key 判冲突）、`report` 返回结构。测试用 `node --test` 风格，仿 `electron/editor-shortcuts.test.js`。

## 五、假设（Assumptions）

- 冲突只在渲染层计算，主进程只负责收集原始清单与 `isRegistered` 探测 → 工具模块可离线复用检测逻辑，改动面最小。
- mac 平台主修饰符统一 `Cmd+`，与编辑器键位显示一致；Windows/Linux 为 `Ctrl+`。
- 编辑器键位直接读 localStorage（tools 页同源），不额外引入 editor-shortcuts.js 全局监听。

## 六、验证步骤（Verification）

1. 单测：`node --test electron/shortcut-audit.test.js`（或项目现有 test 脚本）通过。
2. 手动：启动 Electron → 主界面「工具」视图 → 出现「快捷键检测」卡片 → 打开：应列出菜单/全局/编辑器三组绑定、无冲突时显示空态。
3. 冲突复现：在设置页把编辑器某 action（如 `outline`）改为与全局搜索相同的 `Ctrl+Shift+F` → 重新检测 → 该组合应标红，并列出「文档大纲(编辑器)」与「全局搜索(菜单)」两竞争功能；同功能合并提示区不误报全局搜索自身。
4. 占用风险：把截图快捷键改成与已占用相同组合（或模拟 `isRegistered=false`），检测面板「占用风险」区应橙色提示。
5. 回归：截图工具配置、其余工具卡片开合不受影响（改动仅在新增 id 分支与 SYSTEM_TOOLS 尾部追加）。
