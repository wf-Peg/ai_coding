# 截图工具黑屏与贴图失效根治与优化方向

## 1. 摘要 (Summary)

用户反馈：F1 截图黑屏卡死、再按 F1 仍黑屏、F2/贴图无效；且关心 **升级 Electron 到 36 / Node ≥22 后**，截图工具实现是否也需要随大版本演进。

本次计划范围：**先稳住 bug（捕获可靠性 + 贴图体验），再给出优化方向（作为文档建议，不在本期落地大重构）**。

已确认的既有改动：截图族 preload 暴露名已由 `screenshotApi` 统一改为 `electronScreenshotApi`，三处 HTML（screenshot-window / paste-window / ocr-result）均已同步，`startScreenshot failed: undefined` 日志中的 `Identifier 'screenshotApi' has already been declared` 是**改名前的旧日志**，该 SyntaxError 现已消除。但黑屏/贴图失效仍可能由**状态复位不彻底与国家/链路兜底缺失**导致，本期以观测 + 确定性修复收口。

## 2. 现状分析与根因 (Current State Analysis)

### 2.1 截图全链路（已探明）
- [electron/screenshot/screenshot-service.js](file:///Users/pengwenfeng/Documents/gitRep/trae_demo/codex-project/electron/screenshot/screenshot-service.js)：主进程服务。
  - `startScreenshot()` 流程：`inFlight`/覆盖层可见防重入 → `getOrCreateOverlayWindow`（覆盖层**复用**）→ `win.show()` 深色底"加载中" → `win.hide()` 抓屏防入镜 → `captureScreen()` → `encodeForDisplay()` → `win.show()` + 发 `screenshot:init` → 2s/8s 看门狗兜底。
  - 覆盖层复用 + `closeScreenshotWindow()` 用 `hide()` 而非 `destroy()`（L648-655）。
  - 捕获空帧/黑帧：`captureScreen()` 重试 3 次，仍黑则 `throw createEmptyCaptureError()`（L183-212）。
  - 贴图：`pasteFromClipboard()` 按 剪贴板图→剪贴板文本→`lastSnip`→`lastCapture` 兜底（L451-470）。
- [electron/screenshot/screenshot-window.html](file:///Users/pengwenfeng/Documents/gitRep/trae_demo/codex-project/electron/screenshot/screenshot-window.html#L123)：覆盖层页面，`const screenshotApi = window.electronScreenshotApi;`，`onBackgroundReady()` 里 `send('screenshot:painted')` 回执。
- [electron/screenshot/paste-window.html](file:///Users/pengwenfeng/Documents/gitRep/trae_demo/codex-project/electron/screenshot/paste-window.html#L77)：贴图页面，`img.onerror` → `send('paste:render-error')`。
- [electron/main.js](file:///Users/pengwenfeng/Documents/gitRep/trae_demo/codex-project/electron/main.js#L4340)：`initScreenshotService({...})` 注入依赖；退出时 `screenshotService.cleanupOnQuit()`（L2210、L4636）。

### 2.2 黑屏卡死的根因（分层判断）
1. **历史根因（已修）**：改名导致覆盖层脚本 SyntaxError → `screenshot:init` 从未注册 → 覆盖层永远只显示深色 body `#101014` ≈ 黑屏。现已修复。
2. **残留隐患（本期需加固）**：覆盖层**复用 + hide()**，若某次截图失败/超时后状态未复位（`screenshot:loading` 已发但 `screenshot:init` 未完成、或覆盖层 visible 标志未清），再按 F1 会因 `screenshotWindow.isVisible()` 提前 return，表现为"黑屏卡死在覆盖层上"。需**每次 F1 全量复位 + 兜底关闭**。
3. **捕获空帧不会被显式兜底**：`captureScreen` 抛错后走 `failScreenshot()`（L305），理论上会关闭覆盖层并恢复主窗口；但若抛错发生在捕获前（如 `getTargetDisplay`/`win.show`），`inFlight` 尚未置 true，看门狗不武装，需确认 catch 覆盖全链路。

### 2.3 贴图无效的根因
- **空值兜底无提示**：若本次从未成功截图，`lastSnip`/`lastCapture` 为空，F2 走 `pasteFromClipboard()` 末尾 `return {status:'empty'}`（L469）**无任何用户提示**，表现为"贴图无效"。
- **贴图渲染失败不关窗**：`paste:render-error`（paste-window 发送，service L785-787 仅 `log`）**不销毁贴图窗** → 深色 `#000000` 背景窗口（L500）挂在那，表现为"黑窗/贴图无效"。
- **`screenshot:copy-last`/`paste:save` 对 `lastSnip` 空值不提示**：L721 返回 `{status:'empty'}` 同样无提示。

### 2.4 升级 Node/Electron 的影响评估
- 截图服务本身用的都是 **Electron API**（`desktopCapturer`/`nativeImage`/`BrowserWindow`/`clipboard`），逻辑不依赖 Node 版本，**无需因 node 升级改动逻辑**。
- 真正相关的是**原生依赖 ABI 必须与 Electron 36 匹配**：`onnxruntime-node ^1.27`、`sharp ^0.35`。`postinstall` 的 `electron-builder install-app-deps` 会重建，需确认 OCR/贴图缩放（sharp）可用。此外 Electron 36 已弃用**回调式 `console-message` 事件签名**（日志里有 deprecation warning），有兼容性收尾项。

## 3. 变更方案 (Proposed Changes)

按 **A. 捕获可靠性 → B. 贴图体验 → C. Electron36 兼容收尾** 顺序落地。全部为小步、可回归的确定性改动。

### A. 捕获可靠性（根治黑屏卡死）

**A1. [screenshot-service.js] `startScreenshot()`：每次 F1 全量武装看门狗 + 全链路 catch**
- 位置：L249-302。
- 把 `inFlight = true` 提前到 `win.show()` 之前（打开覆盖层即武装），并让 8s 看门狗在 `win.show()` 失败/抛住的路径也能兜底。
- `catch (e)` 分支（L298-301）补充：打印 `e.stack` 帮助定位，并确保 `failScreenshot` 一定走 `closeScreenshotWindow()`（复位 `inFlight`、清定时器、hide 覆盖层、恢复主窗口）。

**A2. [screenshot-service.js] `closeScreenshotWindow()`：复位覆盖层渲染状态**
- 位置：L648-655。
- hide 前主动 `webContents.send('screenshot:reset')`（新增通道，需要 preload ALLOWED_ON 加白名单），或复用现有加载态复位；确保覆盖层 DOM/遮罩/背景上轮残留被清干净，杜绝"复用窗口显示陈旧黑屏"。
- 若 `isDestroyed()` 返回 true 但引用未清，确保 `screenshotWindow = null`（当前靠 `win.on('closed')`，需确认 no-race）。

**A3. [screenshot-service.js] 黑帧/空帧观测增强**
- 位置：`captureScreen`（L183-212）、`isBlackFrame`（L157-179）。
- 增加更细致的采样日志（命中黑帧时输出 `img.getSize()` + 黑点计数），便于下次出现时直接从日志确认是"权限黑帧"还是"捕获报错"，避免反复人工猜测。
- 补充：捕获回归测试用到可注入 `desktopCapturer`（`_test.setDeps` 已存在），便于单测黑帧分支。

### B. 贴图体验（修复"贴图无效"）

**B1. [screenshot-service.js] `pasteFromClipboard()`：空值给用户明确提示**
- 位置：L466-470。
- 当剪贴板与 `lastSnip`/`lastCapture` 都为空时，`notifyMainWindow('无内容可贴图：先截图或复制一张图片', 'warn', 4000)` 再返回 `{status:'empty'}`，避免静默无反馈。

**B2. [screenshot-service.js] 贴图渲染失败自动收尾**
- 新增 IPC：`paste:render-error` 目前仅 log（L785-787），改为**根据 sender 找到贴图窗** `win.destroy()`（若 sender 是 paste 窗），并 `notifyMainWindow('贴图渲染失败，已关闭', 'warn', 4000)`。需用 `BrowserWindow.fromWebContents(e.sender)`，与 L792 一致。

**B3. [paste-window.html] 空/坏图兜底**
- 位置：paste-window.html `img.onerror`（L125）。
- 在发 `paste:render-error` 前附加 `message` 带 `naturalWidth/Height`，方便定位。

**B4. [screenshot-service.js] copy-last / paste-save 空值提示**
- L720-725（`screenshot:copy-last`）、L864-873（`paste:save`）：`{status:'empty'}` 前补 `notifyMainWindow` 提示。

### C. Electron36 兼容收尾（随问题一并清理，低风险）
**C1. 弃用事件签名：`console-message`（service L348-350、L559-561）**
- Electron 36 新签名为 `(event)` 对象（`event.level`/`event.message`）。改为：
  ```js
  win.webContents.on('console-message', (event) => {
    const { level, message } = event;
    if (level >= 2) log('window console[' + level + ']:', String(message).slice(0, 200));
  });
  ```
- 必需：否则升级到不再支持旧签名的 Electron 时，`(e, level, message)` 的 `level`/`message` 变成 undefined，日志失效（不 crash）。**低风险、高收益**。

**C2. 原生依赖 ABI 校验（Node/Electron 升级相关）**
- 运行 `npx electron-builder install-app-deps` 后确认 `onnxruntime-node` / `sharp` 能加载（`require` 测试 + OCR 功能冒烟），若失败则重新安装/对齐版本。此为**验证项**，非代码改动。

## 4. 假设与决策 (Assumptions & Decisions)
- **本期只做 bug 根治 + Electron36 兼容收尾**，不做捕获/渲染底层重构（Tauri 迁移、大改 capture 方案等留待后续评估）。
- 覆盖层继续走 **复用 + hide** 策略，但通过啄一次复位 + 看门狗前置武装来消除黑屏残留；不改为 destroy+重建（避免性能回退）。
- 贴图空值/渲染失败一律**给用户可见提示**，不再静默失败。
- `console-message` 弃用签名改动属于低风险兼容收尾，纳入本期。

## 5. 优化方向（文档建议，本期不落地）
> 参考 Snipaste / Flameshot / macOS 原生截图 / Windows 截图工具，按用户关注排序：

1. **捕获可靠性**（用户已选关注）：
   - 多显示器细化：非主屏 DPI 缩放/尺寸差异下的裁剪换算（当前以 DIP + scaleFactor 近似）。
   - 黑帧归因收敛：区分"权限未授"vs"窗口合成未就绪"，首帧仍黑时自动 retry 而非立即 fail。
   - 在半 Tauri 迁移考量下，捕获仍用 `desktopCapturer`（Electron 唯一可靠全屏源）。
2. **贴图体验**（用户已选关注）：
   - 对齐 Snipaste 语义：F3 重复贴最近选区、Ctrl+V 贴选区、置顶/透明度/缩放锚点已实现，可补"旋转/镜像/标注悬浮"。
   - 贴图失败所有分支给出提示 + 自动回收坏窗。
3. **启动与生命周期**：覆盖层首次按需创建已落地；进一步把 toast/贴图/覆盖层统一纳入"临时窗口注册表"，退出时统一 `destroy()`，杜绝 `app.quit()` 阻塞。
4. **权限引导**：利用 Electron36 新 `systemPreferences` 事件，在权限变更后自动恢复截图，而非要求重启。

### 手动冒烟（npm start，macOS）
1. **F1 截图**：A1-A3 后，F1 出覆盖层显示真实画面（非黑），拖选 → Enter 复制，弹"已复制"提示。

3. **Esc 取消**：F1 → Esc，覆盖层关闭、主窗口恢复、`inFlight` 复位（log 验证）。
4. **F2 贴图**：先 F1 复制再 F2，出贴图窗可拖动/缩放/置顶/关闭；右键菜单项可用。
5. **空贴图**：清空剪贴板、然后 F2，出现"无内容可贴图"提示（B1）。
6. **贴图渲染失败**：构造坏图（可选）触发 render-error → 贴图窗自动销毁 + 提示（B2）。
7. **Quit**：有贴图窗时 Cmd+Q，应用能正常退出（cleanup 生效，无阻塞）。
