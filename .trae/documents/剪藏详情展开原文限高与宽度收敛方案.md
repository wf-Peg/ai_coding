# 剪藏详情「展开原文」Markdown 渲染限高与宽度收敛方案

## 概述（Summary）

剪藏列表展开详情后，原文 Markdown 渲染存在两个设计缺陷：
1. **无高度限制**：`.content-text.truncated.expanded` 展开后不设 `max-height`，超长原文会撑爆整个页面（整页滚动到底，体验差）。
2. **宽度溢出**：原文内的 `<img>`、`<table>`、超长代码/URL 等无任何宽度约束，直接超出应用显示区宽度。

**采用方案**（用户已确认）：
- **高度**：展开态限高 `min(55vh, 560px)` + 容器内部滚动（细滚动条自动继承全局样式）。
- **宽度**：所有 Markdown 子元素约束在显示区内——图片 `max-width:100%`、代码块自动换行、表格横向滚动、长词/URL 自动断行。

本次改动仅限**桌面应用剪藏页**（`frontend/styles/clip.css`），纯 CSS，不改 DOM/JS 与交互逻辑。

## 现状分析（Current State Analysis）

### DOM 结构（frontend/clip.html + frontend/js/clip-list.js）

```
.clip-detail.expanded（点击「展开」显示）
  └─ .content-section（白卡片，padding 20px）
      └─ .content-text.truncated（L419：renderContent() → renderMarkdown() 输出）
```

- 折叠态（L1997-2004）：`-webkit-line-clamp: 3` + `overflow: hidden` + 底部渐变遮罩（L2007-2017）
- 展开态（L2018-2027）：`.content-text.truncated.expanded { display:block; -webkit-line-clamp: unset; }` —— **无 max-height（问题1）**
- 原文内的 `img` 无 `max-width:100%`（`max-width:100%` 只存在于 `.markdown-content img`，见 L2406-2409，但原文容器是 `.content-text` 而非 `.markdown-content`）→ **宽图溢出（问题2）**
- `pre` 换行规则仅挂在 `.content-text.truncated pre`（L2034-2038）——展开态虽仍生效，但语义上应提升为基础规则
- `table`、超长 URL/无空格长串：均无约束 → 溢出

### 全局滚动条（可复用，无需新增）

clip.css L3040-3067 已有全局窄滚动条（`::-webkit-scrollbar` 约 6px、圆角滑块、随主题变色），内部滚动容器自动继承，无需额外写滚动条样式。

## 变更方案（Proposed Changes）

**唯一改动文件**：`frontend/styles/clip.css`

### 1. 展开态限高 + 内部滚动（问题1）

`.content-text.truncated.expanded`（L2018-2021）追加：

```css
.content-text.truncated.expanded {
    display: block;
    -webkit-line-clamp: unset;
    max-height: min(55vh, 560px);
    overflow-y: auto;
}
```

- `min(55vh, 560px)`：小屏按视口高度、大屏封顶 560px，约一屏内，避免超长原文撑爆页面。
- 内部滚动容器自动套用全局窄滚动条样式。
- 点击内容区仍可收起（现有事件委托不变，L65-70 已忽略拖选文本）。

### 2. 宽度收敛（问题2）

`.content-text` 基础规则（L1627-1631）追加宽度约束，并新增子元素规则：

```css
.content-text {
    font-size: 1rem;
    line-height: 1.6;
    color: var(--text-secondary);
    min-width: 0;
    overflow-wrap: anywhere;
}
.content-text img {
    max-width: 100%;
    height: auto;
}
.content-text pre {
    white-space: pre-wrap;
    word-break: break-word;
}
.content-text table {
    display: block;
    max-width: 100%;
    overflow-x: auto;
}
```

- `overflow-wrap: anywhere`：长 URL / 无空格长串自动断行，作用于所有文本子元素（p/li/blockquote/a/code 等继承）。
- `img { max-width: 100%; height: auto; }`：宽图缩放进显示区，不拉伸变形。
- `pre { white-space: pre-wrap; word-break: break-word; }`：代码块换行（从 `.content-text.truncated pre` 提升为通用规则）。
- `table { display: block; max-width: 100%; overflow-x: auto; }`：宽表格在自身容器内横向滚动，保留列宽可读性，不撑破页面。
- `min-width: 0`：防御 flex/grid 祖先导致的 min-content 溢出。

### 3. 移除旧规则（去重）

删除 L2034-2038 的旧规则（其职责已由第 2 步 `.content-text pre` 覆盖）：

```css
.content-text.truncated pre,
.content-text.truncated pre code {
    white-space: pre-wrap;
    word-break: break-word;
}
```

保留其余折叠态规则（`> * { margin: 0 }`、`::after` 渐变遮罩、`expanded > * { margin: revert }`）不变。

## 假设与决策（Assumptions & Decisions）

- **限高值**：`min(55vh, 560px)` —— 约一屏内容，兼顾小屏（55vh）与大屏（560px 封顶），用户确认采用「限高+内部滚动」交互。
- **内部滚动不叠加底部渐隐**：滚动条本身已清晰提示可滚动，避免与折叠态渐变遮罩语义混淆。
- **宽度收敛覆盖折叠态与展开态**：规则挂在 `.content-text` 基础类上，折叠预览里的宽图/长代码同样被约束，避免折叠时也溢出。
- **同时作用于「我的思考」section**：该 section 也用 `.content-text.truncated`（L444），限高与宽度规则一致生效，行为统一。
- **不改浏览器扩展版**：扩展版（browser-extension/clip.html L1028）仅有 `.content-text.truncated`，缺少 expanded 状态样式，原文展开本就不可用（属既有差异，非本次范围）。本次仅桌面应用。
- **纯 CSS 改动**：不触碰 JS（toggleDetail / 事件委托 / renderMarkdown）与 DOM 结构。

## 验证步骤（Verification）

1. **启动应用**（完全退出旧进程后 `npm start`），进入「剪藏」列表。
2. **宽度验证**：
   - 找一条含**宽图**的剪藏并展开原文 → 图片缩进显示区内、不变形。
   - 找一条含**超长代码块**的剪藏 → 代码自动换行，不横向溢出。
   - 找一条含**宽表格 / 长 URL** 的剪藏 → 表格在容器内横向滚动、URL 自动断行，页面无横向滚动条。
   - 折叠态同样检查宽图不溢出。
3. **高度验证**：
   - 展开一条超长原文 → 内容在 `min(55vh, 560px)` 容器内滚动，页面不再被撑长；内部滚动条为全局窄样式。
   - 短内容（不足限高）→ 无滚动条、视觉无变化。
4. **交互回归**：
   - 再次点击已展开的内容 → 正常收起为 3 行省略。
   - 拖选文本不误触发收起；「复制原文」「复制到编辑区打开」按钮仍可用。
   - 「我的思考」section 展开后同样限高滚动。
5. **深色主题**：切换暗色主题确认渐变遮罩、滚动条、代码块配色正常。
