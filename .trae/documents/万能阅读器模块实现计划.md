# 万能阅读器模块实现计划

## Summary

为剪藏应用新增一个"万能阅读器"轻量预览模块：纯展示、不编辑，支持 Word(docx)、PPT(pptx)、PDF、Excel(xlsx)、Markdown、JSON/TXT/代码等文本类格式。采用**自组轻量渲染器**方案（用户已确认），按需懒加载第三方库，避免应用体积膨胀；同时打通**工具页 + 剪藏链路**两个入口。

## 体积对比结论（用户关注点）

| 方案 | 增量体积（gzip） | 说明 |
|---|---|---|
| 自组渲染器（本方案） | 总资源约 **0.9~1.3MB**，但**全部懒加载** | 常驻壳（reader.js/css）约 20KB；PDF 库 ~250KB+worker ~500KB、docx-preview ~45KB、exceljs ~250KB、pptx-renderer ~300KB+、highlight.js 核心 ~40KB，均为"打开对应格式时才加载"。首屏/启动零额外负担 |
| Flyfish File Viewer full 包 | npm 包 **199MB**（含全部 wasm/字体/worker），IIFE 单文件数 MB | 格式最全（206 种）但重；即使 standard preset 也携带 PDF/DOCX/PPTX/XLSX/archive 的 worker+wasm+字体 |

**实测落地体积（2026-09-19 已实现）**：pdf.js 312KB + worker 1062KB、docx-preview 71KB、exceljs 926KB（未 gzip）、highlight.js 119KB、jszip 95KB（pptx 文本提取用），合计 **2.52MB 原始 JS，全部懒加载**（打开对应格式才注入），首屏零负担。PPtx 因无 IIFE 构建改用 jszip 文本提取降级方案。

**决策依据**：本应用核心是轻量、低占用；`frontend/libs/` 已采用"本地放 min 库"模式（如 marked.min.js），无构建工具。自组方案完全贴合现有架构，且重库只在命中格式时注入页面。

## 需要新增/修改的文件

### 1. 主进程 `electron/main.js`（新增 2 个 IPC）

**`reader:select-file`** — 打开系统文件对话框，过滤文档扩展名（pdf/docx/pptx/xlsx/md/txt/json/xml/yaml/csv/log 等），返回选中路径。
- 参考现有 `select-directory` handler 写法（[main.js L3789](file:///l:\归档\30_Projects%20(行动项目)\31_Work%20(主要工作)\code\ai_coding\electron\main.js#L3789)）。
- `properties: ['openFile']`，`filters` 按格式分组列出。

**`reader:read-file`** — 以**二进制**读取本地文件，返回 `{ fileName, displayPath, size, base64 }`，供渲染进程交给各渲染库解析。
- 限制大小（建议 100MB，超过返回 `{ tooLarge: true }` 并前端友好提示）。
- 用 `fs.readFileSync` + `Buffer.toString('base64')`；渲染端转 `Uint8Array`。
- 与编辑器通道分开，避免污染编辑器令牌机制（编辑器需要写权限令牌，阅读器只读）。

### 2. Preload `electron/preload.js`（暴露 2 个方法）

- `selectReaderFile()` → `ipcRenderer.invoke('reader:select-file')`
- `readReaderFile(filePath)` → `ipcRenderer.invoke('reader:read-file', filePath)`
- 参照现有 `openFileByPath` 暴露方式（[preload.js L410](file:///l:\归档\30_Projects%20(行动项目)\31_Work%20(主要工作)\code\ai_coding\electron\preload.js#L410)）。

### 3. 新页面 `frontend/reader.html` + `frontend/js/reader.js` + `frontend/css/reader.css`

作为独立 iframe 子页面（模式同 tools.html / knowledge.html）。

**页面结构**：
- 顶部工具栏：返回按钮、文件名+大小信息、格式徽标；右侧动作区（放大/缩小/适应宽度、翻页/页码、打开文件按钮、在编辑器中打开按钮）。
- 主内容区 `#reader-container`：各格式渲染挂载点。
- 空状态：拖拽文件到窗口 + 点击"打开文件"两个入口。

**渲染分发逻辑（reader.js 核心）**：
- `detectType(fileName, base64)` 按扩展名分类：pdf / docx / pptx / xlsx / csv / md / code(js/json/py/...)/ text。
- **按需加载**：`loadLib(src)` 动态插入 `<script>` 标签（本地 file:// 路径，同 marked.min.js 惯例），带缓存避免重复加载。
- 各格式渲染：
  - **PDF**：pdf.js（`libs/pdfjs/pdf.min.js` + `pdf.worker.min.js`）。`PDFJS.GlobalWorkerOptions.workerSrc` 指向本地 worker；Electron 下 worker 用 file:// 可能受限，需处理为 Blob URL（`URL.createObjectURL(new Blob([...], {type:'application/javascript'}))` 或直接同目录相对路径）——**实现时优先尝试 Blob URL 方案**。单页 canvas 渲染 + 上一页/下一页 + 页码显示 + 缩放。
  - **docx**：docx-preview（`libs/docx-preview.min.js`）。`renderAsync(uint8, container)`，滚动连续阅读。
  - **pptx**：pptx-renderer（`libs/pptx-renderer`，浏览器构建版）。逐页渲染为 DOM 幻灯片，左右翻页。
  - **xlsx**：exceljs（`libs/exceljs.min.js`）。只读解析第一个 sheet（或 sheet 切换下拉），自建表格 HTML 渲染（表头 + 单元格 + 合并单元格），不引入 Handsontable（避免重依赖）。
  - **csv**：轻量解析为表格。
  - **md**：复用 `MediaKit.render.renderMarkdown`（marked + sanitize）。
  - **代码/text/json/xml/yaml**：`highlight.js`（`libs/highlight.min.js`，按需启用常用语言包）或纯 `<pre>` 文本展示（JSON 可做格式化）。
- 全部渲染结果容器样式对接主题变量（design-tokens.css），深浅色自适应。

**与主框架的通信**：
- 接收 `window.parent.postMessage({ type:'openInReader', filePath, fileName })` → 调 `readReaderFile` 后渲染。
- 打开文件按钮 → `selectReaderFile()` → 本地渲染（工具页自用场景）。

## 假设与决策

- **只读不编辑**：阅读器纯展示；需要编辑时通过"在编辑器中打开"按钮（文本类）或系统默认程序打开（二进制类），不做内嵌编辑。
- **不做旧格式**（doc/xls/ppt）：MVP 仅覆盖 docx/xlsx/pptx/pdf + 文本类；doc/xls/ppt 给出"不支持预览"提示 + 可用系统默认程序打开。
- **文件大小上限 100MB**（可配常量），避免大文件卡死；pdf/xlsx 大文件依赖库自带懒加载/分页能力。
- **安全性**：md 渲染沿用现有 sanitize 管线；docx/pptx 解析库在 Electron 渲染进程本地执行，不涉及远程资源。
- **pdf worker 在 Electron 下的加载方式**：优先 Blob URL 方案，若失败回退相对路径，实现时验证。
- **体积取舍**：xlsx 用 exceljs（250KB）而非更轻的 SheetJS 社区版，因其无授权争议且能力稳定；如后续发现体积敏感可替换为更轻解析器。

   - [electron/command-line-handler.js](file:///l:\归档\30_Projects%20(行动项目)\31_Work%20(主要工作)\code\ai_coding\electron\command-line-handler.js) 解析 `--clip-file / --open-editor / --pdf-ocr` 等 → `dispatchActions` → `mainWindow.webContents.send(...)`。

   **结论**：新增"轻量预览"右键，无需从零造注册表/分发机制，只需在这 3 处各加一个 `--open-reader` 分支。

3. **文件关联只在 mac 段**（[package.json L202-L279](file:///l:\归档\30_Projects%20(行动项目)\31_Work%20(主要工作)\code\ai_coding\package.json#L202-L279)，均为 `role: Editor` 文本类）；Windows 无 fileAssociations，靠 registerOpenWith + 注册表实现"打开方式"。桌面级 office/pdf 的右键打开应走注册表 `SystemFileAssociations`，而非 electron-builder fileAssociations（后者需重新打包 + 影响默认程序优先级）。

5. **两处入口统一**：剪藏链路（postMessage `openInReader`）与系统右键打开（`--open-reader` → IPC `open-reader-request`）最终都应汇聚到同一处理函数 `renderView('reader')` + 向 `readerFrame` 转发文件信息，避免两套打开逻辑。
