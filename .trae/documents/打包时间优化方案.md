# 打包时间优化方案（完整深度优化：层 1 + 2 + 3）

## Summary

当前 `CutShelter` 打包慢且 **`dist-electron` 占用磁盘高达 4.2GB**，同时打包源约 750MB 每次全量处理。用户的明确诉求：
1. 打包时间变慢 → 优化提速
2. 精简无用包（跨平台冗余、开发期文件）
3. **`dist-electron` 目录占用磁盘太大 → 瘦身**

本方案通过「缓存跳过 + 跨平台资源裁剪 + 架构收敛 + 产物目录清理」四管齐下，在**不改变 .dmg/.exe 运行时功能**的前提下：
- 日常验证性打包装秒级
- 完整发布只产必要产物
- `dist-electron` 从 4.2G 瘦身到 ~1-1.5G

目标平台：**macOS arm64** + **Windows 11 x64**（用户明确）。

## Current State Analysis（现状诊断，全部实测确认）

### 打包入口
- `build:mac` = `build:jar && prebuild && electron-builder --mac --arm64 --x64`
- `build:win` = `build:jar && prebuild && electron-builder --win --x64 && build-update-zip`

### dist-electron 磁盘占用实况（4.2GB）
```
1.1G  dist-electron/mac-arm64      ← .app 中间目录（打包遗留，未清理）
1.1G  dist-electron/mac            ← .app 中间目录（x64，打包遗留，未清理）
499M  CutShelter-1.0.9-x64.zip
497M  CutShelter-1.0.9-arm64.zip
496M  CutShelter-1.0.9-x64.dmg
483M  CutShelter-1.0.9-arm64.dmg
+ blockmap / yaml / builder 配置
```
**根因**：`prebuild-clean.js` 虽在打包前清 `dist-electron`，但**打包完成后中间 `.app` 目录（2.2G）和全部产物都保留累积**，双架构各自 1.1G。

### 打包源体积（每次全量复制，约 750MB）
```
322M  jre/                 ← 完整 JDK，含 jmods 77M（仅开发用）
299M  dist-dsh-offline/    ← 含跨平台冗余二进制（node-pty win32 25M 等）
 88M  backend/target/*.jar
 22M  frontend/
 15M  electron/screenshot/ocr-models
```

### 各环节耗时瓶颈（实测）
| 环节 | 现状 | 耗时实测 |
|------|------|---------|
| `build-dsh-offline.mjs` | 每次 `rmSync` 删 `dist-dsh-offline` 后逐文件复制 3.3万文件，无缓存 | **18.5 秒** |
| `generate-icons.js` | 每次无缓存重跑 cairosvg 全量生成 | 每次全量 |
| `prebuild-clean.js` | 删 dist-electron（含上次产物），无法增量 | — |
| `electron-builder --mac --arm64 --x64` | 双架构 + 每架构 dmg/zip = 4 产物 | 分钟级 |
| jre/jmods + 跨平台二进制 | 纯冗余负担 | — |

## Proposed Changes

> 设计原则：**产物功能不变**，只优化过程耗时与磁盘占用；新增脚本均为增量入口，保持 `build:mac`/`build:win` 可用。

---

### 层 1：缓存跳过 + 秒级速测（提速核心）

**1-a. `build-dsh-offline.mjs` 加缓存指纹**
- 文件：`scripts/build-dsh-offline.mjs`
- 逻辑：用 `crypto.createHash('sha256')` 对 `package-lock.json` 内容算指纹，与 `.dsh-offline.hash` 比对；**一致且 `dist-dsh-offline/node_modules` 存在则跳过**。lockfile 变化/产物缺失/设 `DSH_OFFLINE_FORCE=1` 才重建。
- 收益：依赖未变时省 18.5s。

**1-b. `generate-icons.js` 加缓存判断**
- 文件：`scripts/generate-icons.js`
- 逻辑：对每个输出 PNG，若「目标存在且 mtime ≥ 源 SVG」则跳过该图标。
- 收益：SVG 未变时跳过 cairosvg 调用。

**1-c. 新增 `build:mac:dir` / `build:win:dir` 速测脚本**
- 文件：`package.json` scripts
- `"build:mac:dir": "npm run build:jar && npm run prebuild && electron-builder --mac --dir --arm64"`
- `"build:win:dir": "npm run build:jar && npm run prebuild && electron-builder --win --dir --x64"`
- 说明：`--dir` 只产 `.app`/`win-unpacked` 目录，不出 dmg/exe，秒级验证。

---

### 层 2：精简无用包（体积瘦身核心）

**2-a. dsh-offline 排除非本平台预编译二进制**
- 文件：`scripts/build-dsh-offline.mjs`
- 复用现有 `--platform`/`process.platform` 判定：复制 `prebuilds`、`build/Release` 原生产物时仅保留匹配 `darwin-arm64|darwin-x64|win32-x64|linux-x64` 中目标的一项，删除其他平台与 `.pdb` 调试文件。
- 收益：node-pty win32 25M 等不再打包。

**2-b. jre 用 `jlink` 裁剪（重）**
- 新增 `scripts/build-jre-jlink.sh`（mac/win 分别生成到 `jre/mac-arm`、`jre/win`）
- `jlink --strip-debug --no-header-files --no-man-pages --add-modules=<Spring Boot 所需模块>` 生成精简运行时，替代完整 JDK。
- 收益：jre 322M → 预计 60~80M（去掉 jmods 77M + 未用模块）。
- 前提：`afterPack.js`/运行时能处理 flat `jre/` 结构（现有 `afterPack.js` 已兼容 `Contents/Resources/jre`，需保留 `bin/java` 相对结构）。
- 风险点：需验证 Spring Boot 后端在精简运行时完整启动（打包 `dependsOn` 缺失模块会抛 NoClassDefFoundError，需用 `--add-modules` 显式补齐或用 `jdeps` 分析）。

**2-c. extraResources 的 `jre` 按平台过滤（兜底）**
- 文件：`package.json` build.extraResources
- 若因风险不做 jlink，则至少把 `jre/filter` 从 `**/*` 改为排除 `**/jmods/**` 与 `**/man/**`（至少省 ~78M），并可改为按打包平台引用对应 `jre/<platform>` 子目录（当前 `jre/` 扁平需先重构为 `jre/win`、`jre/mac-arm`）。
- 说明：当前 `jre/` 是单份扁平 mac-arm 结构。若要跨 win+mac 同时维护，**建议把 jre 重构为分平台子目录** `download-jre.sh` 已在 `out_dir="$JRE_DIR/$platform"` 待命，只是当前没执行 `all`。可将 extraResources 改为两段带条件，或用 electron-builder 的 `${os}` 宏/ filter 区分。

---

### 层 3：架构收敛 + 产物目录清理（磁盘瘦身核心）

**3-a. 架构收敛：默认只打目标架构**
- 文件：`package.json`
- 新增：`"build:mac:arm": "... electron-builder --mac --arm64"`；`"build:win": ...`（保持 x64）。
- `build:mac`（双架构）仅正式发布用。
- 收益：本地打 mac 只产 1 架构，少一半 electron-builder 工作量。

**3-b. 打包后清理中间 `.app` / win-unpacked 目录**
- 新增 `scripts/clean-artifacts.js`（或在 `prebuild` 末尾 / 独立脚本调用）：
  - 打包完成后删除 `dist-electron/mac-arm64`、`dist-electron/mac`、`dist-electron/win-unpacked` 等中间目录（只保留最终 .dmg/.zip/.exe/blockmap/yaml）。
  - 需给 electron-builder 配 `"electron-builder:complete"` 或在 `build:mac:arm`/`build:win` 命令尾部串联。
- 收益：dist-electron 从 4.2G → 约 1G（仅 dmg+zip / exe+blockmap+yaml）。

**3-c. cleanup dist-dsh-offline 的 `.progress.log` 等辅助文件（可选）**
- 不影响打包耗时的边缘清理，可并入 2-a。

---

## Assumptions & Decisions

- **产物功能不变**：所有优化不改变运行时行为。
- **目标平台**：macOS arm64 + Windows 11 x64（放弃 mac x64 的本地构建必要性，正式发布仍可用双架构）。
- **层 2-b(jlink)** 较大且有后端兼容风险 → **已决定不采纳**（用户需 win/mac 双平台），改走 **2-c 兜底**：jre 按平台拆分 + 过滤 `jmods`/`man`，零运行时风险。
- **jre 分平台重构（已落地）**：`download-jre.sh`/`download-jre.bat` 归档到 `jre/win`、`jre/mac`（mac 含 arm64），`download-jre.sh all` 下载两平台；下载后自动删除 `jmods`/`man`。extraResources 用 `${os}` 宏 `"from": "jre/${os}"` + filter 排除 `**/jmods/**`、`**/man/**`，win→`jre/win`、mac→`jre/mac` 自动选取，两者俱备可交叉维护。
- **产物只保留 dmg/zip/exe + blockmap/yaml**，中间 `.app`/`win-unpacked` 打包后删除。

## Verification（验证步骤）

1. **dsh 缓存命中**：连续两次 `node scripts/build-dsh-offline.mjs`，第二次跳过复制，耗时 <2s；改 lockfile 后强制重建仍成功。
2. **图标缓存**：`node scripts/generate-icons.js` 二次运行跳过未变 PNG。
3. **速测路径**：`npm run build:mac:dir` 生成 `dist-electron/mac-arm64/CutShelter.app` 可正常启动、后端/基塔/DSH 面板可用；`build:win:dir`（若在 win）同理。
4. **跨平台排除**：`find dist-electron/.../dsh-offline -path "*node-pty/prebuilds*"` 只剩目标平台，无 win32/linux。
5. **jlink 精简运行验证**：用精简 jre 启动后端，跑完整剪藏/AI 流程，确认无模块缺失错误。
6. **磁盘瘦身**：完整 `build:mac:arm` + `build:win` 后，`du -sh dist-electron` 应在 ~1-1.5G，无中间 .app/win-unpacked 残留。
7. **最终发布回归**：跑一次完整 `build:mac`(双架构)，确认 dmg/zip 正常生成安装运行。
8. **耗时对比**：记录优化前后速测与完整发布耗时。

## 结论预览

- **层 1**：dsh 缓存+图标缓存+`--dir` 速测 → 日常验证秒级。
- **层 2**：跨平台冗余清除 +（可选 jlink）jre 裁剪 → 打包源 750M 降到 ~400M。
- **层 3**：架构收敛 + 中间目录清理 → dist-electron 4.2G 降到 ~1-1.5G，打包只产必要产物。
- 组合后「完整发布耗时」与「磁盘占用」均显著下降。
