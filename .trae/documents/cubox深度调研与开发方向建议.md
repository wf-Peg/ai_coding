## 二、Cubox 调研核心发现（关键结论）

### 2.1 产品定位与哲学
- 定位「人生阅读记忆体」：知识发现 → 收藏 → 阅读 → 使用全链路，不做算法推荐、不做社交、不做富文本笔记（官方"暂不擅长"清单）。
- 核心承诺：**收藏一次，永久可用**（正文解析 + 网页快照存档防失效）；「延展认知，不替思维代劳」。

### 2.2 平台矩阵
iPhone / iPad / Mac / Android / Web / 浏览器扩展（Chrome+Safari）/ 微信助手（公众号+转发）/ Widgets / Apple Watch。**无 Windows 桌面端**（CutShelter 机会点）。

### 2.3 收集能力（6.0 后从"网页收藏"扩展为"收集碎片"）
网页、网页片段、图片、语音、视频、速记（memo）、文件；微信转发文字/语音/视频；邮件速递（email-drop）；API 入库；iOS 快捷指令 / URL Schemes；RSS；IFTTT/Zapier；浏览器历史同步（"后悔药"，另一台电脑看过的网页也能找回收藏）。

### 2.4 解析与存储
- 自动识别文章并正文解析（广告/侧栏剥离），**文章解析名单**：按站点强制解析/不解析。
- 网页快照存档：原网页删除/修改后仍可回溯。
- 图片 OCR 转文字、语音/视频音轨转文字（成为检索原料）。
- 封面图自动提取、标签建议、重复收藏自动检测。

### 2.5 管理
嵌套收藏夹、嵌套标签、标签建议、**智能列表**（自定义规则自动筛选归类，支持全文搜索/阅读状态等条件）、高级搜索 + 全文搜索（快照与转写文本也可搜）。

### 2.6 阅读与标注
沉浸式阅读器（自定义字体样式）、多色高亮标注 + 想法笔记、**标注浮顶**（长文阅读时固定参考卡片）、**标注透视列表**（跨文章统一管理所有标注）。

### 2.7 AI（Pro+AI 会员，$69/年，1000 次/月；14 天试用）
- 自动解读：摘要、关键问题、**幻影高亮**（AI 自动标出精彩内容）。
- **Library Q&A**：对全库收藏提问，30 篇变 5 分钟简报。
- 主题关联、探索报告/知识报告。
- Reading Assistant：阅读中随时提问，支持 **BYOK（自接 OpenAI API Key）**，云不存 key。

### 2.8 回顾
每日回顾推送、Widgets、Apple Watch 提醒回顾标注重点。

### 2.9 导出与集成
Markdown / HTML / PDF / TXT 导出（含批量、标注、快照导出）；官方 Obsidian 插件、Notion、Readwise、FlowUs、Bear、Day One、Things 集成；精美图片分享标注。

### 2.10 开放生态（重点）
- **开放 API**：`POST https://cubox.pro/c/api/save/<token>`，JSON `{type:"url"|"memo", content, title, description, tags[], folder}`，会员 500 次/天。API link 同时授权 CLI 与 Obsidian 官方插件。
- **官方 cubox-cli**（Go，npm 分发）：文件夹/标签 CRUD、卡片过滤搜索（按文件夹/标签/星标/已读/已归档/时间范围）、**RAG 语义检索**、读取卡片全文（含标注与 AI 解读）、批量保存/归档/删除、标注跨卡搜索——本质是给 AI Agent 用的个人阅读记忆接口。
- AI Agent 授权：通过 API link 让外部 Agent 读写收藏库。

### 2.11 定价与口碑
Free 200 张卡片；Pro $39/年（无限 + 非 AI 功能）；Pro+AI $69/年。**仅年付无月付**——第三方评测点名的摩擦点。优势：本地化、收集广度、标注透视；劣势：无富文本编辑、无复杂笔记、无朗读、无社交/协作。

## 三、与 CutShelter 现状对比矩阵（差距分析）

| 能力域 | Cubox | CutShelter 现状 | 差距判定 |
|---|---|---|---|
| 收集入口 | 十余种（扩展/微信/邮件/API/快捷指令/RSS） | 桌面表单、浏览器扩展（右键/快捷键/弹窗）、截图贴图、TRAE 手机剪藏入库（mobile-clip → clip-storage） | 缺口：快捷指令、邮件速递、RSS、微信 |
| 内容类型 | 网页/片段/图/音/视频/速记/文件 | 文本 4 类剪辑 + 图片上传 + 截图 OCR | 缺口：语音/视频转写（有 OCR 无 ASR） |
| 正文解析 | 自动 + 站点解析名单 | 链接 AI 解析、文档解析 | 缺口：解析名单、正文提取器偏弱 |
| 快照存档 | 网页快照防失效 | 无（只存链接） | **真实缺口（核心价值）** |
| 标签/分类 | 嵌套夹、嵌套标签、标签建议 | 分类（二级）+ 标签 + AI 生成标签 | 缺口：嵌套、规则重组 |
| 智能列表 | 规则自动归类 | 工作台已有「规则与筛选」模块 + TODO「工作台规则与筛选」 | 底座已有，可对标补强 |
| 去重 | 自动检测重复 | 剪藏优化调研中列入（D5） | 待落地 |
| 阅读 | 沉浸阅读 + 标注 + 浮顶 + 透视 | 剪藏详情 + Markdown 预览 | 缺口：**标注体系** |
| 回顾 | 每日回顾/Widgets/手表 | 待办提醒、日报/周报邮件 | 部分覆盖 |
| AI | 解读 + Library Q&A（云端计次） | 自建多模型（DashScope/DeepSeek）+ Prompt 配置 + 发散总结/同义词/知识补充 + DSH agent | **差异化优势**：本地、自带 key、无计次；缺口：全库问答、解读 |
| 知识沉淀 | 导出 + Obsidian 官方插件 | 本地 vault + wikilink/反链 + 知识图谱（M3）+ Git 同步 + frontmatter 反写 | **CutShelter 更深** |
| 平台 | 全端（无 Windows） | Win/Mac/Linux 桌面 + 扩展 + 手机剪藏入口 | 缺口：移动端阅读/管理、无 Web 端 |
| 开放 | API + CLI + AI Agent 授权 | 本地 REST（8081）+ 扩展 + smart-ingest | 缺口：对外 API 包装、CLI、文档 |

**结论**：CutShelter 不必复制 Cubox 的"阅读器"，应坚持「剪藏 → 加工整理 → 归档 → 知识图谱」全链路 + 桌面全平台 + 本地模型的差异化；借 Cubox 验证过的方向补齐收集广度、智能列表、标注、回顾、开放 API 五个短板。

## 四、分方向开发建议

### 4.1 浏览器插件（browser-extension/，现状：background.js / content.js / popup / options 齐备）
1. **P1 网页高亮标注**：选中文字 → 高亮 + 笔记 → 入库剪藏（带回链 URL；已有高亮能力的 content.js 基础上扩展，产物走 `POST /api/clip/add`）。对标 Cubox 扩展的"智能捕捉/网页标注"，投入可控回报高。
2. **P1 保存时去重提示**：popup 保存前调后端查重（同上文 D5），提示"已收藏过 × 条"。
3. **P2 文章解析名单**：options 页新增 per-site 强制解析/不解析列表，content.js 提取前读名单。
4. **P2 速记入口**：popup 增加「速记」类型（对标 Cubox memo），5 秒写灵感。
5. **P3（暂不做）浏览器历史同步"后悔药"**：隐私敏感、实现重，不符合"轻量"偏好。
6. **P3（暂不做）搜索引擎结果注入 / 地址栏 'C' 搜索**：开发维护成本高。

### 4.2 App 端（用户点名分析；结论：不做原生客户端，走轻量路径）
现状：仅 TRAE 手机 APP 剪藏入库（mobile-clip skill，文本/URL/文件 → clip-storage JSON），无移动端读取/管理能力。
1. **P0 强化手机剪藏入口**：让 mobile-clip 入库内容支持标签/分类字段直通收件箱，与 smart-ingest 对齐（成本极低，两边 skill 已存在）。
2. **P1 移动端只读轻量 Web**：frontend/clip.html 已是静态页 + 8081 API 架构；输出响应式移动版只读页（列表 + 搜索 + 详情阅读，内网访问 + 简单 token），满足"路上回顾/阅读"，**借现有架构自然覆盖 Web 端缺口**。
3. **P2 邮件速递**：复用现有 SMTP/邮箱配置做"发邮件 → 入库"收信桥（对标 Cubox email-drop）。
4. **P3（明确不做）iOS/Android 原生客户端、微信公众号助手**：成本/收益不匹配；如需手机端抓取继续走 TRAE 手机剪藏 + 移动 Web。

### 4.3 桌面端剪藏模块补强
1. **P0 全库问答（Library Q&A 对标）**：底座使用进行中的「SQLite本地索引层M4（全库统一搜索）」；问答走已有 `synthesizeAnswer`（deepseek-v4-pro），在剪藏页与编辑器 AI 面板增加"询问我的剪藏库"入口。**这是 Cubox 最具吸引力 AI 能力且本软件已具备大部分底座。**
2. **P1 网页快照存档**：链接剪藏时抓取页面存 HTML/MHTML + 截图（复用截图能力），详情页提供"看快照"回退。弥补信息失效风险，与"归档"定位强契合。
3. **P1 智能列表**：复用工作台「规则与筛选」能力输出"剪藏智能列表"视图（按分类/标签/关键词/时间自动归类），对标 Cubox 智能列表。
4. **P2 剪藏标注（轻量版）**：详情页增加"摘录 + 想法"标注区块与全局标注透视列表（对标 Cubox 标注透视）；不做阅读器级浮顶。
5. **P2 回顾模式**：收件箱"每日回顾"入口（随机/按待读展示），复用待办提醒调度器机制。
6. **P3（暂不做）语音/视频转写**：本地 whisper 过重，外部 API 增加依赖，后续按需接 DSH。

### 4.4 AI 能力对标结论
- 已有优势保留：六方法走 PromptConfigService、多模型路由、DSH agent 干活。
- P1 自动解读增强：现有"摘要"升级为「摘要 + 关键问题 + 亮点摘录」（对标解读三件套），用 deepseek-v4-flash 控制成本，提供"新剪藏自动解读"开关（对标 Cubox 自动解读）。
- P2 主题关联/探索报告：基于知识图谱 M3 输出剪藏聚类周报。

### 4.5 平台开放与生态
1. **P1 入库 API 对外化**：`POST /api/clip/add` 已成熟，补齐：① API key 机制（对标 Cubox API link）；② 官方文档 + 示例（curl/Python/uTools/Quicker/iOS 快捷指令 HTTP 请求即可对接，无需公网服务）；③ 轻量 CLI（`npx` 分发，对标 cubox-cli 的 save 命令 + 搜索/列表只读命令）。
2. **P2 Cubox 互操作**：支持导入 Cubox 导出数据（Markdown/CSV）、提供全库 Markdown 导出（用户若并用 Cubox 可双向迁移）。
3. **P3（不单独做）官方 Obsidian 插件**：CS 与 Obsidian 同 vault 天然打通（wikilink 索引），只需输出"CutShelter ⇄ Obsidian 最佳实践"文档。

### 4.6 定位声明（写入报告）
- Cubox 的短板（无 Windows 端、仅年付、无富文本编辑、无本地模型）恰是 CutShelter 机会：**桌面全平台 + 本地优先 + 无订阅 + AI 模型自有**。
- 遵循既有产品原则：做核心好用的功能，太复杂的不做（用户长期偏好）。

## 五、落地路线图（优先序）

- **Phase A（立即施工）**：① 全库问答入口（依赖 M4，若 M4 未完成则先接现有搜索 + synthesizeAnswer 占位）；② 浏览器插件网页高亮标注 + 去重提示；③ 移动端只读页（clip.html 响应式变体）。
- **Phase B**：④ 网页快照存档；⑤ 剪藏智能列表；⑥ 入库 API key + 文档 + CLI；⑦ AI 解读三件套 + 自动解读开关。
- **Phase C**：⑧ 轻量标注与透视列表；⑨ 回顾模式；⑩ Cubox 导入/导出互操作；⑪ 邮件速递。
- **明确不做（写入报告防范围蔓延）**：原生移动客户端、微信助手、浏览器历史同步、搜索引擎注入、本地语音转写。

## 七、假设与决策点

- 假设：产品保持「本地优先、轻量、核心功能」定位与无订阅模式（依据用户长期偏好与项目记忆）。
- 决策：App 端不做原生客户端，走"手机剪藏入口强化 + 移动 Web 只读页"路径（若用户坚持原生 App，需另行立项讨论成本）。
- 决策：全库问答依赖 M4 索引进度，若未完工先降级接入现有搜索（报告中注明）。
