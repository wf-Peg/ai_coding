# 画布区「加载失败」修复方案

## 背景与现象

画布区无法加载，页面提示：

```
加载失败
请检查本地索引或后端服务是否正常
```

用户怀疑「画布区没开发完全」。经排查，画布功能本身已完整实现（便签/链接/图片/引用节点、手动连线、分组 frame、布局持久化、后端双向同步均已开发并提交），**真正原因是本地索引库的 schema 迁移存在缺陷，导致画布表从未创建，本地索引查询抛错**，前端回退 REST 请求后端时又不可用，最终走到错误分支。

## 根因分析（证据链）

### 1. 迁移函数版本跳级 bug（核心根因）

文件：`electron/sqlite/init.js`（`migrate()`，第 123-162 行）

```javascript
if (current < 3) {
  db.exec(SQL_V3);
  upsertMeta(db, 'schema_version', String(SCHEMA_VERSION));  // ← 写入 5，不是 3
  return;                                                    // ← 提前返回
}
if (current < 4) { /* SQL_V4 ... 写入 5 ... return */ }
```

对存量库做增量迁移时，`current < 3` / `current < 4` 分支把版本号**直接置顶为 SCHEMA_VERSION(5) 并提前 return**：

- 库在 v2 → 只执行 SQL_V3（canvas_layout），版本直接变 5，**SQL_V4（canvas_node / canvas_edge）和 SQL_V5（canvas_group / canvas_group_member）永远不执行**；
- 库在 v3 → 只执行 SQL_V4，版本变 5，V5 不执行。

### 2. 实库证据

真实索引库（当前配置 storagePath=`/Users/pengwenfeng/Documents/知识库/git知识库/Clip_Bed`，由 `~/.cut-shelter/config/config.json` 决定）：

```
schema_version|5          ← 已跳到 5
表清单：content / content_fts* / relation / canvas_layout / meta
       ← 没有 canvas_node / canvas_edge / canvas_group / canvas_group_member
```

即「版本号=5，但画布表缺失」的坏状态。

### 3. 运行时错误

`app.log`（第 2694 行）：

```
[ERROR] [local-index] error: Error: no such table: canvas_node
    at Object.listNodes (electron/sqlite/canvas-node.js:26:6)
    at Object.getGraph (electron/sqlite/graph.js:102:31)
    at ... (electron/main.js:2947:30)  // local-index:graph IPC handler
```

### 4. 前端错误路径

`frontend/canvas.js` `loadData()`：

1. 先走 `window.electronAPI.localIndex.graph({})` → IPC handler 抛「no such table」→ 被 `localIndexGuard`（main.js:2955-2958）捕获，返回 `{ success: false, message: 'no such table: canvas_node' }` → 前端 `res.success` 为假，`nodes` 保持 null；
2. 回退 `fetch('http://127.0.0.1:8081/api/graph')` → 后端未启动 / 无画布数据时失败 → 进入 `showEmpty('加载失败', ...)`。

### 5. 端口问题澄清（非本次根因）

- 真实配置 `~/.cut-shelter/config/config.json`：`backendPort=8081`，与前端硬编码 `http://127.0.0.1:8081` **一致**（日志 2682 行「Backend started successfully on port 8081」佐证）。
- 早前排查发现的 `~/Library/Application Support/clip-demo/config/config.json`（backendPort=8080）是**旧构建残留**，真实 userData 是 `~/.cut-shelter`（日志 2592 行），本应用不再使用。无需改动端口。

## 修复方案

只改两个文件：`electron/sqlite/init.js` 与 `electron/sqlite/db.test.js`。

### 变更 1：`electron/sqlite/init.js` — 重写 migrate() 为逐级顺序迁移 + 新增 v6 兜底修复

**为什么需要 v6**：坏库的 `schema_version` 已经是 5，即使把迁移逻辑改成顺序执行，`current=5` 时所有 `if (current < N)` 分支都不会进入，坏库无法被修复。因此新增 v6 迁移，重跑画布建表 SQL（全部 `CREATE TABLE IF NOT EXISTS`，幂等，健康库零副作用）。

**改法**：

1. `SCHEMA_VERSION` 由 `5` 改为 `6`（第 16 行）。
2. 在 `SQL_V5` 后新增：

```javascript
// v6 修复迁移：历史库在 v3/v4/v5 增量迁移时被「提前写入最高版本号 + return」跳级，
// 出现 schema_version=5 但画布表缺失的坏状态。重跑画布各层建表 SQL
//（全部 CREATE TABLE IF NOT EXISTS，幂等；健康库执行无副作用）。
const SQL_V6 = SQL_V3 + SQL_V4 + SQL_V5;
```

3. `migrate()` 整体替换为逐级顺序执行，**只在全部迁移完成后统一写一次最终版本号**：

```javascript
function migrate(db) {
  db.exec('CREATE TABLE IF NOT EXISTS meta (key TEXT PRIMARY KEY, value TEXT);');
  const row = db
    .prepare('SELECT value FROM meta WHERE key = ?')
    .get('schema_version');
  const current = row ? parseInt(row.value, 10) : 0;

  // 逐级执行所有未到位的迁移（各段 SQL 均为 CREATE TABLE IF NOT EXISTS，可重入幂等）
  if (current < 1) db.exec(SQL_V1);
  if (current < 2) db.exec(SQL_V2);
  if (current < 3) db.exec(SQL_V3);
  if (current < 4) db.exec(SQL_V4);
  if (current < 5) db.exec(SQL_V5);
  if (current < SCHEMA_VERSION) {
    // v6：兜底补齐缺失的画布表（修复旧实现跳级导致的坏状态）
    db.exec(SQL_V6);
    // 仅在全部迁移完成后统一写入最终版本号
    upsertMeta(db, 'schema_version', String(SCHEMA_VERSION));
  }
}
```

覆盖情况验证：

| 原版本 | 执行内容 | 结果 |
|---|---|---|
| 0（全新） | V1~V6 | 全部表 + version=6 |
| 2（旧库） | V3+V4+V5+V6 | 全部表 + version=6 |
| 3 | V4+V5+V6 | 全部表 + version=6 |
| 5（坏库，缺画布表） | V6（IF NOT EXISTS 补齐） | 画布表补齐 + version=6 |
| 5（健康库） | V6（无副作用） | version=6 |
| 6 | 无操作 | 不变 |

### 变更 2：`electron/sqlite/db.test.js` — 更新断言 + 新增坏库回归测试

1. 第 27-31 行「建库后 meta.schema_version 应为 5」改为断言 `'6'`。
2. 追加两个回归测试（放在文件末尾，模拟真实坏库后调用 `require('./init').migrate(db)` 验证自愈）：

```javascript
test('回归：schema_version=5 但缺画布表（真实坏库）应被 v6 补齐', () => {
  const { db } = makeDb();
  // 还原线上坏库状态：版本 5，画布四表缺失
  db.exec('DROP TABLE IF EXISTS canvas_node; DROP TABLE IF EXISTS canvas_edge; DROP TABLE IF EXISTS canvas_group; DROP TABLE IF EXISTS canvas_group_member;');
  db.prepare("UPDATE meta SET value='5' WHERE key='schema_version'").run();
  require('./init').migrate(db);
  const names = db.prepare(
    "SELECT name FROM sqlite_master WHERE type='table' AND name IN ('canvas_node','canvas_edge','canvas_group','canvas_group_member')"
  ).all().map((r) => r.name).sort();
  assert.deepEqual(names, ['canvas_edge', 'canvas_group', 'canvas_group_member', 'canvas_node']);
  const v = db.prepare("SELECT value FROM meta WHERE key='schema_version'").get();
  assert.strictEqual(v.value, '6');
});

test('回归：旧库 schema_version=2 增量迁移不应跳级', () => {
  const { db } = makeDb();
  db.exec('DROP TABLE IF EXISTS canvas_layout; DROP TABLE IF EXISTS canvas_node; DROP TABLE IF EXISTS canvas_edge; DROP TABLE IF EXISTS canvas_group; DROP TABLE IF EXISTS canvas_group_member;');
  db.prepare("UPDATE meta SET value='2' WHERE key='schema_version'").run();
  require('./init').migrate(db);
  const names = db.prepare(
    "SELECT name FROM sqlite_master WHERE type='table' AND name IN ('canvas_layout','canvas_node','canvas_edge','canvas_group','canvas_group_member')"
  ).all().map((r) => r.name).sort();
  assert.deepEqual(names, ['canvas_edge', 'canvas_group', 'canvas_group_member', 'canvas_layout', 'canvas_node']);
  const v = db.prepare("SELECT value FROM meta WHERE key='schema_version'").get();
  assert.strictEqual(v.value, '6');
});
```

## 验证步骤

1. **单测**：项目根目录执行 `node --test electron/sqlite/db.test.js`，全部用例通过（含新增 2 条回归）。
2. **重启应用**：彻底退出并重新启动应用（迁移在 `openDatabase` 时执行，DB 连接为单例，必须重启才生效）。
3. **实库核对**（重启后）：
   ```bash
   sqlite3 "/Users/pengwenfeng/Documents/知识库/git知识库/Clip_Bed/.index/app-index.sqlite" \
     "SELECT value FROM meta WHERE key='schema_version'; \
      SELECT name FROM sqlite_master WHERE type='table' AND name IN ('canvas_node','canvas_edge','canvas_group','canvas_group_member');"
   ```
   预期：`6`，且 4 张画布表全部存在。
4. **界面验证**：打开画布视图 → 不再出现「加载失败」；本地无画布数据时显示空态「暂无画布节点」，若后端存在画布快照则经 canvas-sync 恢复显示。
5. **功能验证**：右键空白处新建便签/链接/图片 → 节点落库（canvas_node 出现新行），拖动位置持久化（canvas_layout），重启后位置保留。

## 假设与决策

- 真实后端端口为 8081，与前端硬编码一致，**不做端口改动**；`clip-demo/config` 为废弃残留配置，不处理。
- 遗留的 `clip-storage/.index/app-index.sqlite`（v2）为旧配置产物，当前配置不再使用，**不做清理**（避免误删风险）。
- 本次只改 `init.js` 与 `db.test.js`，前端与 IPC 层无需改动（迁移修复后本地索引 IPC 即可正常返回画布数据）。
- v6 为幂等兜底迁移：对健康库只是无副作用的 `IF NOT EXISTS` 重放。
