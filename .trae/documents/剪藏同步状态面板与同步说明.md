# 剪藏页「同步仓库」优化：独立同步状态面板 + 同步说明 + 同步方案扩展接口

## Summary

参考 NoteGen 的极简信息面板风格，把剪藏页顶部散乱的「同步仓库」交互升级为一个**独立的「同步状态」面板**：集中展示所选同步方案、仓库连接状态、远程 URL / 分支、最近同步时间、以及**同步范围说明**（含剪藏 json / 周报 / tmp 等各存储路径）。

**核心扩展点**：为「同步/备份」设计一套**方案扩展接口**（`SyncProvider`），当前 Git 同步作为第一个实现接入；后续可按 NoteGen 的多同步方案路线接入更多方案（本地目录备份、WebDAV/坚果云、网盘、Obsidian 同步、对象存储等），前端面板会自动列出新方案，无需改动面板结构与说明区。

依据用户确认的三项决策：
- **呈现形态**＝独立「同步状态」面板（非并入 Git 配置弹窗、非内联说明条）。
- **同步范围**＝保持现状（继续 `git add .` 同步 `clip-storage` 父目录全部内容，含 tmp），**只新增说明性展示**，不改动现有同步行为。
- **预留扩展**＝本次只定义接口 + Git 实现 + 面板主框架，**不实现**其它同步方案。

不改变 Git 同步逻辑本身（pull/commit/push 分步结果已具备，见 [clip-sync.js](file:///f:/30_Projects%20(行动项目)/31_Work%20(主要工作)/ai_coding/frontend/js/clip-sync.js#L100-L131)），本方案聚焦「信息可见性 + 可扩展性」。

## Current State Analysis

- Git 同步工作目录是 `clip.storage.path` 的**父目录**（`剪藏_Obsdian`），`executeGitOperations(parentPath)` 对整个父目录执行 `pull → add . → commit → push`，因此父目录下所有内容都会入仓，包括：
  - `clip-storage/` → 剪藏数据（JSON）
  - `clip-organized/` → 日报总结（AI 整理产物）
  - `weeklyReport/` → 周报文件
  - `tmp/` → 临时文件（含 `{storagePath}/tmp/exception-logs/…` 异常日志、编辑器草稿等，见 [ExceptionLogWriter.java](file:///f:/30_Projects%20(行动项目)/31_Work%20(主要工作)/ai_coding/backend/src/main/java/com/example/clip/service/ExceptionLogWriter.java#L44)）
- [GitController.java](file:///f:/30_Projects%20(行动项目)/31_Work%20(主要工作)/ai_coding/backend/src/main/java/com/example/clip/controller/GitController.java#L66-L79) 已有 `POST /sync`（分步结果）、`GET /config`、`POST /config`、`POST /test-connection`，但**无**一个接口返回「同步范围 / 工作目录 / 最近同步时间 / 仓库是否初始化」，也**无**方案抽象。
- **命名冲突提醒**：`SYNC_API_BASE_URL=/api/sync` 已被 Web Clipper 同步占用（[clip-shared.js](file:///f:/30_Projects%20(行动项目)/31_Work%20(主要工作)/ai_coding/frontend/js/clip-shared.js#L12)）。新方案接口必须以其它前缀（如 `/api/sync-provider`）路由，避免冲突。
- 前端 `clip.html` 头部仅一个「🔄 同步仓库」按钮 + Git 配置弹窗（[clip.html](file:///f:/30_Projects%20(行动项目)/31_Work%20(主要工作)/ai_coding/frontend/clip.html#L185-L191)），`git-sync-result` 容器仅在同步后显示分步结果；**没有任何地方展示同步范围与存储路径说明**。
- 前端样式已用 `--app-*` 主题令牌映射（`--primary/--surface/--border/--radius`，见 [clip.css](file:///f:/30_Projects%20(行动项目)/31_Work%20(主要工作)/ai_coding/frontend/styles/clip.css#L4-L26)），`.git-sync-result` 系列 class 已存在（[clip.css](file:///f:/30_Projects%20(行动项目)/31_Work%20(主要工作)/ai_coding/frontend/styles/clip.css#L197-L256)），新面板样式沿用同一令牌体系（主题主蓝族，禁止导入新色相，符合项目约束）。

## Proposed Changes

### A. 后端：同步方案扩展接口（预留设计，核心）

新建包 `com.example.clip.service.sync`（与现有 `GitService` 解耦，但 Git 方案委托复用它）。

**文件 A1（新）：`service/sync/SyncProvider.java`（接口）**

```java
public interface SyncProvider {
    String getType();                    // 唯一标识，如 "git"
    String getDisplayName();             // 展示名，如 "Git 远程仓库"
    boolean isConfigured();              // 是否已配置/可用
    boolean isReady();                   // 目标仓库/目录是否就绪（如 .git 存在）
    SyncStatus getStatus();              // 状态快照（含 scope 说明 + lastSyncAt）
    SyncResult sync();                   // 执行同步，返回 ok/steps/message
    SyncResult testConnection();         // 连通性测试
}
```

- `SyncStatus`：`{ type, displayName, configured, ready, lastSyncAt, fields[] }`——`fields` 为载体相关参数（Git 用 `remoteUrl/branch/workingDir/dirs`），保证不同方案的差异收敛到各自 `fields`，前端通用渲染。
- `SyncResult`：`{ ok, message, steps[] }`，`steps` 沿用现有 `{ name, ok, files, message }` 结构，跨方案统一。

**文件 A2（新）：`service/sync/GitSyncProvider.java`（Git 方案实现）**
- `implements SyncProvider`，注入现有 `GitService` + `FileStorageService`。
- `sync()/testConnection()` 委托 `GitService.executeGitOperations(...)/testGitConnection(...)`；`getStatus()` 组装 `fields`（`remoteUrl/branch/workingDir/dirs`，`dirs` 由 `FileStorageService` 提供）。
- `getStatus()` 需取得最近提交时间：复用现有 `GitService.run(...)` 执行 `git log -1 --format=%ci`，本地时区格式化，无提交/无 `.git` 时 `lastSyncAt=null`。

**文件 A3（新）：`service/sync/SyncProviderRegistry.java`**
- 注入 `List<SyncProvider>`（Spring 自动收集所有 `SyncProvider` bean），暴露 `list()`、`getByType(type)`、`defaultProvider()`。
- 后续新增方案＝新增一个 `@Component implements SyncProvider` 即自动注册，前端面板自动列出。

**文件 A4（新）：`controller/SyncProviderController.java`**
- `GET /api/sync-provider/providers` → `[{type, displayName, configured, ready}]`（供面板渲染「同步方案」选择区，动态发现）。
- `GET /api/sync-provider/{type}/status` → `SyncStatus`（当下 Git 面板数据来源）。
- `POST /api/sync-provider/{type}/sync`、`POST /api/sync-provider/{type}/test-connection` → 分发到对应 provider（预留；Git 现有 `/api/git/sync` 保留为向后兼容，不删除）。

> **不迁移既有**：保留 `GET/POST /api/git/config`（Git 专用配置）与 `POST /api/git/test-connection`；`POST /api/git/sync` 暂保留（前端同步按钮仍可走它），新面板状态走 `GET /api/sync-provider/git/status`。避免破坏现有功能，才是真正的“预留”而非“重写”。

**文件 A5：`FileStorageService.java`（补充能力）**
- 新增 `Map<String,Object> getSyncDirs()`：把 `storagePath`（剪藏）、`organizedStoragePath`（日报）、`weeklyReportPath`（周报）、`storagePath/tmp`（临时）解析为 `{name, path, exists}` 列表；未注入的空路径项跳过。补齐所需 getter（`getStoragePath()` 已有；`organizedStoragePath`、`weeklyReportPath` 若无 getter 则加）。

### B. 前端：独立「同步状态」面板

**文件：`frontend/clip.html`**
- 在头部「同步仓库」`action-split-group` 内新增信息按钮（图标优先）：`<button class="icon-btn" id="sync-info-btn" title="同步说明与状态" onclick="toggleSyncPanel()">ℹ️</button>`。
- 在 `git-sync-result` 后新增 `#sync-status-panel`（默认 `hidden`）：
  - **同步方案**：展示当前方案（`displayName`）+ 预留占位“更多方案即将支持”。渲染由 `providers` 列表动态生成，未来新增方案自动出现。
  - **连接状态**：badge（已配置远程 / 仅本地提交 / 未初始化）+ 最近同步时间。
  - **同步范围说明**：标题「同步范围说明」，逐行列出 `dirs`（`name` + 全路径 + 中文说明），路径等宽可复制。
  - 关闭按钮 + tmp 附注“程序运行产物，通常无需手动编辑”。

**文件：`frontend/js/clip-sync.js`**
- 新增 `toggleSyncPanel()`；新增 `loadProviders()`（`GET /api/sync-provider/providers`）与 `loadSyncStatus()`（`GET /api/sync-provider/git/status`），用 DOM API / `escapeHtml` 渲染，避免 XSS：
  - `ready=false` → “仓库尚未初始化（缺少 .git）”。
  - `configured=false` → “仅本地提交（未配置远程）”。
  - `lastSyncAt=null` → “暂无提交记录”。
  - 接口失败 → 降级提示，不阻塞页面。
- 面板主状态入口走 `loadSyncStatus()`；`syncGit()` 成功后与页面加载初始化处调用，保证实时。
- **预留一个前端 provider 渲染层**：`providers` 数组 → 每个方案有 `name+fields 渲染器` 的 registry（Object map），当前仅 Git；新增方案时前端加一个渲染器即可，面板主框架不动。

**文件：`frontend/styles/clip.css`**
- 新增 `.sync-status-panel` 系列，仅消费 `--app-*`/`--primary/--surface/--border/--radius` 令牌（主蓝族）：面板卡片、状态 badge、路径行（等宽 + `--text-muted`）、折叠动画复用现有 transition。

### C. 组装
- 进入剪藏页自动预取 `loadProviders()` + `loadSyncStatus()`（数据缓存，不主动弹窗）。
- 「同步仓库」按钮逻辑保持（`syncGit()` 不变）；新增信息按钮触发面板。

## 扩展路径（后续新增同步方案示例，非本轮实现）

| 方案 | 实现方式 | 说明 |
|---|---|---|
| 本地目录备份 | 新 `LocalBackupSyncProvider` | 定时/手动整目录拷贝到指定备份路径，`SyncStatus.fields` 换成源/目标路径 |
| WebDAV / 坚果云 | 新 `WebDavSyncProvider` | 增量上传改动文件，`fields` 含 server/路径/账号 |
| 网盘（OneDrive/Dropbox） | 新 `NativeCloudSyncProvider` | 依赖系统已同步文件夹，提供“纳入同步”开关 |
| Obsidian 同步 | 复用 vault 链路 | `.obsidian` 已在同步范围内，方案层标记即可 |

新增步骤：① `@Component implements SyncProvider` 注册；② 提供 `SyncStatus` 的 `fields` 与前端渲染器（`PROVIDER_RENDERERS[type]`）；③ 面板自动发现。**本轮不做**以上任何一项。

## Assumptions & Decisions

- **不改动同步逻辑**：`git add .` 同步父目录全部内容（含 tmp），面板只做如实说明（用户已确认“保持现状”）。
- **接口命名避开 `/api/sync`**：新方案路由用 `/api/sync-provider/...`。
- **预留而非重写**：保留 `/api/git/sync|config|test-connection` 向后兼容；新面板状态走 provider 抽象。`SyncProvider` 是新增抽象层，不为对齐它而改动现有 Git 同步命令逻辑。
- **数据来源**：路径由后端动态返回，前端不硬编码绝对路径。
- **最近同步时间**＝`git log -1` 提交时间；无提交时展示“暂无提交记录”。
- **仅实现 Git**：其它方案只留接口与示例，不实现（范围克制）。
- **接口失败降级**：面板显示降级文案，不阻塞页面。
- **遵循项目规范**：所有改动补日志与注释；维持主蓝族主题色相。
