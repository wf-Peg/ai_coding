# 优化应用退出：后端强杀 + 非阻塞索引落盘 + 丝滑关闭动画

## Summary

解决 CutShelter 关闭响应慢、退出不够丝滑的问题。核心改动三块：

1. **后端立刻强杀**：`stopBackend()` 从「SIGTERM → 等3秒 → SIGKILL」改为「立刻 kill -9 / taskkill /F /T」；
2. **退出逻辑幂等**：`quitApp()` / `before-quit` / `will-quit` 三处重复执行 stop 系列，收敛为单一幂等入口；
3. **非阻塞索引落盘**：`will-quit` 里同步的 SQLite `optimize` + `wal_checkpoint(TRUNCATE)` 改为轻量 `PASSIVE` checkpoint（只刷已提交页，通常毫秒级），不再阻塞进程退出。

外加关闭弹窗/窗口的入场与退场淡入淡出动画，提升退出「丝滑」感。

***

## Current State Analysis

基于对 `electron/main.js` 的实测阅读：

### 1. 退出有三处几乎重复的 stop 序列

- `quitApp()`（[main.js L2339-2375](file:///f:/30_Projects%20\(行动项目\)/31_Work%20\(主要工作\)/ai_coding/electron/main.js#L2339-L2375)）：同步执行 `stopBackend(); stopFrontendServer(); stopDshAgent();` 后 `app.quit()`。

- `before-quit`（[main.js L4841-4850](file:///f:/30_Projects%20\(行动项目\)/31_Work%20\(主要工作\)/ai_coding/electron/main.js#L4841-L4850)）：又调用 `stopBackend()+stopFrontendServer()+stopDshAgent()`。

- `will-quit`（[main.js L4853-4864](file:///f:/30_Projects%20\(行动项目\)/31_Work%20\(主要工作\)/ai_coding/electron/main.js#L4853-L4864)）：再次调用三者，并同步执行 `localIndexService.close()`。

即一次退出，`stopBackend` 等逻辑最多执行 3 轮，每轮都会 `netstat`/`taskkill`（`execAsync`），重复开销明显。

### 2. 后端优雅关闭 + 3 秒等待（慢的关键）

`stopBackend()`（[main.js L905-942](file:///f:/30_Projects%20\(行动项目\)/31_Work%20\(主要工作\)/ai_coding/electron/main.js#L905-L942)）：

- 先 `backendProcess.kill('SIGTERM')` 优雅关闭；

- `setTimeout(…, 3000)` 3 秒后才 `SIGKILL`；

- 另有 1 秒端口清理定时器。

Windows 上 `child.kill()` 本身即 TerminateProcess，早已是强杀；但 macOS/Linux 上 SIGTERM 会走 Spring Boot 优雅关闭，可能等待在途异步 AI 任务/调度器而卡住，用户感知「关闭久」。用户诉求：项目无关键数据，后端可直接强杀。

### 3. 索引库同步落盘阻塞退出

`will-quit` 调用 `localIndexService.close()`（[index-service.js L184-189](file:///f:/30_Projects%20\(行动项目\)/31_Work%20\(主要工作\)/ai_coding/electron/sqlite/index-service.js#L184-L189)）→ `db.closeDatabase()`（[db.js L66-71](file:///f:/30_Projects%20\(行动项目\)/31_Work%20\(主要工作\)/ai_coding/electron/sqlite/db.js#L66-L71)），内部同步执行 `optimize()`（扫描全库）+ `PRAGMA wal_checkpoint(TRUNCATE)`（手动 WAL 落盘）。这是 **will-quit 的同步阻塞点**，大库下可耗时数百毫秒\~数秒，是「退出慢」最可能的实锤。

### 4. 关闭弹窗无动画

[main.js L1908-2018](file:///f:/30_Projects%20\(行动项目\)/31_Work%20\(主要工作\)/ai_coding/electron/main.js#L1908-L2018) 的关闭确认弹窗：`ready-to-show` 后直接 `show()`，卡片无入场动画；点「退出程序」直接 `quitApp()` 立即消失，无退场动画；主窗口无淡出，一瞬间「啪」断掉。

## Proposed Changes

### Change 1 — 后端立刻强杀 + 幂等守卫（`electron/main.js`）

- 新增模块级守卫（放在 `let backendProcess` 声明附近）：

  ```js
  let backendStopInFlight = false; // 后端强杀只执行一次
  ```

- 重写 `stopBackend()`（L905-942）：

  - 开头：`if (backendStopInFlight) return; backendStopInFlight = true;`

  - 有 `backendProcess` 时**立即**强杀（去掉 3 秒 SIGTERM 阶梯与 1 秒端口定时器）：

    - Windows：`exec('taskkill /F /T /PID ' + backendProcess.pid)`（`/T` 连子树一起强杀，防 Java 子进程残留）；随后 `backendProcess = null`。

    - macOS/Linux：`backendProcess.kill('SIGKILL')` 直接强杀。

  - 结尾仍保留 `killPortProcess(backendPort)` / `killPortProcess(frontendPort)` 作为僵尸进程兜底（尽力而为，非阻塞）。

  - 全部 `try/catch` + 日志（遵守项目「代码加日志注释」约定）。

- `startBackend()` 内 `backendProcess = spawn(...)` 处重置 `backendStopInFlight = false`（兼容重启场景，即便本机极少发生）。

### Change 2 — 收敛三处 stop 为单一幂等入口

- 新增模块级 `let shutdownStarted = false;`。

- 新增：

  ```js
  function beginShutdown() {
    if (shutdownStarted) return;
    shutdownStarted = true;
    stopBackend();
    stopFrontendServer();
    stopDshAgent();
  }
  ```

- `quitApp()` 中把三行 stop 调用替换为 `beginShutdown();`。

- `before-quit` 与 `will-quit` 中的三行 stop 也替换为 `beginShutdown();`（幂等，重复触发不再二次 netstat/taskkill）。

- 注释说明：无论从哪个入口退出，后端/前端/DSH 只收停一次，避免重复端口扫描。

### Change 3 — 索引库关闭改为非阻塞轻量落盘

- 在 `electron/sqlite/index-service.js` 的 `close()` 中，将同步繁重的 `db.closeDatabase()`（内含 `optimize()` + `wal_checkpoint(TRUNCATE)`）替换为轻量关闭路径。

- 具体：新增/复用 `db.js` 一个 `closeFast()`（或修改 `closeDatabase` 的调用参数）：

  - 保留 `stopMaintenance()`（停掉 unref 的维护定时器）。

  - 不再执行 `optimize()`（扫描全库，重）；

  - 仅执行 `PRAGMA wal_checkpoint(PASSIVE)`（只刷已提交页，通常毫秒级，不阻塞）。

  - 然后 `try { dbInstance.close(); } catch {}`。

- 说明（写进注释）：`better-sqlite3` 每条语句本就同步提交至 WAL，退出时残留的 `-wal`/`-shm` 在下次打开时由 SQLite 自动恢复，不会损坏数据；PASSIVE checkpoint 足够把已提交数据刷主库，避免感知到的「退出卡顿」。

- 若 `closeFast` 仍需同步阻塞（better-sqlite3 是同步 API），因其只做 PASSIVE checkpoint（毫秒级）+ 无全库扫描，对退出时延的影响可忽略。

### Change 4 — 关闭弹窗 + 主窗口「丝滑」动画

**4a. 关闭确认弹窗入场动画**（`showCloseDialog` 的 HTML，L1985-2018）：

- 给 `.card` 加入场动画：

  ```css
  @keyframes cardIn { from { opacity: 0; transform: translateY(6px) scale(.97); } to { opacity: 1; transform: none; } }
  .card { animation: cardIn .22s ease-out; }
  ```

- 按钮增加按压力反馈：`.btn:active { transform: scale(.97); }`。

**4b. 弹窗退场动画（退出/托盘）**（L2012-2017 的 `choose()`）：

- 把 `choose()` 改为先播放退场再收尾：

  ```js
  function fadeOut(done) {
    const card = document.querySelector('.card');
    card.style.transition = 'opacity .16s ease-in, transform .16s ease-in';
    card.style.opacity = '0'; card.style.transform = 'scale(.98)';
    setTimeout(done, 160);
  }
  function choose(action, remember) {
    fadeOut(() => { window.dialogApi.choose(action, remember); window.close(); });
  }
  ```

  顶部 `close-btn`（取消）不播退场，直接 `window.close()`。

**4c. 主窗口退场淡出 + 最小化到托盘淡出**（`electron/main.js`）：

- 新增辅助函数，利用 Electron 原生 `BrowserWindow.setOpacity`（macOS 恒支持、Windows 支持、Linux 不支持）实现 GPU 淡出：

  ```js
  function fadeOutWindow(win, ms, done) {
    if (!win || win.isDestroyed() || process.platform === 'linux') { done && done(); return; }
    const steps = 12, step = ms / steps;
    for (let i = 1; i <= steps; i++) {
      setTimeout(() => { if (!win.isDestroyed()) win.setOpacity(1 - i / steps); }, i * step);
    }
    setTimeout(done, ms);
  }
  ```

- `quitApp()`：开头判断 `if (shutdownStarted) return; shutdownStarted = true;`（与 Change 2 共用同一 flag），最后 `app.quit()` 前先把「销毁托盘/注销菜单/停更新/停提醒/清理临时窗口」等**同步快速**步骤执行完，再：

  ```js
  fadeOutWindow(mainWindow, 180, () => { beginShutdown(); app.quit(); });
  ```

  说明：由于 Change 1/2/3 已让 stop 变成非阻塞，180ms 淡出期间系统无阻塞，退出视觉丝滑。

- 最小化到托盘分支（L2167 close 事件与 L2126 modal 关闭后的 `parent.hide()`）改为先 `fadeOutWindow(win, 160, () => win.hide())`，托盘隐藏也带淡出。

**4d. 顺手统一其他退场窗口**（若改动面小）：

- `destroyTransientToasts` 涉及的气泡窗口如仅 `close()`，不动；若要动画统一，单独评估，避免范围失控。本轮不强推。

## 涉及文件

- `electron/main.js`：`backendStopInFlight`、重写 `stopBackend()`、新增 `beginShutdown()`/`shutdownStarted`、改 `quitApp()`/`before-quit`/`will-quit`、新增 `fadeOutWindow()`、`showCloseDialog` 的 HTML/CSS/JS、托盘隐藏淡出。

## Assumptions & Decisions

- **数据安全取舍**：用户确认项目无关键数据，故（a）后端直接强杀，允许在途 AI/同步任务未落库；（b）索引库退出跳过 `optimize`，仅 PASSIVE checkpoint；残留 WAL 由 SQLite 下次打开自动恢复。

- `BrowserWindow.setOpacity` 仅用于非 Linux（Linux 不支持），其余平台走原生 GPU 淡出；DOM 前缀用的是弹窗内部卡片动画（透明窗口渲染层内），不依赖系统窗口透明度。

- `shutdownStarted` 语义：进程生命周期内只允许一次完整关闭，天然防三入口重复触发。
