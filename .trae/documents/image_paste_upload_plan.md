# 图片粘贴和上传功能实现计划

## 1. 仓库研究结论

通过分析当前代码结构，我发现：

- **前端**：默认的Vite + React项目，还没有实现剪藏功能
- **后端**：已经实现了图片存储功能，支持接收Base64编码的图片数据并存储到指定路径
- **需求**：需要在前端实现图片粘贴和上传功能，生成Markdown格式的图片引用

## 2. 前端实现计划

### 2.1 核心功能
1. **剪藏内容输入框**：支持文本输入和图片粘贴
2. **图片预览**：在输入框下方显示粘贴/上传的图片缩略图
3. **图片上传**：支持手动上传图片
4. **Markdown引用**：自动在内容中生成Markdown格式的图片引用
5. **分类选择**：用于后端存储路径的生成

### 2.2 技术实现

#### 2.2.1 组件结构
- `ClipForm`：剪藏表单组件
  - `ContentInput`：内容输入框（支持图片粘贴）
  - `ImageUploader`：图片上传组件
  - `CategorySelector`：分类选择器
  - `TypeSelector`：剪藏类型选择器
  - `SubmitButton`：提交按钮

#### 2.2.2 关键功能实现

1. **图片粘贴功能**
   - 监听输入框的`onPaste`事件
   - 从剪贴板获取图片数据
   - 转换为Base64编码
   - 生成唯一文件名
   - 显示图片缩略图
   - 在内容中插入Markdown格式的图片引用

2. **图片上传功能**
   - 实现文件选择功能
   - 读取文件并转换为Base64编码
   - 生成唯一文件名
   - 显示图片缩略图
   - 在内容中插入Markdown格式的图片引用

3. **文件名生成**
   - 格式：`file-${date:{momentJsFormat:'YYYYMMDDHHmmssSSS'}}-${index}.${图片格式}`
   - 其中`index`为图片序号，从1开始

4. **Markdown引用生成**
   - 格式：`![图片](assets/${noteFileName}/file-${date}-${index}.${格式})`
   - 其中`noteFileName`基于分类生成

5. **分类处理**
   - 从后端获取分类树
   - 实现分类选择器
   - 根据选择的分类生成`noteFileName`

### 2.3 数据流

1. 用户在输入框中输入文本或粘贴图片
2. 图片被转换为Base64编码并生成唯一文件名
3. 图片缩略图显示在输入框下方
4. Markdown格式的图片引用被插入到内容中
5. 用户选择剪藏类型和分类
6. 点击提交按钮，将内容、类型、分类、图片数据发送到后端
7. 后端存储图片并返回存储路径
8. 前端更新图片引用为最终的存储路径

## 6. 潜在问题和解决方案

### 6.1 潜在问题
- **图片大小限制**：大图片可能导致上传失败
- **Base64编码长度**：长Base64字符串可能导致请求失败
- **浏览器兼容性**：不同浏览器的剪贴板API可能不同
- **文件名冲突**：可能出现文件名重复的情况

### 6.2 解决方案
- **图片大小限制**：在前端添加图片大小检查，限制最大图片大小
- **Base64编码处理**：确保后端能够处理长Base64字符串
- **浏览器兼容性**：使用兼容性较好的剪贴板API实现
- **文件名冲突**：使用时间戳+序号的方式确保文件名唯一
