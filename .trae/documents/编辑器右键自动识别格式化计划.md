# 编辑器右键「自动识别格式化」功能计划

## 摘要
在编辑器画布右键菜单新增「🧹 格式化」入口，**无视右上角文本类型下拉框**，自动识别（或依次尝试 JSON/XML/SQL）内容类型并格式化；支持仅格式化选中区域（无选中则格式化全文）。

## 现状分析
- 现有格式化入口为工具栏按钮 `#formatBtn`（`Ctrl+L`），走 [editor.js](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/frontend/js/editor.js#L957) 的 `formatCurrentContent()`，**依赖**右上角 `elements.languageSelect.value`（仅 json/xml/sql），否则提示"请选择 JSON、XML 或 SQL 模式"。
- 工具类 [editor-core.js](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/frontend/js/editor-core.js#L19-L111) 已提供 `detectLanguage`、`formatJson`、`formatXml`、`formatSql`、`extractErrorLocation`，可复用。
- 右键菜单 [editor.html](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/frontend/editor.html#L467-L492) 结构：`编辑操作` 段（已有 `joinLineEndsContextBtn`）→ 分隔线 → AI → 翻译 → 词典。菜单动作经 `data-context-action` → `executeEditorContextAction()` 分发（[editor.js](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/frontend/js/editor.js#L1914-L1934)）。
- `/编辑操作` 段按钮默认始终可见（2161-2167 只隐藏 AI/翻译/词典按钮），新按钮随默认显示。

## 变更方案

### 1) 新增右键菜单项 — `frontend/editor.html`
在「编辑操作」段，紧跟 `joinLineEndsContextBtn`（L473）后新增：

```html
<button type="button" data-context-action="format" role="menuitem" id="formatContextBtn"
        title="自动识别 JSON/XML/SQL 并格式化，忽略右上角文本类型">🧹 格式化（自动识别）</button>
```

### 2) 挂载元素引用 — `frontend/js/editor.js`
在 elements 数组 L94 追加 `'formatContextBtn'`。

### 3) 分发动作 — `frontend/js/editor.js` `executeEditorContextAction`
在 `joinLineEnds` 分支附近新增：
```js
if (action === 'format') { formatCurrentContentAuto(); return; }
```

### 4) 新增自动识别格式化函数 — `frontend/js/editor.js`
新增 `formatCurrentContentAuto()`（放在 `formatCurrentContent` 附近），逻辑：

1. 取选区/全文：`const target = getTargetRangeAndText();`（含 5MB 上限拦截与 `MAX_TRANSFORM_LENGTH` 校验，复用现有 `formatCurrentContent` 的校验方式）。
2. **候选语言排序**（无视下拉框）：
   - `detected = EditorCore.detectLanguage(state.fileName, target.text)`
   - 候选数组按 `[detected, 'json', 'xml', 'sql']` 去重（detectLanguage 对空文本返回 text）。
3. **依次尝试**：对每个候选调用对应 formatter（`formatJson/formatXml/formatSql<any>`），首个成功即用；记录命中的类型。
4. **行尾换行合并兜底**：若候选全失败，执行 `target.text.replace(/\r\n|\r|\n/g,'')` 合并截断行后，重复第 2、3 步重试一次。
5. **提交通知**：`mainEditor.session.replace(target.range, formatted)`；`showToast(...)` 提示"选区/全文 已按 X 格式化（自动识别）"。不修改右上角 `languageSelect`（满足"无视右上角类型"）。
6. **全部失败**：`EditorCore.extractErrorLocation` 提取错误，`showToast` 报错；`FrontendLogger.warn` 记录。
7. （可选增强）命中类型为 sql 时用 `'sql'` 方言。

> 实现提示：可抽一个 `tryAutoFormat(text)` 辅助函数（返回 `{ type, value }` 或 `{ error }`），供本函数内部两次调用（原文 + 合并换行后），避免重复代码。

## 假设与决策
- 不改变右上角下拉框选中态（需求：无视右上角类型）。
- 不修改现有 `Ctrl+L`/工具栏 `formatBtn` 行为，仅新增右键入口，避免回归。
- 右键入口对新旧内容一视同仁，始终可见。
- 选区优先：有选区只格式化选区，无选区格式化全文（与现有 `getTargetRangeAndText` 语义一致）。

## 验证
1. `node --check frontend/js/editor.js` 语法通过。
2. 前端静态服务（3001）返回 200，加载 editor.html / editor.js 无控制台报错。
3. 手动场景：
   - 打开含 JSON 的 `.txt`（右上角设为 text），右键 → 格式化 → 正确美化 JSON 且下拉框不变。
   - 选中 XML 片段 → 右键 → 仅选区被格式化。
   - SQL 内容自动识别并按 SQL 格式化。
   - JSON 但被客户端截断成多行（每行尾有换行）→ 自动合并并格式化成功。
   - 纯普通文本（如英文句子）→ 提示格式化失败，不崩溃。
