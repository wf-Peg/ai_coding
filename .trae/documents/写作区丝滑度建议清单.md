## 三、流畅性建议点

### A. 输入响应（打字不卡、不跳）

**A1. 中文输入法友好（composition 期间暂停一切"跟随"任务）** · P0 · 小
- 现状：中文输入时每敲一个拼音字母都会触发 `change` → 预览渲染、字数统计、自动补全、反链刷新，候选框易跳动/闪烁。
- 建议（借鉴：Notepad++ 输入法与编辑区零冲突）：监听 `compositionstart`/`compositionend`，期间跳过 Markdown 预览渲染、状态栏字数统计、自动补全触发，`compositionend` 后再补一次。
- 方案要点：在 [editor.js](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/frontend/js/editor.js#L4213) 的 `session.on('change')` 及各防抖调度处加组合态判断。

**A2. 大文件关闭自动补全** · P1 · 小
- 现状：大文件降级只关了 worker/wrap/选中词高亮，`enableBasicAutocompletion` / `enableLiveAutocompletion` 仍在，键入时实时补全在 >2MB 文件上明显拖慢。
- 建议：>2MB 时 `setOption('enableLiveAutocompletion', false)`（保留手动触发），恢复时还原。

**A3. Markdown 预览"自适应防抖"** · P2 · 小
- 现状：固定 300ms 防抖。
- 建议：连续击键时把防抖拉长到 500ms，停顿 200ms 即渲染，兼得响应与性能（轻量实现：比较两次 change 间隔决定下一轮延时）。

**A4. 状态栏更新合并到帧** · P2 · 极小
- 现状：[updateCursorStatus](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/frontend/js/editor.js#L3787) 由 `changeCursor` + `changeSelection` 直接触发，高频移动/拖选时反复写 DOM。
- 建议：用 `requestAnimationFrame` 合并到一帧内只更新一次。

### B. 滚动与跟随（写作区最直接的"丝滑"）

**B1. Markdown 预览滚动同步（跟随模式）** · P0 · 中
- 现状：编辑区与预览各自独立滚动，写作时无法对照"正在写的内容在预览哪一段"，体验割裂。现有 `changeScrollTop` 只服务于概览（Overview Ruler），**未接入预览**。
- 建议（借鉴：Typora / Notepad++ 双栏写作、UltraEdit HTML 预览联动）：编辑区滚动时按滚动比例同步预览滚动；提供"跟随"开关（状态栏或预览头部小按钮），默认开。
- 方案要点：在 [editor.js](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/frontend/js/editor.js#L6716) 的 `changeScrollTop` 处理器上扩展：仅当 Markdown 预览打开且"跟随"开启时，按 `scrollTop/maxScrollTop` 比例设置 `markdownBody.scrollTop`（需互相抑制死循环）。已具备的分屏/全屏布局不变。

**B2. 预览点击反向定位（可选）** · P2 · 中
- 在预览点击段落标题/内容 → 编辑区定位到对应行（配合 B1 形成双向联动，Obsidian 阅读模式有类似体验）。

**B3. 超长行渲染优化** · P1 · 中
- 现状：单行无换行符的超长行（如粘贴的压缩 JSON/日志）会拖慢 ACE 渲染与滚动。
- 建议（借鉴：Notepad++/UE 对长行均有专门处理）：检测到超长行（如 >8k 字符/行）时临时开启 wrap 或提示"已进入长行模式"，避免横向滚动卡顿。

### C. 操作反馈（及时、不打扰）

**C1. 自动保存成功提示静默化（收尾）** · P2 · 极小
- 现状：防抖 2s 保存、失焦保存、失败 Toast **已实现**；剩余唯一缺口是成功路径仍闪烁"保存中.../已自动保存"文字。
- 建议：成功时不改文字（状态栏用一个小状态点微变化即可），仅失败时 Toast。

**C2. 大文件打开不阻塞** · P1 · 中
- 现状：读大文件后一次性 setValue，界面可能短暂无响应。
- 建议：打开时显示"正在打开…"轻提示，分块写入 + 完成后一次性 resize；利用现有编辑器缓存与恢复逻辑做加载态过渡。

**C3. 搜索高亮上限** · P1 · 小
- 现状：ACE searchbox 全文档匹配高亮在超大文件上可能卡顿。
- 建议：>5MB 时限制高亮匹配数或临时关闭实时高亮（保留结果跳转）。

**C4. 面板动效统一** · P2 · 小
- 现状：反链/大纲/标签全屏悬浮层已带 0.65 透明度与过渡，但部分非全屏抽屉切换仍有硬切感。
- 建议：统一抽屉进出场的过渡时长与缓动曲线（共用 CSS 变量），补齐交互一致性。

### D. 借鉴 Notepad++/UltraEdit 的轻量体验细节（低成本、感知强）

**D1. 中键关闭标签** · P0 · 极小
- 现状：标签只能点 × 关闭；**双击空白新建已存在**，勿重复做。
- 建议：补中键（`auxclick` button=1）关闭标签，未保存走既有确认逻辑（Notepad++ 行为）。

**D2. 行号区点击 = 选中整行** · P2 · 极小
- 现状：行号 gutter 已有"点击跳转语法错误红点"交互，需共存。
- 建议（Notepad++ 行为）：无错误标记的行点击行号 = 选中整行（拖拽连续选择）；有错误红点的行仍优先跳转错误。

**D3. 状态栏补"总行数/字符数 + 缩放百分比"** · P1 · 小
- 现状：状态栏有行/列、选中字符、语言、Tab 大小，但无全文篇幅与缩放比例。
- 建议（Notepad++/UE 均有）：追加"L: xxx  C: xxx"与"100%"两项（Ctrl+滚轮缩放后即时更新），写作时便于感知篇幅与字号状态。

### E. 键盘与开关响应细节

**E1. 全屏/预览切换后 resize 改 ResizeObserver** · P2 · 小
- 现状：[toggleFullscreen](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/frontend/js/editor.js#L5280) 与 Markdown 预览切换用 `setTimeout(resize, 100)` 兜底，进出瞬间可能有半帧错位。
- 建议：用 ResizeObserver 监听容器尺寸变化立即 `editor.resize()`，消除闪烁。

**E2. 命令面板/快速切换输入防抖** · 可略
- 现状：已用 rAF 渲染列表（[8443](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/frontend/js/editor.js#L8443)、[8646](file:///l:/归档/30_Projects%20(行动项目)/31_Work%20(主要工作)/code/ai_coding/frontend/js/editor.js#L8646)），体验已达标。
- 结论：**不做**，避免重复开发。
