一、参赛者介绍

我是一名非技术背景的AI爱好者。侥幸进入复赛，这次参赛作品 Foclip 是我围绕一个真实痛点、用 TRAE 从零打磨出来的完整产品。

我平时的工作场景是"高频地在网页与 AI 之间来回切换"：比如看到很好的文字内容、用户的评论评价、招聘网站的求职信息、好的构图海报、酷炫的前端特效……这些动作如果都靠手动的「复制 → 切换 → 粘贴」，既浪费时间又容易丢格式。

初心很简单，我就是想做一个减少选择内容的时间，可以替代ctrl+c/v的工具。

二、产品简介

2.1 它是什么

Foclip 是一款 Chrome 浏览器扩展，定位是网页内容的 「拾取 → 加工 → 分发」工作站：把网页里你想用的内容，一键抓下来、随时整理、再精准投递给 AI 或本地文件。

image2560×1186 280 KB

它解决的核心问题是：从网页复制内容到 AI 时，格式丢失、整理耗时、反复切换。与爬虫类工具不同，它不追求"抓全"，而是让你精准选中真正想要的那一块，并以完整、可用的形态拿出去。

2.2 面向谁

内容创作者：从社区、论坛提取内容喂给 AI 提问或二次创作；

高频使用 Web 的上班族：需要把网页内容、截图快速转给 AI 的任何人。

学生 / 研究者：整理论文、长文、表格，让 AI 总结或理解页面结构；

四、产品创作历程

灵感来源。 最初是某次在 TRAE 里看到一大段内容，想整理成素材发给 AI，却发现"全选复制会带进一堆无关内容，鼠标拖动又很慢"。于是我想做一个"点一下就能把想要的网页内容喂给 AI"的东西。

初赛 Demo。 先用 TRAE 搭起了扩展骨架，跑通了"识别 → 复制 → 跳转 AI 平台填入"这一条核心链路。当时它能用，但只是个"能演示的雏形"。

复赛完整作品。 打磨过程中，我陆续踩过并解决了几类关键问题：

识别精度：最初只能选中单段落，在论坛页面上分不清"发帖人"和"评论"。后来引入内容密度算法，从点击位置向上推断"内容块"边界，让识别从"单段落"升级为"内容块"，并发展出元素 / 帖子 / 内容块 / 大容器四级识别。

数据不丢：早期导出内容靠 URL hash 传递，长文会截断。复赛改为写入 IndexedDB，URL 只带一个 clipId，彻底解决了大内容丢失问题。

格式保真：Markdown 曾经把图片语法混进去，富文本粘出来"非所见即所得"。复赛重写了 Markdown 内联管线（逐项保真），并新增按渲染态提取的富文本路径。

投递可靠：AI 平台自动填入曾依赖硬编码选择器，平台一改版就失效。后来改为"数据驱动"的规则包，并扩展到 8+ 平台。

内容沉淀：这是复赛最大的形态升级——从"用完即焚"的剪藏工具，变成带历史库、编辑器、AI 能力的"工作站"。

一个值得分享的设计决策： 为了让"网页内容"能被 AI 正确消费，我设计了三路并行解析——Markdown（喂 AI 对话，剥离图片）、结构树（让 AI 看页面布局，体积最小）、富文本（保留图文混排，所见即所得）。三条路径互不替代，用户按场景选择，也避免了单一路径的性能爆炸。

五、TRAE 实践过程（复赛阶段）

复赛阶段，我围绕"把上一版能演示的 Demo，打磨成一件可被真实上手使用的完整产品"这一目标，用 TRAE 完成了一次从架构到体验的全面进化。整个过程按时间顺序分为四个阶段，每个阶段都有明确的「问题 → 与 TRAE 协作 → 产出」。

阶段一：架构重构 —— 从"能用"到"工作台"

复赛伊始，我先把上一版 Demo 的源码整体评审了一遍，梳理出 20+ 个影响产品化的问题（长文数据丢失、无预览、无历史沉淀、AI 平台硬编码、单文件巨石等），然后和 TRAE 一起把它重构为"抓取 · 加工 · 分发 · 沉淀"四层架构：

模块化拆分：把 2200+ 行的单文件巨石，拆成 core（消息总线 / 存储 / 历史库 / Prompt 模板 / 平台规则包）、content（选择引擎 / Shadow DOM 工具栏 / 悬浮按钮 / 截图 / 自动填入）、background（Service Worker 消息路由）等独立模块，让每个模块可独立开发、可测试；

数据通道改造：导出内容从"URL hash 传大对象"改为写入 IndexedDB，页面 URL 只带一个 clipId，彻底解决长文截断丢失；

补齐核心能力：新增悬浮按钮（FAB）、实时预览面板、剪藏历史库、文本编辑器、图片编辑器、Prompt 模板、快捷键、三主题设计系统。

阶段二：多轮实测反馈迭代 —— 打磨产品完整度与体验

架构重构后，我进入"实测 → 反馈 → 打磨"的密集迭代，一笔一笔把产品做扎实。这一阶段集中解决了几类核心问题：

识别精度：最初识别范围要么太细、要么把"发帖人"和"评论"混在一起。TRAE 帮我把选择引擎升级为"元素 / 帖子 / 内容块 / 大容器"四级识别，并支持"选中父级 / 选中子级"沿层级链上下调整，单选状态机避免误叠加；

格式保真：Markdown 曾把图片语法混进输出、富文本粘出来"非所见即所得"。TRAE 帮我重写了 Markdown 内联管线（粗体、斜体、代码、[链接] 逐项保真），并新增"按渲染态提取"的富文本路径；

截图链路：截图会把 Foclip 自己的选中框截进去、长截图会撞上粘性顶栏。TRAE 用 visibility:hidden + requestAnimationFrame 防闪烁、按帧裁剪去重并实时预览，最终长截图也能稳定输出；

Studio 编辑器：把"文本编辑器 + 图片编辑器"合并成单页 Studio。文本模式支持富文本编辑与整理工具（去空行 / 去分割线 / 正则 / 去重），图像模式升级为"底图 + 标注对象 + 预览层"的画布，支持 8 控制点裁剪、对象化标注、网格切分，甚至接入了 AI 生成 / 编辑图片。

阶段三：解析引擎性能优化与新增能力 —— 让 AI 更懂网页

为了让 AI 用更小的成本、更准地理解网页，我专门做了一轮解析引擎优化：

三路并行解析：Markdown（喂 AI 对话，剥离图片）、结构树（让 AI 看页面布局，体积最小）、富文本（保留图文混排，所见即所得）三条路径互不替代，按场景选用；

性能优化：Markdown 路径跳过图片的无谓解析；结构树改为"语义角色"推断（[main] / [list] / [heading:h1]）并聚合同构兄弟节点，计算量大幅下降，信息密度反而更高；

新增"设计快照"格式：让 AI 以"读源码"的方式理解页面设计，输出 class 去重 + <style> 块 + 完整布局属性的代码块，方便 AI 复刻页面。

六、其他

6.1 技术方案与架构

整体架构图：

architecture-diagram1280×1370 67.3 KB

说明：架构图按「用户入口 → 拾取 → 加工 → 分发 → 沉淀 → 核心支撑」的层次展开。底部「Agent 能力」层（foclip-cli / TRAE Skill）为面向未来的迭代规划，当前已实现的核心能力集中在浏览器扩展这一完整链条上。

技术实现要点：

技术栈：Chrome Extension Manifest V3、Vanilla JavaScript（无框架、无构建依赖）、IndexedDB、Shadow DOM、Canvas、WebSocket。

架构设计：整体拆分为「抓取 / 加工 / 分发 / 沉淀」四层 + 独立 core 纯逻辑模块，跨上下文统一走消息总线协议，数据经 chrome.storage / IndexedDB 传递，避免巨石文件和 URL 传大对象。

关键实现：

三路并行解析 + 防爆炸机制（图片剥离、硬上限、白名单清洗、同构聚合）；

截图链路用 visibility:hidden + requestAnimationFrame 防闪烁，长截图按帧裁剪去重并实时预览；

Studio 画布采用"底图 + 标注对象 + 预览层"三层合成，撤销 / 重做为统一快照。

6.2 商业化

目标用户：高频使用 Web 与 AI 的开发者、内容创作者、学生、上班族，市场基数大、需求真实且高频；

价值主张：把"网页内容 → AI"之间反复的复制粘贴与手动整理压缩成"点一下"，同时保留完整格式与可沉淀能力，是提升个人 AI 工作流效率的刚需工具；

商业模式：核心能力免费开放，后续可考虑 ① 面向企业 / 团队的高级版（云同步、站点净化规则库、团队共享剪藏）；② 与 AI 助手 / 生产力工具联动的增值服务；③ 引流到同生态的付费工具链；

护城河：精准的网页内容解析能力、三路并行格式、可沉淀的剪藏库，以及"AI 也能调用"的 CLI / Skill 能力，具备技术壁垒与用户转换成本。

6.3 迭代规划

近期：支持更多站点净化规则、云同步（预留接口）、更多导出格式（PDF / 更多文档类型）；

中期：把规则包做成可远程更新的"数据驱动"体系，让 AI 平台改版也能快速适配；扩展至 Firefox / Safari 等更多浏览器；落地 foclip-cli 命令行工具与 TRAE Skill，通过 WebSocket / Native Messaging 与扩展通信，把"抓取 → 加工 → 分发 → 沉淀"全链路封装成命令，让 AI Agent 也能用自然语言端到端调用；

长期：把"网页内容拾取 + 整理 + 喂给 AI"沉淀为一条可复用的生产力链路，逐步向团队协作与生态化演进。
